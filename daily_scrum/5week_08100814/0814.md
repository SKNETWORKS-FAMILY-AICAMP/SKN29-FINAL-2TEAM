## 스크럼 회의록 (2026-08-14 금)

> 출근 인원 2명이 비어 새 기능을 붙이는 대신 **환경 이전과 정리**에 썼다.

### 1. AWS 이전 완료 — 시연 서버가 열렸다 (준)

**진행 내용**

`halil-ai.site` 도메인을 확보하고 EC2 에 https 로 올렸다.

| | |
|---|---|
| 화면 | **https://halil-ai.site** (apex 가 본 주소, `www`·`app` 은 301) |
| API | `https://api.halil-ai.site` |
| MCP 시연 서버 | `https://mcp.halil-ai.site` — **주소가 고정됐다** |
| 인증서 | Let's Encrypt 자동 발급·갱신 (Caddy) |

**주요 논의**

* 도메인이 세 가지를 한 번에 풀었다 — Google OAuth 는 공인 IP 의 `http` redirect
  를 받지 않고, MCP 서버 등록은 https 를 요구하며, 화면이 https 인데 API 가 http
  면 브라우저가 막는다
* **RunPod 터널이 없어졌다.** 그동안 `PUBLIC_BACKEND_BASE_URL` 이 재시작마다 바뀌는
  임시 터널이라 시연 중 파싱이 조용히 끊길 수 있었는데, 이제 고정 주소다
* Atlassian 은 앱마다 Callback URL 이 **하나뿐**이라 AWS 로 넘겼다 —
  **로컬에서 Jira 연결은 이제 안 된다.** 고장이 아니라 결정이다

**이전 중 잡은 것**

* Caddy 가 재시작만 반복 — 빈 `CADDY_EMAIL` 이 인자 없는 `email` 로 전개돼 파싱이
  깨졌다. web·frontend 는 둘 다 200 이라 안쪽만 보면 멀쩡해 보이는 종류였다
* swap 이 0 — 909MB 에서 프론트 빌드가 OOM 날 자리였다 (2GB 확보)
* `production.py` 에 `SECURE_PROXY_SSL_HEADER` 누락 — Caddy 뒤에서 **무한 리다이렉트**가 날 상태
* dev-mcp 가 401 을 보내며 요청 본문을 안 읽어, **인증 없는 요청 하나가 다음 정상
  요청을 먹었다.** 공개 주소라 스캐너만으로도 재현된다

### 2. 자동 배포 (준)

`main` 에 push 하면 GitHub Actions 가 EC2 에 배포한다. 실제 로직은
`infra/deploy.sh` 에 둬서 리뷰되고 손으로도 돌아간다.

⚠ **배포 때 `web` 이 재생성돼 몇 초 끊긴다. 시연 중에는 `main` 에 푸시하지 않는다.**

### 3. 프로젝트 정리 (준)

* **문서** — 참조를 전부 확인한 뒤 구버전·중복·외부자료 16개(19.7MB) 삭제.
  지우려다 만 것도 둘 있었다 — `개발_기획서_샘플/` 은 파싱 평가 코퍼스였고
  `_archive/기획서_v2` 는 아키텍처 문서가 인용 중이었다
* **코드** — 7갈래 병렬 감사로 25건 확정. `ProjectRepository.get()` 은 호출부가
  0건인데 **팀 검증 없이 아무 프로젝트나 꺼내는 함수**여서 특히 걷어야 했다.
  안 쓰는 인증 엔드포인트 3종, CSS 선택자 18개도 정리
* **문서 정합** — AS-IS 가 「CI/CD 없음」·「Vite 개발 서버」·「브라우저가 5173·8000
  직접 접속」이라고 적고 있어 실제 구조로 맞췄다
