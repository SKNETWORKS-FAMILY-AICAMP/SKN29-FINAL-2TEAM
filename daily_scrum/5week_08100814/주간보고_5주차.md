# 5주차 주간 업무 보고 (2026.08.10 ~ 08.14) — 2팀

> 8/8 멘토링에서 프로젝트 방향이 **업무 분배 서비스 → 프로젝트 운영 Agent Platform**
> 으로 확장됐다. 이번 주는 그 전환을 설계·화면·코드에 반영하고, 시연 환경을
> 공개 주소로 여는 데 썼다.

* **Agent Harness 구조 조사 및 방향 확정**
  * OpenCode·deep-agent·clawcode 세 오픈소스를 3인이 나눠 분석
    — 코드 재사용이 아니라 우리 플랫폼에 적용할 구조와 설계 요소 중심
  * 세 사례 모두 「도구를 가진 하나의 루프」라는 뼈대는 같고 도구 정의·실행 계약·
    이벤트 표현에서 갈린다는 것을 확인
  * **기존 `orchestration` 을 확장한다는 전제를 정정**하고 신규 작성으로 결정
    — 실제로는 12줄짜리 함수 하나뿐이라 확장할 실체가 없었고, 해당 모듈은
    이후 정리에서 삭제

* **Agent Platform 구현 — 팀이 직접 에이전트를 만들어 쓴다**
  * 에이전트 정의·도구 카탈로그·실행 기록 스키마 추가, 에이전트 빌더 화면에
    도구 선택 UI 와 생성·검증 흐름 구현
  * **정문 에이전트** 도입 — 사용자의 요청을 받아 필요한 도구와 다른 에이전트를
    부르는 구조. 화면을 순서대로 밟는 대신 대화로 요청한다
  * 실행 기록(`agent_run`·`tool_call`) 적재 시작 — 평가의 모수가 되는 자리라
    Harness 개발 초반에 넣어야 했다
  * 업무 추출 결과를 `task`·`proj_know_model` 에 실제로 저장
    — 그전에는 응답으로만 존재해 새로고침하면 사라졌다
  * 외부 **MCP 서버 등록·수정·연결 확인** 구현, 시연용 MCP 서버로 실제 도구 호출 검증

* **화면 전면 개편 — Chat 을 정문으로**
  * 업무 분배 시절의 단계형 화면(온보딩 3종·대시보드·업무분배 계열·워크스페이스)을
    걷어내고 Chat 중심 구조로 전환
  * 대시보드가 하던 부하·업무 현황은 화면이 아니라 Chat 에서 내장 도구
    (`workload_report` 등)를 호출해 확인
  * 커넥터 연결을 온보딩에서 **설정 탭으로 이동** — 한 번 밟고 끝나는 절차가 아니라
    반복적인 「팀 관리」 성격이기 때문
  * 설정을 팀·Connector·MCP·Model 네 탭으로 재편하고 팀원은 읽기 전용으로 제한

* **운영자 콘솔 조치 기능 개방 및 모델 등록 흐름 전환**
  * 보기만 가능하던 네 가지를 실제 조치 가능하도록 구현
    — 운영자 권한 부여·회수, 팀 소유자 이전, 팀 에이전트·실행 기록 조회,
    **커넥터 강제 해제**
  * 커넥터 강제 해제는 그동안 제품 어디에도 없어서 **토큰이 유출돼도 고객도 운영자도
    연결을 끊을 수 없는 상태**였다
  * 멘토링 피드백에 따라 모델 등록 방식을 전환 — 사용자가 직접 API 키를 붙이는 대신
    회사가 요청하면 운영자가 등록하는 흐름으로 바꾸고 제공자를 셋으로 확대
  * 권한 정책 문서가 약속한 규칙 중 서버가 실제로 막지 않던 경로를 확인해 보완

* **AWS 시연 환경 구축 — 공개 서비스 가동**
  * **1단계(8/11)**: RDS·S3·IAM 구성, 팀원별 로컬 DB 를 공유 DB 로 통합
    — 스키마 드리프트와 데이터 분산 해소
  * **2단계(8/14)**: 도메인 `halil-ai.site` 확보, EC2 에 HTTPS 서비스 가동
    (Caddy + Let's Encrypt 자동 발급·갱신)
  * `main` 브랜치 push 시 GitHub Actions 로 **자동 배포** 연결, 배포 후 도메인
    헬스체크까지 자동 확인
  * 도메인 확보로 세 가지가 함께 해결 — Google OAuth 의 HTTPS redirect 요구,
    MCP 서버 등록의 HTTPS 요구, 화면·API 혼합 콘텐츠 차단
  * **RunPod 원문 수신 주소가 고정**됐다. 그전에는 재시작마다 바뀌는 임시 터널이라
    시연 중 문서 파싱이 조용히 끊길 수 있는 상태였다

* **문서 전처리 고도화**
  * 제목 검출 개선 — Docling 이 고려하지 않는 **텍스트 볼드 여부**를 폰트 정보로
    판단해 제목 판정 신호로 쓰는 후처리 로직 시험, 제목 레벨 판정 고도화 진행
  * 읽기 순서 보정 — 문장이 완결되지 않은 구간에서 다음 섹션을 검출하는 방안을
    **범용성과 효율성** 두 지표로 비교 검증 중
  * Deep Agents 오픈소스의 함수 호출 흐름 정리

* **코드·문서 정리 및 정합화**
  * 다중 에이전트 기반 저장소 전수 점검으로 폐기 기능의 잔해와 죽은 코드 정리
    (8/13 약 1만 3천 줄, 8/14 추가 25건)
  * 팀 검증 없이 임의 프로젝트를 조회할 수 있는 미사용 함수, 프론트가 호출하지 않는
    인증 엔드포인트 3종, 미사용 CSS 선택자 18개 제거
  * 참조 관계를 확인한 뒤 구버전·중복·외부 참고자료 문서 16건(19.7MB) 정리
  * 설계 문서가 실제 코드와 어긋난 부분 정합화 — 화면 목록, API 목록, 배포 구조를
    현행 기준으로 갱신

## 현재 제한 및 다음 주 계획

* **문서 파싱·임베딩 종단 흐름이 아직 실제 문서로 검증되지 않았다.** RunPod 워커가
  모델을 이미지에 포함하지 않아 첫 실행 시 콜드 스타트가 크므로, 시연 전에 반드시
  사전 실행이 필요하다 — **최우선 과제**
* 검색 품질 평가용 골든셋(G-DOC·G-QUERY) 착수 필요. 현재 0건이며 문서 단위 Recall 을
  한 번도 측정하지 않았다. A안(요약 임베딩)이 기준 미달이면 A′(하이브리드 검색)로
  확장해야 하는데, 늦게 확인하면 대응할 시간이 없다
* 문서 원문의 S3 저장 어댑터 구현 — 버킷·IAM 권한은 준비 완료, 코드만 남았다
* Google Drive·Jira 실연동 검증 (redirect URI 등록 완료, 화면 동작 확인 필요)
* 에이전트 빌더 검증·스캐폴드 마무리
