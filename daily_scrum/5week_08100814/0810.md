## 스크럼 회의록 (2026-08-10 월)

8/8 오프라인 멘토링에서 프로젝트 방향이 **업무 분배 서비스 → Agent Platform**
으로 확장됐다. 이번 주는 그 전환을 설계와 코드에 반영하는 것으로 시작한다.

### 1. Harness 오픈소스 분석 — 3인 분담

방향 전환의 핵심이 **Agent Harness 환경 구축**이라 보고, 기존 오케스트레이션을
확장하는 대신 어떤 구조로 새로 짤지를 오픈소스 셋에서 확인했다.

| 담당 | 대상 | 본 것 |
|---|---|---|
| 임준억 | OpenCode | Agent 구조와 설계 요소. 코드 재사용이 아니라 **우리 플랫폼에 적용할 구조** 중심 |
| 김지훈 | deep-agent | 동작 방식과 우리가 쓸 수 있는 것. Agent 를 어떤 방식으로 설계해야 하는지 |
| 성주연 | clawcode | Agent product 가 어떤 구조로 동작하는지 |

**주요 논의**

* 세 사례 모두 「도구를 가진 하나의 루프」라는 뼈대는 같고, 도구 정의·실행
  계약·이벤트 표현에서 갈린다
* 우리 것은 **비개발자가 만들 수 있어야** 하므로 도구 목록과 검증을 화면에서
  다룰 수 있는 형태여야 한다

### 2. 문서 구조 재편과 Base Code 정리 (준)

* 중간발표 산출물 전체 커밋·푸시
* `docs/` 를 **AS-IS / TO-BE** 로 재구조화 — AS-IS 는 중간발표 시점 기록,
  TO-BE 는 새 방향 설계
* 설계 문서 11종 초안 작성 (IA·아키텍처·평가·E2E·질문지 등)
* Base Code 정리 — 정적 화면 4종 삭제, 라우팅 단일화
* TO-BE 화면 18프레임 Figma 구성·검증, 팀 공간 이동 완료

**확인 사항**

* **Harness 는 기존 `orchestration` 확장이 아니라 신규 작성**으로 전제를 정정했다.
  기존 코드에 12줄짜리 함수 하나뿐이라 확장할 실체가 없었다.
