# 3주차 주간 업무 보고 (2026.07.27 ~ 07.31) — 2팀

* 외부 도구 연결 및 데이터 입력 경로 구현
  * Google Drive·Jira OAuth 연결과 호출 직전 토큰 자동 갱신 구현, 실계정 기준으로
    폴더·파일 조회, 프로젝트 조회, 선택 저장·해제 흐름 검증
  * 읽을 폴더·탐색 깊이·문서 역할을 지정해 프로젝트 소스와 문서 데이터로 저장하는
    구간 완성, 재저장 시 기존 문서의 파싱 관련 정보 보존
  * 폴더를 선택하는 행위가 곧 프로젝트를 생성하는 행위가 되도록 화면 순서 재정의
    — 문서를 근거로 프로젝트를 파악한다는 제품 목적과 사용자 흐름 일치
  * 구현 과정에서 확인된 인증 누락, 입력값 검증, 자격증명 관리 등 보안 사항 조치

* 비정형 문서 파싱 방식 확정 및 검증 레이어 설계
  * 여러 파싱 모델의 성능과 결과물을 비교한 뒤 Docling SDK 도입 결정
    — 단일 파싱 모델이 아니라 여러 처리 단계를 조합해 파싱 워크플로우를 구성하는
    방식이 다양한 문서 형식에 유연하게 대응 가능하다고 판단
  * 파싱 결과와 원본 문서를 비교하는 검증 레이어 초기 설계
    — 내용 정확도, 텍스트·구성요소 누락, 문서 구조 유지, 표 변환 4개 기준
  * 멘토링 피드백을 반영하여 검증 로직을 확대하기 전에 Docling 내부 파라미터를
    충분히 조정·테스트하는 방향으로 전환, 파라미터별 역할과 적용 범위 조사
  * 설정만으로 해결 가능한 문제와 별도 검증 로직이 필요한 문제를 구분해
    경량 검증 레이어로 재설계 진행 중

* 계정·권한 체계 및 인력 데이터 구축
  * 가입 경로를 기준으로 팀장·팀원 역할을 판정하는 정책 확정, 초대 코드 기반
    계정–직원 매핑 구현 (이메일 비교가 아닌 링크 소유 기반 신원 확인)
  * 로그인 세션 보관 방식, 라우트 가드, 인증 만료 처리, 비밀번호 재설정 흐름 보완
  * People DB 조직·직원·스킬·책임수준·근무일정·부재 데이터 입력 완료
    (직원 57명 기준, 추천 로직 연결 시 즉시 활용 가능한 상태)
  * ORM 중심 구조를 schema.sql 기반 직접 SQL 구조로 정리하고
    벡터 저장소를 ChromaDB에서 pgvector로 전환해 단일 PostgreSQL로 운영

* 화면 구현 및 API 연동
  * 온보딩 4개 화면(커넥터 연결·폴더 선택·폴더 역할 지정·Jira 프로젝트 선택)
    실제 API 연동 완료, 로딩·오류·미연결·재연결 상태 처리 포함
  * 운영자 콘솔을 일반 사용자 화면과 분리된 흐름으로 설계하고
    운영 현황·연결 조직·계정 관리·계정 연결·연결 서비스·감사 로그·전역 정책 7개 화면 구현
  * Figma 기반 랜딩·설정·문서 등록·프로젝트 화면 정리 및 목업 데이터를 실제 연동으로 교체

* 제출 산출물 작성 및 문서 정합화
  * 데이터베이스저장소 설계 문서 작성 — PostgreSQL 17·pgvector 저장 구조,
    47개 엔터티의 5개 업무 도메인 분류, ERD, schema.sql 기준 물리 테이블 정의서 포함
  * 데이터 전처리 결과서 작성 — People DB 시드 8개 테이블의 스키마·타입·명명·참조
    정합성 확보 절차, 품질 이슈 진단, 전처리 파이프라인 흐름 정리
  * 제출 산출물을 `docs/산출물`로 일원화하고 문서 인덱스 갱신
  * 중간발표 To-Do를 코드·DB 실측 기준으로 갱신해 완료·부분 완료 항목 구분,
    기능별 작업기록에 판단 근거와 검증 결과 기록 시작

  * Docling 파라미터 테스트 결과 정리 및 문서 유형별 설정 조합 확정,
