## 스크럼 회의록

### 1. 신규 문서 등록부터 업무 추출까지의 데모 흐름 보완

**진행 내용**

* Google Drive 신규 문서 확인·등록, 대표 문서 선택, 문서 처리 이력 확인 흐름을 보완
* Jira 프로젝트 연동, 프로젝트 상세 조회와 완료 처리까지 이어지는 문서·프로젝트 흐름을 연결
* 문서에서 추출된 업무를 확인할 수 있도록 업무 추출 화면과 관련 API를 반영

**주요 논의**

* 문서 등록 이후 파싱·청킹·업무 추출 상태를 사용자가 확인할 수 있어야 함
* 기존 폴더 역할 지정 단계는 현재 데이터 흐름과 중복되는 부분을 정리하고 문서 선택 흐름을 단순화
* 프로젝트 상세 화면에서 Jira 업무 목록과 완료 상태를 확인할 수 있도록 데모 경로 구성

⸻

### 2. 주차별 업무량과 마감 중심 대시보드 개선

**진행 내용**

* 기존 단순 부하율 중심 화면을 주차별 업무량과 프로젝트 진행 상황을 확인하는 구조로 개선
* 곧 다가오는 마감과 지연된 업무를 별도 구획으로 분리
* 팀별 업무량과 프로젝트 진행률을 대시보드에서 함께 확인할 수 있도록 화면과 API를 보완

**주요 논의**

* 단순한 부하율 수치보다 업무가 어느 주차에 집중되는지 보여주는 것이 데모와 의사결정에 적합
* 마감 임박 업무와 지연 업무를 구분해 사용자가 먼저 확인할 대상을 명확하게 제시
* 프로젝트 상세의 업무 상태와 대시보드의 진행 상황이 서로 다르게 보이지 않도록 데이터 흐름을 정리

⸻

### 3. 팀 명부와 프로필·스킬 관리 정비

**진행 내용**

* 팀원 관리를 초대 현황이 아닌 실제 소속 팀원 기준의 팀 명부로 정리
* 팀장과 팀원의 프로필·부서·직급·보유 스킬 표시를 실제 데이터 흐름에 맞게 보완
* 프로필 사진 변경, 비밀번호 변경, 팀장 스킬 시드 등 설정 기능을 반영

**주요 논의**

* 팀 명부는 소유자를 우선 표시하고 직급 기준으로 정렬해 관리자가 팀 구성을 빠르게 확인할 수 있도록 함
* 화면에 표시되는 프로필 정보와 People 데이터의 의미가 일치하도록 사번·직급·부서 표현을 정리
* 업무량과 업무 분배에 활용되는 팀원 정보는 실제 소속과 보유 스킬을 기준으로 관리

⸻

### 4. 문서 파싱·청킹·임베딩·업무 추출 MVP 정리

**진행 내용**

* 비정형 문서를 파싱하고 하이브리드 청킹과 임베딩을 거쳐 저장하는 처리 흐름을 반영
* Docling 기반 문서 처리, 768차원 임베딩, 문서 역할 구분과 RunPod 문서 처리 워커를 구성
* 업무 추출 서비스와 관련 API를 연결해 문서에서 추출된 업무를 화면 흐름에 전달

**주요 논의**

* 문서 구조와 원문 근거를 보존하면서 업무 추출에 필요한 문맥을 전달하는 방식 검토
* 업무량 계산은 LLM이 임의로 생성하지 않고 주차별 업무량과 팀별 설정을 이용하는 결정론적 계산으로 유지
* 추출 결과가 원문 근거와 연결되지 않거나 필수 정보가 부족한 경우 추측하지 않고 제한 상태로 표현하는 방향 확인

⸻

### 5. 중간발표 자료와 실제 구현 현황 정합성 검토

**진행 내용**

* 중간발표 PPT를 전반적으로 검수하고 실제 구현된 화면과 진행 중인 기능을 구분
* 문서 등록 → 프로젝트·Jira 연결 → 업무 추출 → 팀 업무량·마감 확인 순서로 핵심 데모 흐름 구성
* AI가 업무를 자동 확정하는 서비스가 아니라 근거 기반 의사결정을 지원한다는 제품 방향을 발표 자료에 반영

**주요 논의**

* 발표 화면의 순서와 실제 애플리케이션의 이동 경로가 일치하는지 확인
* MVP로 동작하는 기능과 실제 Retriever·외부 데이터 연동 등 후속 검증이 필요한 기능을 분리해 설명
* 업무 추출 결과와 원문 근거, 누락 필드, 제한 상태를 발표에서 어떻게 보여줄지 검토

⸻
