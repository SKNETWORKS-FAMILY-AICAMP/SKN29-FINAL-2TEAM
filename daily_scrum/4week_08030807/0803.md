## 스크럼 회의록

### 1. 전체 데이터 처리 파이프라인 구조 구체화

**진행 내용**

* 커넥터를 통해 데이터를 수집한 뒤 파서 → 청킹·리트리버 → 에이전트로 전달하는 전체 처리 흐름을 정리
* 문서 데이터가 업무 추출과 업무 분배에 활용될 수 있도록 단계별 책임과 연결 구조를 검토

**주요 논의**

* 커넥터에서 수집한 원본 문서를 파싱하고, 문서 구조를 보존한 청크로 변환하는 기준 확인
* 모든 문서를 에이전트에 전달하지 않고 검색된 관련 청크만 다음 단계로 넘기는 방향 검토
* 파서·청킹·리트리버·에이전트 사이의 데이터 계약과 각 단계의 처리 책임을 분리

⸻

### 2. 업무량 계산 방식 검증 및 적용

**진행 내용**

* 기존 업무량 계산 방식을 다시 검토하고 프로젝트에 적용
* Jira 업무 정보와 HR 근무 가능 시간 정보를 이용해 업무량을 산정하는 기준을 확인

**주요 논의**

* 업무량 계산은 LLM의 추론이 아니라 동일한 입력에 동일한 결과를 내는 결정론적 로직으로 처리
* 업무량 계산 결과가 업무 분배와 후보 추천에 활용될 수 있도록 입력 데이터와 출력 결과의 연결 구조를 정리
* 업무량 계산에 필요한 업무 기간, 예상 공수, 근무 가능 시간 등의 필수 데이터가 누락될 경우 결과를 제한하는 기준 검토

⸻

### 3. 하이브리드 청킹·리트리버·임베딩 구조 검토

**진행 내용**

* 하이브리드 청킹 적용 과정에서 발생할 수 있는 문서 구조 보존 문제를 분석
* 문서를 청크 단위로 저장하고 질문과 관련된 청크를 검색해 에이전트에 전달하는 구조 설계
* 임베딩 처리와 검색 대상 청크의 범위를 함께 검토

**주요 논의**

* 표, 제목, 문단 등 원문 구조가 업무 추출 근거에서 유지될 수 있도록 청킹 기준을 검토
* 검색 결과에는 원문 위치와 문맥이 함께 포함되어야 하며, 에이전트가 근거를 추적할 수 있어야 함
* 전체 문서를 매번 전달하는 방식보다 질문과 업무 목적에 맞는 관련 청크만 전달하는 방식이 MVP에 적합한지 검토

⸻

### 4. 에이전트 업무 분배 로직과 LangGraph 구조 구체화

**진행 내용**

* 업무 추출과 업무 분배 흐름에서 업무량 계산을 필수 Tool로 연결
* LangGraph의 노드와 엣지를 다시 설계해 에이전트가 필요한 기능을 단계적으로 호출하도록 구조화

**주요 논의**

* 업무 추출 결과와 업무량 계산 결과를 다음 업무 분배 단계에서 활용할 수 있도록 상태 전달 구조를 정리
* 업무량 계산이 누락된 상태에서 추천 결과가 만들어지지 않도록 필수 실행 단계로 관리
* 데이터가 부족하거나 근거가 불충분한 경우 자동 확정하지 않고 제한 또는 검증 필요 상태로 반환하는 방향 검토

⸻

### 5. 중간발표 자료와 실제 구현 내용 정합성 검토

**진행 내용**

* 현재 구현된 시스템 파이프라인에 맞춰 발표 자료의 구조와 설명 순서를 수정
* 실제 구현 완료 범위와 설계·검토 중인 범위를 구분해 발표 내용에 반영

**주요 논의**

* 발표에서는 커넥터 → 문서 처리 → 청킹·리트리버 → 업무 추출 → 업무량 계산으로 이어지는 핵심 흐름을 중심으로 설명
* AI가 업무를 자동으로 확정하는 서비스가 아니라 근거와 제한 상태를 제공해 PM의 판단을 지원하는 서비스라는 방향 유지
* 화면 데모와 백엔드 처리 흐름이 서로 다르게 보이지 않도록 발표 자료와 실제 구현 상태를 지속적으로 대조

⸻
