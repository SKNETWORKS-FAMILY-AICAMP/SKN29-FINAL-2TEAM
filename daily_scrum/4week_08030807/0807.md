## 스크럼 회의록

### 1. 중간발표 이후 피드백 내용 토론

**진행 내용**

* 중간발표에서 확인된 데모 흐름과 발표 내용에 대한 피드백을 공유
* 실제 구현된 기능과 발표 자료에서 설명된 기능 사이의 차이를 다시 점검
* MVP에서 유지할 범위와 이후 고도화할 범위를 구분해 다음 작업 방향을 논의

**주요 논의**

* AI가 업무를 자동 확정하는 것이 아니라 원문 근거와 데이터 상태를 바탕으로 PM의 판단을 지원해야 한다는 제품 방향 재확인
* 문서 등록부터 업무 추출, 업무량 확인까지의 데모 흐름에서 사용자가 이해하기 어려웠던 지점과 설명이 부족했던 지점 검토
* 실제 연동이 완료된 기능과 설계·검증 중인 기능을 발표와 문서에서 명확히 구분해야 한다는 의견 공유
* 데이터가 부족한 경우 추측하지 않고 제한·차단 상태와 보완이 필요한 이유를 보여주는 방향 유지

### 2. 금주 산출물인 Vector DB 문서 작성

**진행 내용**

* 비정형 문서를 Vector DB에 저장하고 검색하기까지의 전체 처리 과정을 문서화
* 문서 파싱, 구조 보존 청킹, 임베딩 생성, 메타데이터 저장, 유사도 검색과 에이전트 전달 과정을 단계별로 정리
* 문서·Chunk·임베딩·검색 결과 사이의 데이터 구조와 책임 범위를 검토

**주요 논의**

* 원문 문서의 제목·표·문단 구조와 페이지 정보를 보존해 검색 결과가 실제 근거로 연결될 수 있어야 함
* Chunk에는 문서 식별자, Chunk 식별자, 원문 위치, heading 정보와 검색·검증에 필요한 메타데이터가 포함되어야 함
* 임베딩은 검색을 위한 표현이며 최종 업무 확정의 근거 자체가 아니므로, 검색 결과를 원문과 대조하는 검증 흐름이 필요함
* Vector DB 검색 결과는 전체 문서를 그대로 전달하지 않고 업무 목적에 맞는 관련 Chunk와 주변 문맥을 에이전트에 전달하는 방식으로 정리
* 검색 품질과 운영 상태를 확인할 수 있도록 문서 처리 성공·실패, 임베딩 상태, 검색 결과 부족 상태를 구분하는 방향 검토

### 3. 다음 날 오후 멘토링 준비

**진행 내용**

* 중간발표 피드백과 Vector DB 문서를 바탕으로 멘토링에서 확인할 질문을 정리
* 현재 구현 상태, 이번 주 산출물, 다음 개발 우선순위를 설명할 수 있도록 자료를 정리
* 문서 처리와 검색·업무 추출 흐름에서 추가 확인이 필요한 연동 계약과 검증 기준을 목록화

**주요 논의**

* Vector DB 문서의 데이터 구조와 실제 파싱·청킹·임베딩 구현이 일치하는지 확인받을 예정
* 검색 결과를 업무 추출 에이전트에 전달하는 범위와 원문 근거를 연결하는 방식에 대한 멘토 의견 요청
* MVP 이후 실제 Retriever 연동, 필드별 근거 관리, 검색 품질 평가를 어떤 순서로 진행할지 우선순위 확인
* 발표 피드백 중 즉시 수정할 항목과 후속 개발로 남길 항목을 구분해 일정에 반영
