## 스크럼 회의록 (2026-08-18 화)

### N. 홈페이지 고도화 (준)

8/18 멘토링에서 나온 **네 가지를 전부 반영**하고, 그 위에 파일 공유·S3 저장·
운영자 콘솔 정리를 얹었다.

**① 커스텀 도구를 팀이 등록하지 못하게 막았다.** 등록·수정·삭제·연결 확인이
운영자 콘솔로 갔다. 화면에서만 감추지 않고 **팀 쪽 쓰기 API 를 걷어냈다** —
폼만 없애면 API 를 그대로 부를 수 있어서 그건 규칙이 아니라 장식이다.
이름도 「MCP」에서 **커스텀 도구**로 바꿨다(FastAPI·MCP 둘 다 되므로 MCP 가
실제보다 좁다).

**② 기본 채팅 모델을 운영자가 팀별로 정한다.** 설정의 Model 탭을 걷었다.
전역 하나로 두지 않은 것은 계약·리전 요건이 다른 회사를 못 받기 때문이고,
**에이전트별 모델 선택은 빌더에 그대로 남는다** — 옮긴 것은 「아무것도 안 고르고
말을 걸었을 때 도는 모델」 하나뿐이다.

**③ 「내 파일」을 만들었다.** 내 컴퓨터에서 문서를 올려 대화의 근거로 쓴다.

| | |
|---|---|
| 올리기 | drag & drop, PDF·DOCX·txt·md |
| 검색에 사용 | toggle 로 켜고 끈다. 켠 파일은 **모든 에이전트가** 쓴다 |
| 팀에 공유 | 켜면 팀원이 본다. **소유는 안 옮긴다** |
| 지우기 | 원본이 우리뿐이라 되돌릴 수 없다 |

**에이전트에 파일을 붙이는 조작은 만들지 않았다.** 「왜 자료를 직접 골라 줘야
하나」로 되물으니 골라 줄 이유가 없었다 — toggle 이 이미 그 선택이고, 붙이는
표를 두면 같은 파일을 두 번 골라야 한다.

**④ 원문을 S3 에 저장한다.** 버킷·IAM 은 준비돼 있고 코드가 0 이었다. 배포 전에
기존 원문 4 건(6.2MB)을 같은 키로 옮겨서, 갈아타는 순간에 잃은 것이 없다.
**프로필 사진은 원본이 우리뿐이라** 안 옮겼으면 그대로 사라질 뻔했다.

**운영자 콘솔을 「등록」과 「사용」으로 갈랐다.** 등록은 각 페이지에서, 팀별로
무엇을 쓰는지는 팀 상세에서 본다. 전에는 한 팀을 세팅하려면 페이지 둘을 돌며
같은 팀을 두 번 골라야 했다.

**화면 문구를 전수 검토했다.** 설명 문구 29 곳을 걷고, 낫표 24·이어붙임표 30 곳을
다시 썼다. **이름 뒤 조사 11 곳**도 고쳤는데 — 「‘{이름}’을」처럼 조사를 박아
놔서, 이름이 모음으로 끝나면 「‘알파’을」이 된다. 지금 에이전트가 하나뿐이라
안 드러날 뿐이고 이름은 사람이 짓는 값이다.

⸻

**고친 결함 — 올린 파일이 「본문 읽는 중」에서 안 넘어갔다**

원인이 둘이었다.

* **워커가 읽는 형식은 PDF·DOCX 둘뿐인데 7 종을 받고 있었다.** 배포본에서 막혀
  있던 것이 `.md` 파일이었다
* **올릴 때 본문까지 파싱하려 RunPod 를 기다렸다.** 8/15 에 「검색이 필요로 할 때
  한다」로 정해 놓고 내가 어긴 것이다 — 워커가 우리 저장소에서 받아 간다는 것을
  확인 안 하고 「올린 파일은 되받을 곳이 없다」고 잘못 봤다

지금은 올릴 때 **요약까지만** 하고 본문 색인은 대화가 그 문서를 찾을 때 돈다.
그리고 결과를 남기지 않아 **느린 것과 죽은 것이 구분되지 않던 것**도 고쳤다
(`doc.index_status`).

**배포본에서 PDF 한 건으로 전 구간을 확인했다.**

| 단계 | 시간 | 결과 |
|---|---|---|
| 업로드 응답 | 2.2초 | 화면이 바로 돌아온다 |
| 요약 완료 | 10초 안 | 「검색 준비됨」 |
| 첫 검색 (본문 색인 포함) | 68초 | 블록 170 · 청크 563 |
| **근거 문장** | | **10건** |
| 두 번째 검색 | 3.7초 | 워커를 다시 안 부른다 |
