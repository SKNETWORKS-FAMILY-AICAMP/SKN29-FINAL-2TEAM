# HITL 마이그레이션 검사 보강 설계

## 목표

`DB/migrations/_apply.py --check`가 HITL 도구 호출 추적에 필요한 DB 구조를
배포 전에 정확히 확인하도록 한다. 검사 대상은
`tool_call.langchain_tool_call_id` 컬럼과
`ux_tool_call_run_langchain_id` UNIQUE 인덱스다.

## 변경 범위

- 기존 `EXPECTED`에 `tool_call.langchain_tool_call_id` 컬럼 검사를 추가한다.
- 인덱스 검사는 별도 `EXPECTED_INDEXES` 목록으로 관리한다.
- PostgreSQL 카탈로그를 조회해 인덱스가 `public.tool_call`에 속하며 실제로
  UNIQUE인지 확인한다.
- 누락된 컬럼과 인덱스를 기존 `--check` 결과에 함께 출력하고 하나라도 빠지면
  종료 코드 `1`을 반환한다.
- 검사기 동작을 고정하는 집중 테스트를 추가한다.

애플리케이션 실행 코드, 마이그레이션 SQL, 실제 DB 데이터는 이 작업에서 변경하지
않는다.

## 검사 결과

| DB 상태 | 기대 결과 |
|---|---|
| 컬럼 없음 | 실패 |
| 컬럼 있음, 인덱스 없음 | 실패 |
| 컬럼 있음, 같은 이름의 비-UNIQUE 인덱스 | 실패 |
| 컬럼과 UNIQUE 인덱스 모두 있음 | 성공 |

## 구현 원칙

- 기존 테이블·컬럼 검사 구조를 불필요하게 일반화하지 않는다.
- 인덱스 이름, 대상 테이블, UNIQUE 여부만 검사한다.
- 인덱스 SQL 문자열 전체를 비교하지 않아 PostgreSQL 출력 형식에 결합하지 않는다.
- 기존 출력 형식과 호출 방법을 유지한다.

## 검증

1. 새 집중 테스트에서 컬럼 및 인덱스 존재 조합별 종료 결과를 확인한다.
2. `_apply.py` 문법 검사를 수행한다.
3. 관련 테스트와 `git diff --check`를 실행한다.
4. DB에 접근 가능한 환경에서 마이그레이션 전 `--check`, 마이그레이션 적용,
   적용 후 `--check`를 순서대로 실행한다.

실제 DB 적용과 승인·거절·서브에이전트 HITL 수동 QA는 검사기 구현 이후의 별도
운영 단계로 남긴다.
