# 초기 구성 상태 — Django 베이스 코드

> 기준일: 2026-07-28  
> 목적: 현재 코드가 실제로 제공하는 기능, 의도적으로 비워 둔 영역, 다음 수정 위치를 한곳에서 확인한다.

---

## 1. 기술 결정

| 영역 | 현재 결정 | 이유 | AWS 이전 시 대응 |
|---|---|---|---|
| 웹 백엔드 | Django + Django REST Framework | 수업 범위의 ORM·Admin·인증·API 활용 | ECS Fargate의 Django 컨테이너 |
| 프론트엔드 실행 환경 | React + Vite + TypeScript | 화면 구현은 Figma 담당 팀 작업 | CloudFront/S3 또는 별도 컨테이너 |
| 관계 데이터 | PostgreSQL | People DB·프로젝트·분석 실행·감사 관계 관리 | RDS for PostgreSQL |
| 보조 검색 | pgvector 예정 | 문서 청크 보조 검색 | RDS PostgreSQL pgvector |
| 원본 문서 | Local Storage Adapter 예정 | 개발 단계의 원본 보존 | S3 Storage Adapter |
| 비동기 실행 | DB Job/SQS Worker 예정 | 긴 문서 분석을 HTTP 요청과 분리 | SQS + ECS Worker |

FastAPI와 Django를 함께 운영하지 않는다. 이번 프로젝트의 백엔드 서버는 Django 하나로 통일하고, React 프론트엔드는 이 API를 호출한다.

## 7. AWS 이전 시 유지해야 할 계약

- DB는 `DATABASE_URL`만으로 연결한다.
- 문서 저장 위치는 절대 로컬 경로가 아닌 `storage_key`로 기록한다.
- 장시간 분석은 Web 요청과 분리하고 `AnalysisRun` 상태를 DB에 저장한다.
- 외부 인증 정보는 `.env`에서 시작하되 AWS에서는 Secrets Manager로 이동한다.
- Django App의 View와 AI·계산 Service를 분리한다.
