# 홈 화면 정의 v1 — 공통 셸 + Chat

> 2026-08-10 작성. Figma 작업(화~수)의 밑그림. 근거: 1_서비스구조_IA(§1 새 IA,
> §5 FE 인벤토리), 5_E2E_시나리오, 0_멘토링_질문(Q4·Q7 제안 반영 — 멘토링에서
> 뒤집히면 해당 부분만 수정).

## 0. 원칙

1. 로그인 후 첫 화면 = **Chat**. 기존 `/dashboard` 랜딩을 대체한다.
2. 비개발자 실무자 기준 — 화면 어디에도 MCP·Tool Calling·컨텍스트 같은 용어를
   그대로 노출하지 않는다. 사용자가 보는 말은 "에이전트", "연결된 도구", "근거".
3. 빈 화면을 두지 않는다 — 처음 온 사용자도 다음 행동이 보여야 한다(기본 Agent
   카드·예시 요청).

## 1. 공통 셸 (전 화면 공통)

> ⚠ **아래 그림의 상단바가 틀렸다 (2026-08-12 · `58ed034`).** 프로젝트 컨텍스트
> 선택기를 **없앴다.** 지금 상단바에는 사용자 영역만 있다.
>
> 왜 — 상단바에 있다는 것은 「이건 모든 대화의 전제」라는 뜻인데, 회의록 정리처럼
> 프로젝트가 무의미한 요청에도 계속 고르라고 하게 된다. 프로젝트는 전제가 아니라
> **대화가 담기는 자리**다. 그 사실은 Chat 사이드바의 「프로젝트 > 대화」 계층이
> 말한다 → §2.
>
> 사이드바는 **접을 수 있다**(로고 옆 화살표, 상태 유지). 접으면 68px 만 남고
> 대화 목록이 그만큼 넓어진다. 라벨은 「Chat」이 아니라 **「채팅」**이다.

```
┌──────┬──────────────────────────────────────────────┐
│      │                                     [사용자] │  ← 상단바
│ 사이드│                                              │
│ 바 ←  │                                              │  ← 접기/펴기
│      │              콘텐츠 영역                      │
│ 💬 채팅                                               │
│ 🛠 에이전트(Builder)                                  │
│ 📁 프로젝트                                           │
│ ⚙ 설정                                               │
└──────┴──────────────────────────────────────────────┘
```

- **사이드바 4항목**: 채팅 / 에이전트 / 프로젝트 / 설정. Admin(Ops)은 기존대로
  별도 로그인(`/ops`) — 일반 셸에 안 보인다.
- **기존 네비에서 없어지는 것**: 대시보드 메뉴(리포트는 Chat에서 생성),
  업무 분배 계열 메뉴 전부(정적 4종은 8/10 삭제 완료).
  「+ 새 대화」 버튼도 셸에서 뺐다 — 대화 목록 하단으로 옮겼다(§2).
- ~~**상단바의 프로젝트 컨텍스트 선택기**: Q4 제안(팀 Chat + 프로젝트 컨텍스트
  선택)의 UI 구현체. "전체(팀)" 기본값 + 프로젝트 목록. `chat_session.proj_id`
  (nullable)와 1:1 대응.~~ → 위 정정 참조. `chat_session.proj_id` 와 1:1 이라는
  것은 여전히 맞고, **그 값을 정하는 자리**가 상단바에서 사이드바로 옮겨졌다.
- 온보딩 미완(커넥터 미연결) 시: Chat 진입은 허용하되 상단에 "Drive 연결 후
  문서 기반 요청이 가능합니다" 배너 + 설정 링크 (막지 않고 안내).
  > ⚠ ~~**아직 구현 안 됨 (8/11 확인).**~~ **2026-08-12 에 했다 — 다만 배너가
  > 아니다.** 팀이 없으면 에이전트가 0건이라 화면 전체가 죽어 있는데, 그 위에
  > 띠 한 줄을 붙여 봐야 죽은 화면은 그대로다. **빈 상태 자리를 통째로 「시작할

## 2. Chat 홈 레이아웃

> ⚠ **아래 그림도 2026-08-12 에 바뀌었다**(`58ed034`). 실제 모양:

```
┌──────────────┬───────────────────────────────────────┐
│ 대화 목록     │  📁 AI Platform            [새 대화]  │
│  회의록 정리… │───────────────────────────────────────│
│              │                                       │
│ 📁 AI Platform│   (메시지 스트림 영역)                 │
│    업무 뽑기 ⓧ│   - 사용자/에이전트 메시지             │
│    담당자…    │   - 진행 카드 (단계 표시)              │
│              │   - Jira 현황 카드                     │
│ 📁 SKN29…  ＋ │   - 근거 카드 (접기 · 기본 접힘)        │
│              │   - 확인 카드 (체크박스+승인)          │
│──────────────│───────────────────────────────────────│
│ [ + 새 대화 ] │  [무엇을 도와드릴까요?          ] [→]  │
└──────────────┴───────────────────────────────────────┘
      ↕ 너비 드래그로 조절 (200~460px, 저장됨)
```

- **에이전트 선택기가 없다.** 상단에는 이 대화가 어디에 속하는지만 있다 —
  프로젝트 이름, 또는 프로젝트가 없으면 「팀 전체 문서」.
- **대화 목록이 2계층**이다: 프로젝트 > 대화. **대화가 있는 프로젝트만** 나온다
  (사이드바는 돌아갈 대화를 찾는 곳이고, 빈 프로젝트는 돌아갈 것이 없다).
  프로젝트에 안 속한 대화는 **머리말 없이** 맨 위에 — 「프로젝트 없음」이라고
  쓰면 그런 이름의 프로젝트로 읽힌다.
- **「+ 새 대화」가 목록 맨 아래**에 붙어 있다(sticky). 누르면 위로 목록이 펼쳐져
  **어느 프로젝트에서 시작할지 고른다.** 첫 항목은 「팀 전체 문서」 — 프로젝트를
  안 고르는 것은 범위가 없어지는 게 아니라 팀으로 넓어지는 것이다.
- 스크롤은 **목록과 스트림 두 곳에서만** 일어난다. 셸이 창 높이를 고정한다.

### 빈 상태 (첫 진입)

> **두 가지다 (2026-08-12).** 사람 정보가 연결됐는지로 갈린다.
>
> **① 아직 아무것도 연결 안 됨 → 「시작할 준비를 해요」**
>
> ```
> 먼저 이것부터
>   사람 정보 — 연결하면 팀이 만들어집니다        [연결하기]
>
> 그다음, 필요한 만큼
>   문서 저장소   — 문서에서 업무를 뽑고 근거를 찾습니다
>   프로젝트 기록 — 진행 상황과 팀 부하를 봅니다
> ```
>
> **①과 ②③을 갈라 놓는 것이 핵심이다.** 셋을 같은 무게로 세우면 「셋 다 해야
> 한다」로 읽히는데 **필수는 사람 정보 하나뿐**이다 — 그것만 있어도 팀원 조회·
> 부하 리포트·부재 조회·웹 검색은 돈다. 자리 이름은 Connector 탭과 같은 말을
> 쓴다(작업 9).
>
> **② 연결은 됐고 대화만 없음 → 아래 원문대로.**

대화가 없을 때 스트림 영역에:

- 기본 제공 Agent 카드 2~3장 (업무 추출 / 부하 리포트) — 카드 클릭 = 해당
  Agent 선택 + 예시 요청 입력창에 채움
- 예시 요청 문구: "이번 프로젝트 문서를 참고해서 업무를 정리해줘" (E2E 발화와
  통일 — 데모 때 빈 상태에서 시작해도 자연스럽다)

## 3. 상태 정의 5종

| 상태 | 화면 | 비고 |
|---|---|---|
| 빈 상태 | Agent 카드 + 예시 요청 | 위 §2 |
| 스트리밍 중 | 진행 카드 갱신, 입력창 → 중단 버튼 | NDJSON 스트림 |
| 확인 대기 | 확인 카드 활성, 입력창 비활성(또는 "수정 요청" 허용 — 미결정 ③) | E2E STEP 6 |
| 부분 실패 | 결과 카드에 성공/실패 분리 표기 + 재시도 | 성공처럼 뭉개지 않기 |
| 오류 | 스트림 중단 지점에 오류 카드(마지막 `error` 줄), 이전 결과물은 보존 | 기존 NDJSON 오류 규약 |

## 4. 기존 화면·컴포넌트 재사용 요약 (IA §5 기반)

- `TaskCard` 근거 열람(63-152행) → 근거 카드. **이식하면 "새로고침 시 결과
  소실" 문제가 chat_message 적재로 함께 해결**된다.
- 진행 모달 → 진행 카드 (인라인화).
- `/tasks/distribution/documents`의 기준 문서 선택 UI → Agent가 되물을 때의
  문서 선택 카드 (E2E STEP 2 되묻기).
- 대시보드 벤토 위젯 → 부하 리포트 카드의 시각 요소 (Q13 제안: 리포트 뷰어로
  재활용).

## 5. 구현 범위

- **P0 (E2E 필수)**: 셸+사이드바, 세션 목록/생성, 에이전트 선택기, 스트리밍
  메시지, 진행 카드, 근거 카드, 확인 카드, 결과 카드(부분 실패 포함), 빈 상태.
- **P1**: 프로젝트 컨텍스트 선택기(팀 전체만으로도 E2E는 성립), 오류 카드 세분화.
- **여력**: 대화 검색, 세션 이름 자동 요약, 리포트 카드 내 인터랙티브 차트.

## 6. 미결정 (멘토링·팀 확인)

1. 세션 목록에 프로젝트 필터를 줄 것인가 (Q4 결과에 종속).
2. 확인 대기 중 "수정 요청" 채팅 허용 여부 — 허용하면 자연스럽지만 Loop 상태
   관리가 복잡해진다. v1은 체크박스 조정만 허용 제안.
3. 기본 제공 Agent를 사용자가 숨길/복제할 수 있는가 — v1은 고정 제안.
