# 화면 문구 정리표 — A안(사무적·간결)

> 2026-08-18 PM 결정. **반영 완료**(`npm run build` 통과). 이 표가 그 근거다.
>
> ⚠ **「생각하는 중」은 바꾸지 않았다**(PM). 「로딩 중 → 생각하는 중」으로만 바꿔도
> 사용자가 군말 없이 기다린다는 조사 결과가 있다. **같은 근거로 「읽는 중」·「관련
> 문서 좁히는 중」도 유지한다** — 셋 다 *무엇을 하는 중인지* 말해 준다. 반대로
> 「준비 중」과 「몇 분 걸립니다…」는 아무 일도 설명하지 않아 바꿨다.
>
> 화면에 보이는 한국어 문구 **1,040개**를 전수로 뽑아, 구어체 신호(구어체 명사형 ·
> 막연한 시간 · 불필요한 안심 · 1인칭 · 구어 종결)가 걸린 **75건**을 추렸다.
> 그중 **바꿀 것 48건**, **그대로 둘 것 27건**이다.
>
> **「~해 주세요」를 전부 바꾸지는 않는다.** 그건 한국어 UI의 표준 지시문이다.
> 바꾸는 것은 **말맛을 위해 늘어진 것**과 **정보가 없는 안심 문구**다.

## 0. 판단 기준

| | 바꾼다 | 그대로 둔다 |
|---|---|---|
| 동사 | 「뽑기·붙이기·걷기」처럼 **이 제품이 지어낸 구어** | 「접기·찾기·만들기」처럼 **일반 UI 표준어** |
| 시간 | 「몇 분·잠시·곧」처럼 **막연한 것** | 초·건수처럼 **실제 값** |
| 안심 | 「~않아도 됩니다」처럼 **정보가 없는 것** | 결과를 알리는 문장 |
| 인칭 | 「저희가 ~해 드립니다」 | 「~하세요」 (표준 지시문) |

### 1-5. 「~해 주세요」 → 「~하세요」 (17)

입력 지시문은 명령형으로 통일한다. **의미가 바뀌지 않고 길이만 줄어든다.**

```

운영자 이메일과 비밀번호를 모두 입력해 주세요 → 이메일과 비밀번호를 모두 입력하세요
올바른 JSON 형식으로 입력해 주세요   → 올바른 JSON 형식으로 입력하세요

다른 형식으로 저장해 다시 올려 주세요 → 다른 형식으로 저장해 다시 업로드하세요
```

## 2. 그대로 둔다 (27건)

| 문구 | 왜 |
|---|---|
| 즐겨찾기 · 즐겨찾기 추가 · 즐겨찾기 해제 | **표준 UI 용어다.** 「선호 항목」 따위로 바꾸면 오히려 낯설다 |
| 비밀번호 찾기 | 표준 용어 |
| 접기 · 사이드바 접기 · 메뉴 접기 | 표준 용어 |
| 문서 목록 · 도구 선택 · 업무 추출 | 이미 사무적 |
| 확인해 주세요(사람의 판단을 청하는 자리) | 지시가 아니라 **요청**이다 — 「가입한 이메일이 본인 것인지 확인해 주세요」처럼 사용자가 사실을 확인해야 하는 곳 |
| 저희가 대신 합니다(등록 대행 안내) | 실제로 **우리가 하는 일**이라 1인칭이 맞다. 다만 문장은 §1-4 에서 다듬는다 |

## 4. 반영 결과

- §1-5 기계적 치환 **17건** · §1-1~1-4 **26건** · 표에 없었지만 같은 규칙인 지시문 **12건**
- 재검사: 구어체 신호 **75건 → 23건**. 남은 23건은 §2(그대로 둘 것)와
  「사용자에게 사실 확인을 청하는 자리」다 — 「가입한 이메일이 본인 것인지
  확인해 주세요」처럼 **지시가 아니라 요청**인 문장은 「~해 주세요」가 맞다.
- `npm run build`(tsc -b) 통과.

## 5. 다음에 문구를 쓸 때
