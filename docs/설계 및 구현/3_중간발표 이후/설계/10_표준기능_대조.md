> 2026-08-10 작성. 시중 Agent Platform(watsonx Orchestrate·Copilot Studio·
> Dify·OpenAI GPTs 계열)이 일반적으로 갖춘 기능에 우리 설계(IA·Figma 07 페이지)를
> 대조한 것. 용도 두 가지 — ① 8/12 멘토링 "범위가 현실적인가" 논의의 근거,
> ② 최종발표 Future Work 슬라이드의 재료("몰라서 뺀 게 아니라 알고 뺐다").

## 판정 기준

- **✅ 있음** — v1 설계·Figma에 화면/구조로 존재
- **🔶 구조만** — 8/8 멘토링 범위 계층의 "구조적으로 설계할 것" — v1 구현 제외가 합의된 것

## 2. Future Work 문안 (발표·멘토링용 — 그대로 옮겨 쓸 수 있게)

> v1은 "하나의 업무가 처음부터 끝까지, 근거와 승인을 거쳐 동작하는 것"에
> 집중했다. 다음은 표준 플랫폼 기능 중 알고 미룬 것들이다:
>
> 1. **Chat 파일 첨부** — 현재는 Connector로 연결된 문서만 근거로 쓴다. 첨부
>    파일도 같은 파싱 파이프라인을 타면 되므로 구조 변경 없이 확장 가능.
> 2. **에이전트 버전 관리** — 저장 즉시 팀에 노출되는 v1 정책을 draft→publish로
>    분리. Permission 확장과 함께 간다.
> 3. **예약 실행** — 부하 리포트처럼 주기 실행이 자연스러운 Agent부터. 실행
>    경로는 Harness 로그·실행 레코드를 그대로 재사용.
> 4. **에이전트 API 노출·임베드, 템플릿 카탈로그, 자연어 Workflow 생성** —
>    플랫폼 확장 단계의 것.

## 3. Q&A 대비 한 줄 답변

- "파일을 그냥 올리면 안 되나요?" → "됩니다 — 같은 파이프라인을 타면 되는 확장이라 구조에 이미 자리가 있고, v1은 팀 문서 기반 시나리오에 집중했습니다."
- "만든 에이전트가 바로 팀 전체에 보이면 위험하지 않나요?" → "v1은 팀 신뢰 경계 안이라 즉시 공유입니다. draft→publish 분리는 Permission 확장과 함께 Future Work로 잡아 뒀습니다."
- "리포트를 매주 자동으로 받을 수 있나요?" → "예약 실행은 Future Work입니다. 실행 구조(Harness)는 이미 재사용 가능하게 설계돼 있습니다."
