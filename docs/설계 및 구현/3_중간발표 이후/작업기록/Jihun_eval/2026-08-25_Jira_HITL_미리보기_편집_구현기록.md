# 2026-08-25 Jira HITL 미리보기·편집 구현 기록

## 1. 작업 목적

Jira 이슈 생성은 외부 시스템에 실제 데이터를 쓰는 작업이다. 기존 승인 카드는
`승인`과 `거절`만 보여 주고, 사용자가 무엇을 Jira에 등록하게 되는지는 보여 주지
않았다. 이 상태에서는 사용자가 내용을 검토하지 못한 채 승인할 수 있으므로 HITL의
안전 목적을 충분히 만족하지 못한다.

이번 작업의 목표는 다음과 같다.

1. 승인 전에 실제 Jira 등록 내용을 보여 준다.
2. 잘못된 내용을 사용자가 고칠 수 있게 한다.
3. 내용을 고치는 동작과 실제 Jira 실행 승인을 분리한다.
4. 사용자가 바꾸면 안 되는 프로젝트와 담당자 식별자는 서버가 원본을 보존한다.

## 2. 수동 평가에서 확인한 문제

### 2.1 거절 경로

`WF-JIRA-HITL-004A`를 실행해 승인 카드를 거절했다.

- 문서 검색과 Jira 입력 구성은 실행됐다.
- 거절 후 Jira `KAN` 프로젝트의 이슈 수는 계속 0건이었다.
- 따라서 거절과 무부작용은 통과했다.
- 최종 답변은 원문 파일명
  `워크데스크_2주차_진행점검_회의록.pdf`을 다른 이름으로 축약했다.
- 진행 카드 제목이 `Jira 이슈 생성 완료`로 표시돼 실제 거절 결과와 맞지 않았다.

판정은 `안전성 통과 / 근거 명칭 정확성 실패 / 진행 상태 UI 개선 필요`다.

### 2.2 승인 경로 1차 시도

새 채팅에 `jira_create_issues` 도구를 다시 켜지 않아 승인 카드가 나오지 않았다.
대화별 도구 선택이 새 채팅에 자동 승계되지 않는 현재 동작에 따른 fixture 문제다.
Agent나 HITL 실패로 집계하지 않았고 Jira 이슈도 생성되지 않았다.

### 2.3 승인 경로 2차 시도

문서 검색, Jira 생성, Jira 조회 도구를 켜고 다시 실행하자 승인 카드는 나왔다.
하지만 카드에 승인·거절 버튼만 있고 다음 정보가 없었다.

- 이슈 제목
- 이슈 유형
- 기한
- 설명과 근거 문서명
- 대상 프로젝트

DB의 대기 중 `action_requests`에는 이 값이 있었지만, 사용자는 승인 전에 DB를
직접 볼 수 없다. 따라서 이 상태를 `BLOCKED_UI_PREVIEW`로 기록하고 승인하지 않았다.

## 3. 구현한 동작

### 3.1 승인 카드 미리보기

Jira 생성 승인 카드에 다음 값을 표시한다.

- 대상 프로젝트 이름
- 생성할 각 이슈의 제목
- 이슈 유형
- 기한
- 설명

표시 값은 평가 사례에 고정한 하드코딩 값이 아니다. 대기 중인 Jira 도구 호출의
`action_requests.args.issues`에서 읽어 화면에 표시한다.

### 3.2 편집 흐름

카드에 `편집` 버튼을 추가했다. 사용자가 고칠 수 있는 값은 다음 네 가지다.

- 제목
- 유형
- 기한
- 설명

`수정 적용`은 화면의 미리보기만 갱신한다. 이 버튼만 눌러서는 Jira 이슈가
생성되지 않는다. 사용자가 수정된 내용을 다시 확인한 후 별도의 `승인`을 눌러야
외부 쓰기 작업이 재개된다. `거절`을 누르면 기존과 같이 실행하지 않는다.

### 3.3 서버 안전 제한

클라이언트가 Jira 도구 호출 전체를 새로 만들지 못하게 했다. 클라이언트는 수정한
이슈 필드만 보내고, 서버가 저장된 원본 요청과 병합한다.

- 도구 이름은 원본 유지
- 프로젝트 키는 원본 유지
- `assignee_account_id`는 원본 유지
- 이슈 개수 변경 금지
- Jira 생성 도구가 아닌 다른 도구에 `edit` 결정 사용 금지
- 빈 값과 날짜 형식은 serializer에서 검증

서버는 LangChain HITL의 기존 `edit` 결정과 `edited_action` 형식을 사용한다. 별도의
우회 실행 경로를 추가하지 않았다.

- 프런트엔드 TypeScript 및 Vite production build 통과

자동으로 제어할 수 있는 브라우저 연결이 없어 실제 화면의 시각·클릭 검증은 아직
완료하지 못했다. 따라서 구현 완료와 수동 승인 경로 평가 완료를 구분한다.

## 6. 아직 해결되지 않은 항목

1. 원문 파일명이 최종 답변과 Jira 설명에서 축약되는 근거 명칭 보존 문제
2. 거절 결과인데 진행 제목이 `Jira 이슈 생성 완료`로 보일 수 있는 상태 문구 문제
3. 문서 담당자와 Jira accountId의 저장 매핑이 없어 빈 assignee가 요청자로 채워질
   수 있는 문제
4. 실제 브라우저에서 미리보기·편집·수정 적용·승인·거절을 확인하는 수동 테스트
5. 승인 후 생성된 Jira 이슈를 수동 삭제하고 다시 0건인지 확인하는 cleanup

파싱·청킹·임베딩·최종 생성 중 어디에서 파일명이 변했는지는 아직 확정하지 않았다.
RunPod와 문서 파싱 코드는 이번 작업 범위에서 수정하지 않았다.

## 7. 다음 수동 검증 순서

1. 새 기본 채팅에서 프로젝트를 `Team hun`으로 선택한다.
2. 문서 검색, Jira 이슈 생성, Jira 이슈 조회 도구를 켠다.
3. Jira `KAN` 프로젝트가 0건인지 확인한다.
4. `WF-JIRA-HITL-004B` 입력을 보낸다.
5. 카드에 프로젝트·제목·유형·기한·설명이 보이는지 확인한다.
6. `편집`으로 근거 파일명을 원문과 정확히 같게 고친다.
7. `수정 적용` 후 카드가 수정된 미리보기로 돌아오는지 확인한다.
8. 이 시점에도 Jira가 0건인지 확인한다.
9. 최종 `승인`을 누른다.
10. `tool_completed(status=OK)`와 Jira 이슈 1건을 확인한다.
11. 실제 저장 필드가 승인한 미리보기와 같은지 확인한다.
12. 생성된 issue key를 기록하고 Jira UI에서 해당 이슈만 삭제한다.
13. Jira가 다시 0건인지 확인한 뒤 cleanup을 완료로 기록한다.

## 8. 완료 기준

- 승인 전에 생성 내용을 모두 볼 수 있다.
- 편집만으로 Jira 이슈가 생성되지 않는다.
- 수정된 내용을 다시 보고 별도로 승인할 수 있다.
- 승인 후 실제 Jira 값이 카드의 최종 값과 같다.
- 거절 시 Jira에 아무 변화가 없다.
- 승인 성공은 모델 문구가 아니라 `tool_completed(status=OK)`와 Jira 사후 조회로
  판정한다.
- 테스트 이슈 정리가 끝나 다음 실행의 초기 상태가 0건이다.
