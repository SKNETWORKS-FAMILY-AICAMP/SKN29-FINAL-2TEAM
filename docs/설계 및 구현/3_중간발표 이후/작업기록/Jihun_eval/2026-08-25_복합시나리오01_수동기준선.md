## 원래 자동 판정이 실패한 이유

최초 dataset v1은 `document_search`만 최대 3회 허용했다. 하지만 세 실행 모두
사용자가 요청한 "현재 검색할 수 없는 문서 범위"를 확인하기 위해 읽기 전용
`document_list`를 1회 사용했다. 1·2회차는 검색 3회까지 더해 전체 도구 호출이
4회였고, 3회차는 전체 호출이 3회였지만 `document_list`가 허용 목록에 없었다.

따라서 원래 계약으로는 0/3 실패지만, 이는 답변이나 제품의 실패가 아니라 정상적인
대체 실행 경로를 지나치게 좁게 작성한 평가 fixture 문제다. 최초 v1 결과는 수정하지
않고 원시 결과에 그대로 보존했다.

## dataset v2 보정

- 필수 도구: `document_search`
- 허용 도구: `document_search`, `document_list`
- `document_search`: 최대 3회
- `document_list`: 최대 1회
- 전체 도구 호출: 최대 4회
- 두 도구의 호출 순서: 고정하지 않음

이 기준으로 재판정하면 세 실행 모두 성공한다. 특정 실행 순서를 정답으로 하드코딩한
것이 아니라, 동일한 목표를 안전하게 달성하는 두 읽기 도구와 각각의 호출 상한을
정의한 것이다.

## 추가로 발견한 문제

2·3회차 진행 카드에 `Synthesizing...`, `Clarifying...`, `Considering...` 같은 영문
내부 작업 메모 형태의 문구가 노출됐다. 최종 답변의 정확성 문제는 아니지만 사용자
화면의 일관성과 이해도를 떨어뜨리는 UI 품질 문제다. 이번 평가에서는 제품 코드를
수정하지 않고 관찰 결과만 남겼다.
