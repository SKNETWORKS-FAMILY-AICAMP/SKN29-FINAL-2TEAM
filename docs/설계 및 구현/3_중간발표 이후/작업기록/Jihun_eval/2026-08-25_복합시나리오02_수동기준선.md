## 반복된 정확성 실패

세 답변 모두 김도윤을 문서에 기재된 `프로젝트 오너`이며 전체 일정과 부서 간
의사결정을 담당한다고 표현했다. 실제 검색 문서에서 확인되는 내용은 다음이다.

- 프로젝트 배경과 목표를 공유함
- 요구사항 정의서 최종본 배포 담당
- 파일럿 대상 부서 선정과 공지 담당
- Project Management와 Agile 기술을 보유함

이 근거로 회의 조율 후보를 **추천**할 수는 있지만, 현재 프로젝트 오너라는 기존
직책을 사실로 확정할 수는 없다. 같은 과장이 3회 모두 반복됐기 때문에 우연한 문장
실수가 아니라 안정적으로 재현되는 근거 과장 실패로 판정했다. 평가 fixture를
완화하지 않는다.

개선은 `김도윤`이라는 이름을 프롬프트나 코드에 넣는 방식으로 하지 않는다. 사람
추천에서 `현재 담당·오너·책임자` 같은 기존 역할 주장은 검색 근거에 해당 표현이
직접 있을 때만 사실로 말하고, 그 외에는 `이 역량 때문에 후보로 제안한다`고
구분하는 일반 규칙으로 해결해야 한다.

## 도구 선택 관찰

1회차에는 `task_extraction`을 호출했다가 프로젝트 문맥이 없어 실패했고,
`project_list`도 추가로 호출했다. 사용자는 역할과 후보 추천을 요청했지 업무 추출을
요청하지 않았으므로 `task_extraction`은 명확한 도구 오선택이다.

2·3회차는 `document_search`, `people_list`, `workload_report`, `absence_list`를
각각 한 번만 호출해 정상 경로로 안정됐다. 따라서 `project_list`를 새 정상 경로로
추가하거나 평가 기준을 완화하지 않고 1회성 실패로 보존한다.

## 성능 관찰

2회차 `document_search` 한 번이 28.025초 걸려 전체 실행이 44.399초까지 늘었다.
3회차의 같은 검색은 1.336초였다. 모델 호출과 token은 2·3회차가 비슷하므로 큰
latency 변동은 모델 추론량보다 문서 검색 구간에서 발생했다.

표본이 3개뿐이라 이를 성능 예산으로 바로 사용하지 않는다. 검색 서비스의 warm/cold,
RunPod 대기, 재시도 여부를 OpenTelemetry 구간 계측 전까지 계속 별도로 기록한다.

## UI 관찰

세 번 모두 진행 카드에 영문 내부 작업 메모가 노출됐다. 1회차 최종 답변 끝에는
불필요한 비한국어 문자열도 붙었다. 이는 정확성 실패와 별개로 사용자 화면 품질
문제로 유지한다.
