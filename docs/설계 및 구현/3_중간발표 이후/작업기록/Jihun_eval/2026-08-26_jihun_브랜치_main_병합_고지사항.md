## 1. `2e07626` — Jira 이슈 등록 정책이 바뀌었다 (가장 중요)

**담당자 기본값이 바뀌었다.** 이전에는 담당자를 안 정하고 등록을 요청하면
서버가 **요청한 사람 본인**으로 자동 채웠다. 지금은 **기본이 미배정**이고,
사용자가 명시적으로 "나에게 배정해줘"라고 말했을 때만(`assign_to_requester:
true`) 요청자 본인으로 채운다.

- **왜 바꿨나**: 실제 대화에서 담당자를 안 정했는데 조용히 요청자에게
  배정되는 것이, 사용자가 기대한 동작이 아니었다(2026-08-25 Jira HITL
  구현기록). 명시적으로 요청했을 때만 배정하는 쪽이 안전하다.
- **프로젝트 키 해석도 강제됐다.** 채팅에서 이미 프로젝트를 골랐다면
  (`proj_id`가 있으면) 모델이 보낸 `project_key`는 무시하고 저장된 연결을
  정본으로 쓴다. 모델이 프로젝트 이름을 Jira key로 오인하거나 임의의 key를
  추측해도 실제로는 그 채팅이 속한 프로젝트에만 등록된다.
- **부분 실패 처리도 바뀌었다.** 이슈 생성이 전부 실패했는데(`created=[]`,
  `failed=[...]`) 도구 상태가 `OK`로 보고되던 버그를 고쳐, 이제 하드 실패
  (`ToolInputError`)로 처리한다.
- **영향 범위**: `services/harness/registry.py`의 `_jira_create_issues`,
  `_fill_default_jira_assignee`, `BUILTIN_TOOLS`의 도구 설명. 프런트
  (`liveChat.ts`)는 승인 카드에 `jiraAssigneeMode`(`requester`/`explicit`/
  `unassigned`)를 추가로 보여준다.
- **병합 후 확인할 것**:
  - [ ] 담당자를 안 정하고 Jira 등록을 승인하면 실제로 미배정으로 생성되는지
  - [ ] "나에게 배정해줘"라고 말했을 때만 요청자 본인으로 배정되는지
  - [ ] 승인 카드에 담당자 처리 방식이 표시되는지
  - [ ] 이슈 생성이 전부 실패하면 성공으로 위장되지 않고 실패로 보고되는지

### 5.1 `285a15d` — 파일 삭제(`delete`) 도구 재활성화 (가장 중요 — 미해결 권한 격차 포함)

`DEFAULT_EXCLUDED_BUILTIN_TOOLS`에서 `delete`를 뺐다. HITL 미구현을 이유로
막아뒀던 조건이 풀렸다는 뜻이라, 이제 모든 Agent가 `delete`를 쓸 수 있고
다른 side-effect 도구와 똑같이 승인 카드를 거친다.

**커밋 자체가 밝힌 미해결 문제**: `delete`는 `services/agent_runtime/skills/
service.py`의 역할별 권한 검사(TEAM 스킬은 팀장만 등록 가능)를 거치지 않는
별개 경로다. 그 결과 **팀원도 채팅으로 "이 TEAM 스킬 파일 지워줘"라고 요청하고
스스로 승인해서 삭제할 수 있다** — 등록은 팀장 전용인데 삭제는 역할 구분이
없는 비대칭 상태다. 이 저장소 코드에 아직 이 간극을 막는 로직이 없다.

- **영향 범위**: `services/agent_runtime/runtime_policy.py`, 모든 Agent의
  파일 시스템 접근.
- **병합 후 확인할 것**:
  - [ ] `delete` 호출도 승인 카드를 거치는지(다른 side-effect 도구와 동일하게)
  - [ ] 팀원 계정으로 TEAM 스킬 파일 삭제를 요청·승인했을 때 실제로 지워지는지
    확인하고, 이 프로젝트의 권한 정책상 허용 범위인지 담당자와 정한다
  - [ ] 오늘 저녁 시점까지는 이 격차를 막는 후속 커밋이 없다 — 병합 시점에

### 5.2 `e41a63e` — 장기 메모리 저장 기준 프롬프트 전면 개편

`memory/backend.py`의 `_MEMORY_ROUTING_PROMPT`가 영문 요약 지침에서 한국어
상세 지침으로 바뀌었다. 무엇을 저장하고 저장하지 않는지의 **판단 기준
자체가 더 구체화**됐다.

- 저장 대상: 응답 형식·커뮤니케이션·작업 방식 선호, 반복적으로 쓰는 도구
  방식, 장기 유지되는 개인적 사실, "앞으로/항상/기억해줘" 같은 명시적 요청

- 저장할 때 대화 문장을 그대로 옮기지 않고 독립된 사실 문장으로 정규화해서
  적으라는 지침과 예시가 새로 추가됨
- `<agent_memory>` 블록이 방금 저장한 내용을 반영 못할 수 있으니
  "지금 뭐가 저장돼 있어?" 같은 질문에는 `read_file`로 다시 읽으라는 안내 추가
- **영향 범위**: `services/agent_runtime/memory/backend.py`. 오늘 이 문서
  묶음의 장기 메모리 검증(`2026-08-26_작업03.md` "장기 메모리 핵심 3개 검증")은
  이 프롬프트가 적용된 상태에서 수행했다.
- **병합 후 확인할 것**:
  - [ ] 저장 기준이 더 엄격해져서 원래 저장돼야 할 선호가 저장 안 되는
    회귀가 없는지
  - [ ] 정규화 지침 때문에 저장된 문장이 원래 사용자 발화와 의미가 달라지지
    않는지
