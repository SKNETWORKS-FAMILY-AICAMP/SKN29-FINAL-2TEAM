## 0. 무엇을 왜 고쳤나

멘토 지적: 새 에이전트를 만들면 `agent_versions.max_iterations` DB 기본값이
**6**이라, 도구 호출 몇 번만 거쳐도 흔한 멀티스텝 작업이 하드컷으로 끊긴다.
게다가 상한에 닿았을 때 `ModelCallLimitMiddleware`/`ToolCallLimitMiddleware`가
`exit_behavior="error"`라 진행 중이던 대화가 영어 원문 예외 메시지로 그냥
끝났다.

**처음 잡은 방향(폐기)** — `exit_behavior`를 `"error"`→`"end"`로 바꾸면
"지금까지 결과를 정리해서 최종 답변을 만들어 준다"고 예상했는데, 라이브러리
소스(`langchain/agents/middleware/model_call_limit.py:201-208`,
`tool_call_limit.py:422-464`)를 직접 읽어 보니 **모델을 다시 호출하지 않고
고정 영어 문자열을 그대로 최종 메시지로 박아 넣을 뿐**이었다(도구 쪽은 같은
배치의 다른 병렬 호출까지 실행 없이 종료시킨다). 실행이 실제로는 미완료인데
겉보기엔 정상 종료처럼 보일 위험이 있어 폐기했다.

**실제로 적용한 수정**

| 구분 | 내용 | 파일 |
|---|---|---|
| A | `exit_behavior`는 `"error"`로 그대로 둔다(이미 executor의 broad `except`가 `EVENT_ERROR`로 잡아 "성공 위장" 문제가 없었다). 대신 두 예외(`ModelCallLimitExceededError`/`ToolCallLimitExceededError`)를 위한 한국어 메시지 분기를 추가 | `services/agent_runtime/executor.py` `_agent_execution_failure_event()` |
| B | `agent_versions.max_iterations` 기본값 6→10 (아키텍처 설계 §3.1-2가 원래 "기본 10"이었는데 `serializers.py`가 6으로 되어 있던 것 — `작업목록.md` "함께 정할 것" 미결 사안 정리) | 아래 §1 표 |
| B 부속 | `_apply.py`가 **컬럼 존재만** 보고 **기본값**은 안 봐서, 이번처럼 `ALTER COLUMN ... SET DEFAULT`만 하는 마이그레이션은 안 돌려도 `--check`가 "전부 있다"고 거짓 보고할 수 있었다 — `EXPECTED_DEFAULTS` 체크를 추가 | `DB/migrations/_apply.py` |

C(Builder 화면에 `max_iterations` 입력 컨트롤 추가)와 D(팀별 GP 상한 조정
필드)는 이번 범위에 넣지 않았다 — §4 참고.

## 2. `main` 병합 뒤 반드시 할 일

1. **로컬 DB 갱신** — 새 마이그레이션이 있으니 확인부터:
   ```bash
   python DB/migrations/_apply.py --check
   ```
   `agent_versions.max_iterations`가 `[값다름]`으로 나오면:
   ```bash
   python DB/migrations/_apply.py DB/migrations/2026-08-25_agent_versions_max_iterations_default_10.sql
   ```
2. **배포는 마이그레이션을 자동으로 안 돌린다**(`.github/workflows/deploy.yml`,
   `infra/deploy.sh` 둘 다). 운영 RDS에 **배포 직후 손으로** 돌려야 한다:
   ```bash
   ssh -i skn29-2team-key.pem ubuntu@43.200.114.119
   cd ~/SKN29-Final-2Team
   docker compose -f infra/docker/docker-compose.aws.yml exec -T web \
     python DB/migrations/_apply.py --check
   # [값다름]으로 나오면
   docker compose -f infra/docker/docker-compose.aws.yml exec -T web \
     python DB/migrations/_apply.py DB/migrations/2026-08-25_agent_versions_max_iterations_default_10.sql
   ```
   ⚠ `deploy.sh`는 git 갱신 → 컨테이너 빌드 순서다. **컨테이너 안에 이 마이그레이션
   파일이 들어온 것을 확인한 뒤** 돌릴 것(2026-08-21 관측성 문서에서 이미 한 번
   겪은 함정).
3. **전체 테스트**를 한 번 돌릴 것 — `tests/test_migration_apply.py`,
   `tests/test_executor.py`, `apps/agents` 관련 테스트를 특히 확인.
