# 에이전트 빌더 구현 명세 — v1~v4 재구성 가이드 (2026-08-11 작업분)

> 이 문서는 작업기록이 아니라 **명세서**다. `docs/2026-08-11_에이전트_..._v1~v4.md` 네 편이 "왜 이렇게 결정했는가"를 담은 서사라면, 이 문서는 "메인에 무엇을 어떻게 추가해야 지금과 같은 결과가 나오는가"만 담는다. 배경 설명은 최소화하고 파일·코드·순서를 정확히 적는다.

## 0. 전제 — 이 문서가 다루지 않는 것

**메인에는 v1 작업을 시작하기 전 상태(pre-v1)가 이미 구현되어 있다고 전제한다.** 아래는 이미 있다고 가정하고 이 문서에서 다시 다루지 않는 것들이다.

- DB 테이블: `agent`, `agent_tool`, `mcp_server`, `mcp_tool`, `chat_session`, `chat_message`, `agent_run`, `tool_call`, `doc_meta` (`DB/migrations/2026-08-11_agent_platform.sql`) — 이미 생성되어 있고 마이그레이션도 적용되어 있다고 전제한다.
- `chat_session.agent_id`·`agent_run.agent_id`를 nullable로 바꾸는 마이그레이션(`DB/migrations/2026-08-11_chat_agentless.sql`) — **반드시 실제 DB에 적용까지 되어 있어야 한다.** v2 작업 중 이 마이그레이션 파일은 만들어져 있었지만 실제 DB에 적용이 안 돼 `NotNullViolation`이 난 적이 있다(§8 참고). 메인에서 재현할 때 파일 존재 여부가 아니라 **실제 스키마에 컬럼이 nullable인지**를 먼저 확인할 것.
- `services/harness/registry.py`의 기본 골격 — `Tool` dataclass(이 시점엔 `category` 필드 없음), `ToolNotAllowed`, 내장 도구 5종(`document_search`, `workload_report`, `task_extraction`, `jira_create_issues`, `jira_get_issues`), `load_for_refs`/`load_for_agent`/`resolve`.
- `services/harness/runner.py`의 기본 Agent Loop — `run_agent`(당시엔 `draft`·`dry_run` 파라미터 없음), 승인 게이트, 선기록 트레이스 연동, `_default_model` 등. `services/harness/scaffold.py`(당시엔 `write_todos` 언급 없는 3단락짜리 스캐폴드), `services/harness/trace.py`, `services/harness/__init__.py`.
- `backend/db/agent_platform.py` 전체 — `AgentRepository`, `AgentRunRepository`, `ToolCallRepository`, `ChatSessionRepository`, `ChatMessageRepository`, `McpServerRepository`, `AgentCrudRepository`(생성·수정·삭제·목록 CRUD와 `_check_tool_refs`/`_replace_tools`) 전부 이미 있다.
- `apps/agents/` 앱의 기본 CRUD 뼈대 — `AgentWriteSerializer`, `agent_response()`, `AgentListCreateAPIView`, `AgentDetailAPIView`, `AgentToolCatalogAPIView`(단, 이때는 `category` 필드 없이), `apps/agents/api_urls.py`의 `""`·`"tools/"`·`"<str:agent_id>/"` 세 라우트, `config/urls.py`의 `path("api/agents/", include("apps.agents.api_urls"))` 마운트.
- 프런트 `frontend/src/pages/AgentEditPage/AgentEditPage.tsx` — Profile/행동 지시/참고 데이터·도구 세 카드 레이아웃, 저장·취소 버튼. 단, "참고 데이터·도구" 카드의 도구 선택 UI는 **인라인 체크리스트**였다(팝업 없음, §2에서 팝업으로 교체).
- 프런트 `frontend/src/api/agents.ts`의 기본 `Agent`/`AgentWrite`/`ToolChoice`(단 `category` 필드 없음) 인터페이스와 `listAgents`/`getAgent`/`createAgent`/`updateAgent`/`deleteAgent`/`listToolChoices`.
- `frontend/src/api/client.ts`(`ApiError`, `apiRequest`, `apiUpload`) — 단 `streamNdjson`은 **v2에서 신규 추가**됐다(§3 참고, 당시 전제엔 없었다).
- `frontend/src/api/mcp.ts`, `frontend/src/components/index.ts`가 내보내는 공용 컴포넌트 라이브러리(`Button`/`Badge`/`Input`/`Select`/`Checkbox`/`Modal`/`Icon`/`AppShell`/`useToast` 등) — prop 형태만 이 문서에서 사용하고 재구현하지 않는다.
- `tests/test_harness.py`의 기본 테스트 스켈레톤(`echo_tool` 헬퍼 등, 단 `Tool`에 `category`가 추가되며 v1에서 한 번 손을 댐).

이 문서는 위 baseline 위에 **v1 → v2 → v3 → v4 순서로 무엇을 더하고 고치는지**만 다룬다. 각 절 끝에는 그 버전이 끝난 시점의 관련 파일 "완성본"을 실어서, 중간 diff를 일일이 따라가지 않고 완성본만 복사해도 되게 했다(§6은 v4까지 끝난 **최종** 전체 완성본 모음이다 — 시간이 없으면 §6만 보고 그대로 만들어도 된다).

`Tool` dataclass:

class Tool:
    ref: str
    name: str
    description: str
    input_schema: dict[str, Any]
    handler: Callable[..., Any]
    #: 카탈로그 화면에서 묶어 보여주기 위한 표시용 분류일 뿐, 동작에는

def _task_status(*, account_id: str) -> dict[str, Any]:
    """팀의 Jira 연동 업무 현황을 그대로 보여준다. `_workload_report`와 달리
    계산(부하·여유)을 하지 않고, 개별 업무 목록 자체를 묻는 질문에 쓴다."""
    tasks = ExistTaskRepository.list_for_team(account_id)
    person_ids = [t["assignee_person_id"] for t in tasks if t.get("assignee_person_id")]
    persons = lookup_persons(person_ids)

    def _iso(value: Any) -> str | None:
        return value.isoformat() if hasattr(value, "isoformat") else value

    return {
        "task_count": len(tasks),
        "tasks": [
            {
                "summary": t["summary"], "status": t["status"],
                "status_category": t["status_category"],
                "assignee_name": (persons.get(t["assignee_person_id"]) or {}).get("name"),
                "due_at": _iso(t.get("due_at")), "estimate": t.get("estimate"),
                "remaining": t.get("remaining"), "spent": t.get("spent"),
                "project_key": t.get("project_key"), "project_name": t.get("project_name"),
                "jira_issue_id": t.get("jira_issue_id"),
            }
            for t in tasks
        ],
    }


def _team_member_info(*, account_id: str) -> dict[str, Any]:
    """팀원 명부 — 이름·직무·조직·보유 스킬·오늘 부재 여부."""
    team_id = AccountRepository.team_id(account_id)
    person_ids = TeamRepository.member_person_ids(team_id)
    persons = list_persons(person_ids=person_ids)
    today = date.today()
    on_leave = {
        row["person_id"]
        for row in list_absences(person_ids=person_ids, period_start=today, period_end=today)
    }
    return {
        "members": [
            {
                "name": p["name"], "job_role": p["job_role"], "org_name": p["org_name"],
                "level_name": p["level_name"],
                "skills": [s["name"] for s in list_person_skills(p["person_id"])],
                "on_leave_today": p["person_id"] in on_leave,
            }
            for p in persons
        ],
    }


def _jira_update_issue(*, account_id: str, issue_key: str, changes: dict[str, Any]) -> dict[str, Any]:
    """Jira 이슈 한 건의 제목·설명·담당자·마감일을 바꾼다. 상태 전이는 다루지 않는다."""

### 1.3 `ToolPickerModal.tsx` — v1에서 신규 생성한 전체 코드

*(v4까지 이 파일은 수정되지 않았다 — 아래가 곧 최종본이다.)*

```tsx
import { useState } from 'react';
import { Badge, Button, Checkbox, Icon, Modal } from '../../components';
import type { BadgeTone } from '../../components';
import type { ToolChoice } from '../../api/agents';
import type { McpServer } from '../../api/mcp';
import pageStyles from './AgentEditPage.module.css';
import styles from './ToolPickerModal.module.css';

type Tab = 'builtin' | 'mcp' | 'create';

const TABS: { id: Tab; label: string }[] = [
  { id: 'builtin', label: '툴 선택' },
  { id: 'mcp', label: 'MCP 서버 선택' },
  { id: 'create', label: '툴 생성' },
];

const SERVER_STATUS: Record<McpServer['status'], { tone: BadgeTone; label: string }> = {
  CONNECTED: { tone: 'success', label: '연결됨' },
  UNCHECKED: { tone: 'neutral', label: '미확인' },
  ERROR: { tone: 'warning', label: '연결 실패' },
};

export interface ToolPickerModalProps {
  open: boolean;
  onClose: () => void;
  builtinTools: ToolChoice[];
  mcpServers: McpServer[];
  toolRefs: string[];
  onToggle: (ref: string) => void;
  onGoToMcpSettings: () => void;
}

export function ToolPickerModal({
  open, onClose, builtinTools, mcpServers, toolRefs, onToggle, onGoToMcpSettings,
}: ToolPickerModalProps) {
  const [tab, setTab] = useState<Tab>('builtin');

  return (
    <Modal open={open} onClose={onClose} title="도구 선택" width={640} footer={<Button onClick={onClose}>완료</Button>}>
      <div className={styles.tabs} role="tablist">
        {TABS.map((item) => (
          <button key={item.id} type="button" role="tab" aria-selected={tab === item.id}
            className={[styles.tab, tab === item.id ? styles.tabOn : ''].filter(Boolean).join(' ')}
            onClick={() => setTab(item.id)}>
            {item.label}
          </button>
        ))}
      </div>

      {tab === 'builtin' && (
        <div className={pageStyles.toolList}>
          {builtinTools.map((toolItem) => {
            const checked = toolRefs.includes(toolItem.tool_ref);
            return (
              <div key={toolItem.tool_ref}
                className={[pageStyles.toolRow, checked ? pageStyles.toolRowOn : ''].filter(Boolean).join(' ')}>
                <Checkbox checked={checked} onChange={() => onToggle(toolItem.tool_ref)} />
                <div className={pageStyles.toolText}>
                  <strong>{toolItem.name}{toolItem.side_effect && <span className={pageStyles.gate}> · 승인 필요</span>}</strong>
                  <span>{toolItem.description}</span>
                </div>
              </div>
            );
          })}
          {builtinTools.length === 0 && <p className={pageStyles.help}>기본 제공 도구가 없습니다.</p>}
        </div>
      )}

      {tab === 'mcp' && (
        <div className={styles.serverList}>
          {mcpServers.length === 0 && <p className={pageStyles.help}>아직 연결한 MCP 서버가 없습니다.</p>}
          {mcpServers.map((server) => {
            const chip = SERVER_STATUS[server.status];
            const usable = server.status === 'CONNECTED';
            return (
              <div key={server.mcp_server_id} className={styles.serverGroup}>
                <div className={styles.serverHead}>
                  <span className={styles.serverName}>{server.name}<Badge tone={chip.tone}>{chip.label}</Badge></span>
                  <span className={pageStyles.help}>{server.endpoint_url}</span>
                </div>
                {!usable && (
                  <p className={pageStyles.help}>
                    {server.status === 'UNCHECKED' ? '설정에서 연결을 확인해야 도구를 고를 수 있습니다.' : '연결이 실패한 서버입니다. 설정에서 다시 확인해 주세요.'}
                  </p>
                )}
                {usable && server.tools.length === 0 && <p className={pageStyles.help}>이 서버는 제공하는 도구가 없습니다.</p>}
                {usable && server.tools.length > 0 && (
                  <div className={pageStyles.toolList}>
                    {server.tools.map((tool) => {
                      const ref = `mcp:${tool.mcp_tool_id}`;
                      const checked = toolRefs.includes(ref);
                      return (
                        <div key={tool.mcp_tool_id}
                          className={[pageStyles.toolRow, checked ? pageStyles.toolRowOn : ''].filter(Boolean).join(' ')}>
                          <Checkbox checked={checked} disabled={!tool.enabled} onChange={() => onToggle(ref)} />
                          <div className={pageStyles.toolText}>
                            <strong>{tool.name}<span className={pageStyles.gate}> · 승인 필요</span></strong>
                            <span>{tool.description || (tool.enabled ? '' : '비활성화된 도구입니다.')}</span>
                          </div>
                        </div>
                      );
                    })}
                  </div>
                )}
              </div>
            );
          })}
          <button type="button" className={styles.settingsLink} onClick={onGoToMcpSettings}>
            <Icon name="arrow-right" size={14} />
            MCP 서버 관리로 이동
          </button>
        </div>
      )}

      {tab === 'create' && (
        <div className={styles.createTab}>
          <p className={pageStyles.help}>팀에서 직접 도구를 만드는 기능은 아직 준비 중입니다. 지금은 기본 제공 도구와 연결한 MCP 서버의 도구만 쓸 수 있습니다.</p>
          <Button variant="outline" disabled>새 도구 만들기 (준비 중)</Button>
        </div>
      )}
    </Modal>
  );
}
```

### 2.5 프런트 — `streamNdjson` (`api/client.ts` 신규 함수)

```ts
export async function streamNdjson<TEvent>(
  path: string, token: string | null | undefined, body: unknown,
  onEvent: (event: TEvent) => void, signal?: AbortSignal,
): Promise<void> {
  const headers: Record<string, string> = { 'Content-Type': 'application/json' };
  if (token) headers.Authorization = `Bearer ${token}`;
  const response = await fetch(`${API_BASE_URL}${path}`, { method: 'POST', headers, body: JSON.stringify(body), signal });
  if (!response.ok || !response.body) {
    const failure = await response.json().catch(() => null);
    throw parseErrorBody(failure, response.status);
  }
  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop() ?? '';
    for (const line of lines) {
      if (!line.trim()) continue;
      onEvent(JSON.parse(line) as TEvent);
    }
  }
}
```

### 3.1 도구별 직접 확인 — `check_tools()`

**문제**: 채팅식 테스트 실행(`runBuilderTest`)은 모델이 어떤 도구를 부를지 스스로 정한다. 실사용 중 "업무 지연 점검" 같은 질문에서 문서 검색만 불리고 나머지 세 도구는 한 번도 안 불리는 상황이 실제로 확인됐다 — 데이터가 없거나 모델이 안 부른 도구는 영영 확인이 안 된다.

**해결**: 모델 판단 없이 선택한 도구 전부를 순서대로 직접 호출하는 별도 경로를 만든다.

`services/harness/runner.py`에 신규 함수 (최종본은 §6.1):

```python
_CHECK_EXCLUDED_TOOLS = frozenset({"task_extraction"})  # 몇 분 걸리는 파이프라인이라 제외

def check_tools(*, team_id, account_id, tool_refs, arguments_by_ref=None) -> list[dict[str, Any]]:
    """선택한 도구를 모델 없이 순서대로 하나씩 직접 불러 본다.
    side_effect 도구는 실시간 승인자가 없으므로 항상 시뮬레이션한다.
    도구 하나가 실패해도 나머지는 계속 확인한다."""
    arguments_by_ref = arguments_by_ref or {}
    agent = {"team_id": team_id, "instruction": "", "model": None, "reasoning_effort": None, "max_iterations": 1}
    tools = registry.load_for_refs(tool_refs=tool_refs, team_id=team_id)
    context = {"account_id": account_id}
    results = []
    with trace.run(agent_id=None, session_id=None, parent_run_id=None) as run_trace:
        for tool_ref in tool_refs:
            if tool_ref in _CHECK_EXCLUDED_TOOLS:
                results.append({"tool_ref": tool_ref, "tool_name": tool_ref, "status": "SKIPPED",
                                 "detail": "여기서는 확인하지 않습니다 — 프로젝트의 업무 추출 화면을 쓰세요."})
                continue
            try:
                tool = registry.resolve(tools, tool_ref)
            except ToolNotAllowed as exc:
                results.append({"tool_ref": tool_ref, "tool_name": tool_ref, "status": "FAILED",
                                 "error_code": "ToolNotAllowed", "detail": str(exc)})
                continue
            arguments = arguments_by_ref.get(tool_ref) or {}
            if tool.side_effect:
                results.append({"tool_ref": tool_ref, "tool_name": tool.name, "status": "SIMULATED", "arguments": arguments})
                continue
            try:
                with trace.tool_call(run_id=run_trace.run_id, tool_ref=tool_ref, arguments=arguments):
                    output = tool.handler(**{**arguments, **_injected(tool, agent, context)})
            except Exception as exc:  # noqa: BLE001 - 하나 실패해도 나머지를 계속 확인한다
                results.append({"tool_ref": tool_ref, "tool_name": tool.name, "status": "FAILED", "error_code": exc.__class__.__name__})
            else:
                results.append({"tool_ref": tool_ref, "tool_name": tool.name, "status": "OK", "output": output})
    return results
```

"수정한 내용으로 다시 검증하기" 버튼으로 재검증할 수 있는 휴먼인더루프 구조. (이 시점엔 `overall`이 `pass`/`warn` 두 가지뿐이고, `reject` 관련 분기는 v3 §3.4에서 뒤이어 추가된다 — 최종 코드는 §6.12에 있다.)

### 3.3 검증 → 도구 확인 → 대화 테스트를 한 흐름으로 묶기

**문제 의식**: 검증(`InstructionCheckPanel`)·도구 확인(`ToolCheckPanel`)·대화 테스트(기존 `TestRunModal`)가 각각 따로 노는 탭이면, 사람이 순서를 안 지켜도 다음 단계로 넘어갈 수 있어 저장 전 확인이 형식적이 된다.

**해결**: `TestRunModal.tsx`를 `Stage = 'check' | 'tools' | 'chat'` 세 단계 스테퍼로 재구성한다. 검증 단계에서 확정한 설명·지시문이 콜백(`onApplyDescription`/`onApplyInstruction`)으로 부모(`AgentEditPage`)의 상태에 반영되고, 그 상태가 다음 단계(도구 확인·대화 테스트)의 입력이 된다. 뒤 단계에는 "← N단계로 돌아가기" 버튼을 둔다. 모달을 열 때마다 1단계(`check`)로 리셋한다.

이 시점의 `TestRunModal.tsx`가 v3에서 도달하는 구조는 v4에서 `grounded` 표시만 추가된 채 그대로 최종본이 된다 — **전체 코드는 §6.11을 그대로 쓰면 된다.**

### 3.4 빌더 검증 고도화 — 스캐폴드 인지, `reject` 등급, `instruction_check`

**문제 의식**: v2의 검증은 (1) 모든 에이전트에 이미 공통으로 적용되는 스캐폴드 내용(계획 안내, 도구 호출 상한, 근거 원칙, 승인)을 모르는 채로 판단해서 사용자 지시문이 스캐폴드와 겹치거나 모순되는지 못 짚었고, (2) description/behavior가 사실상 텅 비어 있어도 "warn"으로만 처리해 저장을 막지 못했다.

**결정**:
- 검토 프롬프트에 `COMMON_SCAFFOLD.format(max_iterations=6)` 텍스트를 그대로 삽입해, 모델이 "이미 공통으로 적용되는 것"과 "이 에이전트만의 지시"를 구분하게 한다(빌더가 만드는 에이전트는 `max_iterations=6` 고정값을 쓴다).
- `instruction_check` 필드 신규 — behavior에 트리거 조건·절차·도구 사용 기준·판단 기준 네 요소가 있는지를 별도로 본다(도구가 선택되지 않았으면 도구 사용 기준은 안 봄).
- `overall`에 `reject` 등급 추가 — description·behavior가 사실상 비어 있거나 "알아서 처리" 같은 위임 표현뿐이라 다듬어서 쓸 지시문이 안 나오는 수준. `reject`면 `refined_instruction`은 빈 문자열(내용을 지어내지 않는다). `reject_reason`에 무엇을 다시 써야 하는지 담는다.
- **`pass`/`warn`은 저장을 막지 않는다는 기존 원칙(`빌더_에이전트_구체화.md` §3)은 그대로 두고, `reject`만 예외로 저장을 막는다.** 이 예외는 그 원칙 문서를 고치지 않고 이 v3 문서에만 기록해 둔다(설계 문서와 사후 결정을 구분).
- `AgentEditPage.tsx`의 `handleSave()`에 저장 직전 검증 호출을 추가 — `reject`면 저장을 막고 에러 메시지를 보여준다. 검증 서비스 자체가 실패(예: 설정 문제)하면 저장을 막지 않는다(그 실패까지 게이트로 쓰면 배포 사고가 된다).

`services/agent_builder/service.py` 최종 코드는 §6.4, `InstructionCheckPanel.tsx` 최종 코드(`reject`일 때 `refined_instruction`으로 덮어쓰지 않는 분기 포함)는 §6.12, `AgentEditPage.tsx`의 `handleSave()` 게이트는 §6.10에 있다.

## 4. v4 — 계획 도구(write_todos) + 근거 없는 답변 코드 레벨 탐지(grounded)

기존 프로젝트의 deep-agents 조사 문서(`docs/설계 및 구현/3_중간발표 이후/설계/3_Harness_조사/`)가 "Task Planning은 적용"이라고 결론 내렸지만 실제 코드엔 계획 도구가 없었던 간극을 메운다. **filesystem/sub-agent/memory 등 그 문서가 "적용 안 함"으로 정리한 항목은 이번에도 건드리지 않는다.**

### 4.1 `write_todos` 계획 도구

`services/harness/registry.py`에 `PLANNING_TOOL` 신규. **`BUILTIN_TOOLS`에는 넣지 않는다** — 사용자가 빌더에서 켜고 끄는 업무 도구가 아니라 공통 스캐폴드와 같은 층의 메타 도구라서, 도구 카탈로그(`/agents/tools/`)·도구별 확인(`check_tools`)·빌더 검증의 `tool_match_check` 어디에도 안 나타난다. 대신 `load_for_refs()` 끝에서 무조건 주입한다:

```python
def load_for_refs(*, tool_refs: list[str], team_id: str | None) -> dict[str, Tool]:
    allowed = set(tool_refs)
    available: dict[str, Tool] = {ref: tool for ref, tool in BUILTIN_TOOLS.items() if ref in allowed}
    if team_id is not None:
        for row in AgentRepository.mcp_tools(team_id):
            if row["tool_ref"] in allowed:
                available[row["tool_ref"]] = _mcp_tool(row)
    available[PLANNING_TOOL.ref] = PLANNING_TOOL  # 계획 도구는 선택 목록과 무관하게 항상 붙는다
    return available
```

`services/harness/runner.py`의 agentless 분기(`agent_id is None`)도 같은 원칙으로 `tools = {PLANNING_TOOL.ref: PLANNING_TOOL}`(기존엔 `{}`)로 바꾼다.

상태 저장소를 별도로 두지 않는다 — 이 도구 호출의 결과(`function_call_output`)가 그대로 `messages`에 남아 다음 턴에 모델이 다시 읽는 것으로 "기억"된다(deep-agents의 "recitation"과 같은 효과를 상태 저장 없이 낸다).

`services/harness/scaffold.py`의 `COMMON_SCAFFOLD`도 함께 고친다 — `[진행 방식]` 절에 "한두 번의 도구 호출로 끝나는 간단한 요청은 계획 없이 바로 처리", "여러 단계로 나뉘는 요청이면 write_todos로 목록을 적고, 다시 적을 땐 항상 전체 목록을 새로 보낸다"를 명시한다. 최종 텍스트는 §6.3에 있다.

### 4.2 `grounded` 플래그

**근거 없이 추측하지 않는다는 원칙 중 절반은 코드로 확인할 수 있다.** 완전한 사실 검증(도구 결과와 답변 문장을 대조)까지는 못 해도, "쓸 수 있는 도구가 있는데 하나도 안 부르고 답을 냈는가"는 결정적으로 셀 수 있다.

`run_agent` 안에서 (`write_todos`는 새 사실을 확인하는 도구가 아니라 계획 도구라 이 판단에서 뺀다):

```python
made_tool_call = False

def _grounded() -> bool:
    data_tools_available = any(ref != PLANNING_TOOL.ref for ref in tools)
    return made_tool_call or not data_tools_available
```

도구 호출 루프 안, `registry.resolve` 성공 직후: `if tool_ref != PLANNING_TOOL.ref: made_tool_call = True`.

`EVENT_RESULT`를 내보내는 세 지점(정상 종료, 최대 반복 도달) 모두에 `"grounded": _grounded()` 필드를 추가한다.

프런트: `frontend/src/api/agents.ts`의 `BuilderTestEvent`의 `result` variant에 `grounded?: boolean` 추가. `TestRunModal.tsx`에서 `resultComplete && resultGrounded === false`일 때 경고 문구("이 답변은 쓸 수 있는 도구를 하나도 안 부르고 나왔습니다…") 표시(§6.11에 반영됨).

`COMMON_SCAFFOLD`의 `[근거]` 절에도 한 줄 추가: "쓸 수 있는 도구가 있는데 하나도 안 부르고 사실을 단정하면 안 된다. 도구 없이 바로 답해도 되는 건 일반적인 설명이나 확인이 필요 없는 질문뿐이다."

### 4.3 테스트 수정 (`tests/test_harness.py`)

`write_todos`가 항상 주입되므로 기존 두 테스트의 기대값을 고친다:

- `허용 목록에 없는 내장 도구는 빠진다`: `set(tools) == {"document_search"}` → `{"document_search", "write_todos"}`.
- `agent_id가 없으면 도구 없이 기본 대화로 돈다`(이름도 `업무_도구_없이`로 변경): `tools == []` → `[t.ref for t in tools] == ["write_todos"]`.

이 절만 보고 그대로 파일을 만들어도 v4까지의 결과와 동일하다. 순서상 이해가 필요 없다면 §1~§4는 건너뛰고 여기부터 시작해도 된다.

### 6.1 `services/harness/runner.py` (전체)

```python
"""Agent Loop.

`run_agent` 는 **chat_session 에 종속되지 않는 순수 실행기**다. 대화가 있으면
`context["session_id"]` 로 받아 로그에만 적고, 없으면 없는 대로 돈다.

이벤트는 NDJSON 으로 그대로 흘려보낼 수 있는 dict 다.
"""

from __future__ import annotations

import json
import logging
from dataclasses import dataclass, field
from types import GeneratorType
from typing import Any, Callable, Iterator

from django.conf import settings

from backend.db.agent_platform import AgentRepository
from services.harness import registry, scaffold, trace
from services.harness.registry import PLANNING_TOOL, Tool, ToolNotAllowed

logger = logging.getLogger(__name__)

EVENT_STAGE = "stage"
EVENT_TOOL_CALL_STARTED = "tool_call_started"
EVENT_TOOL_CALL_FINISHED = "tool_call_finished"
EVENT_AWAITING_CONFIRMATION = "awaiting_confirmation"
EVENT_RESULT = "result"
EVENT_ERROR = "error"


@dataclass
class ModelDecision:
    text: str | None = None
    tool_calls: list[dict[str, Any]] = field(default_factory=list)
    token_in: int = 0
    token_out: int = 0
    raw_items: list[dict[str, Any]] = field(default_factory=list)


ModelClient = Callable[[str, list[dict[str, Any]], list[Tool]], ModelDecision]

_AGENTLESS_MAX_ITERATIONS = 4


def run_agent(
    agent_id: str | None,
    user_input: str,
    context: dict[str, Any] | None = None,
    *,
    model: ModelClient | None = None,
    draft: dict[str, Any] | None = None,
    dry_run: bool = False,
) -> Iterator[dict[str, Any]]:
    context = context or {}
    approved = set(context.get("approved_tool_calls") or [])
    pending = context.get("resume_tool_call")

    if draft is not None:
        agent: dict[str, Any] = {
            "team_id": draft.get("team_id"),
            "instruction": draft.get("instruction") or "",
            "model": draft.get("model"),
            "reasoning_effort": draft.get("reasoning_effort"),
            "max_iterations": draft.get("max_iterations") or 6,
        }
        tools: dict[str, Tool] = registry.load_for_refs(
            tool_refs=draft.get("tool_refs") or [], team_id=agent["team_id"]
        )
    elif agent_id is None:
        agent = {
            "team_id": None, "instruction": "", "model": None,
            "reasoning_effort": None, "max_iterations": _AGENTLESS_MAX_ITERATIONS,
        }
        tools = {PLANNING_TOOL.ref: PLANNING_TOOL}
    else:
        agent = AgentRepository.get(agent_id)
        tools = registry.load_for_agent(agent_id=agent_id, team_id=agent["team_id"])

    system = scaffold.compose(instruction=agent["instruction"] or "", max_iterations=agent["max_iterations"])
    call_model = model or _default_model(agent)

    messages: list[dict[str, Any]] = list(context.get("messages") or []) or [
        {"role": "user", "content": user_input}
    ]

    made_tool_call = False

    def _grounded() -> bool:
        data_tools_available = any(ref != PLANNING_TOOL.ref for ref in tools)
        return made_tool_call or not data_tools_available

    with trace.run(
        agent_id=agent_id, session_id=context.get("session_id"), parent_run_id=context.get("parent_run_id"),
    ) as run_trace:
        limit = agent["max_iterations"]
        for step in range(1, limit + 1):
            yield {"type": EVENT_STAGE, "step": step, "total": limit, "label": "생각하는 중"}

            if pending is not None:
                decision = ModelDecision(tool_calls=[pending])
                pending = None
            else:
                decision = call_model(system, messages, list(tools.values()))
                run_trace.count_iteration()
                run_trace.count_tokens(token_in=decision.token_in, token_out=decision.token_out)

                if not decision.tool_calls:
                    yield {"type": EVENT_RESULT, "text": decision.text or "", "complete": True, "grounded": _grounded()}
                    return

                messages.extend(_assistant_turn(decision))

            for call in decision.tool_calls:
                tool_ref = call["tool_ref"]
                arguments = call.get("arguments") or {}

                try:
                    tool = registry.resolve(tools, tool_ref)
                except ToolNotAllowed as exc:
                    messages.append(_tool_turn(call, {"error": str(exc)}))
                    continue

                if tool_ref != PLANNING_TOOL.ref:
                    made_tool_call = True

                if tool.side_effect and tool_ref not in approved:
                    if dry_run:
                        yield {"type": EVENT_TOOL_CALL_STARTED, "tool_call_id": None, "tool_ref": tool_ref, "tool_name": tool.name}
                        yield {"type": EVENT_TOOL_CALL_FINISHED, "tool_call_id": None, "tool_ref": tool_ref,
                               "tool_name": tool.name, "status": "SIMULATED", "arguments": arguments}
                        messages.append(_tool_turn(call, {"simulated": True, "note": "테스트 실행이라 실제로 호출하지 않았습니다."}))
                        continue
                    yield {
                        "type": EVENT_AWAITING_CONFIRMATION, "run_id": run_trace.run_id, "tool_ref": tool_ref,
                        "tool_name": tool.name, "arguments": arguments,
                        "resume": {"messages": messages, "tool_call": call},
                    }
                    return

                tool_call_id = None
                try:
                    with trace.tool_call(run_id=run_trace.run_id, tool_ref=tool_ref, arguments=arguments) as tool_call_id:
                        yield {"type": EVENT_TOOL_CALL_STARTED, "tool_call_id": tool_call_id, "tool_ref": tool_ref, "tool_name": tool.name}
                        raw = tool.handler(**{**arguments, **_injected(tool, agent, context)})
                        if isinstance(raw, GeneratorType):
                            output = yield from _forward(raw, tool_ref, tool_call_id)
                        else:
                            output = raw
                except Exception as exc:  # noqa: BLE001 - 도구 실패로 run 을 끝내지 않는다
                    logger.exception("도구 실행 실패: %s (run=%s)", tool_ref, run_trace.run_id)
                    error_code = exc.__class__.__name__
                    yield {"type": EVENT_TOOL_CALL_FINISHED, "tool_call_id": tool_call_id, "tool_ref": tool_ref, "status": "FAILED", "error_code": error_code}
                    messages.append(_tool_turn(call, {"error": f"도구 실행 실패: {error_code}"}))
                else:
                    yield {"type": EVENT_TOOL_CALL_FINISHED, "tool_call_id": tool_call_id, "tool_ref": tool_ref, "status": "OK"}
                    messages.append(_tool_turn(call, output))

        yield {
            "type": EVENT_RESULT, "text": "", "complete": False, "stopped_reason": "max_iterations",
            "iterations": limit, "grounded": _grounded(),
        }


_CHECK_EXCLUDED_TOOLS = frozenset({"task_extraction"})


def check_tools(
    *, team_id: str | None, account_id: str, tool_refs: list[str],
    arguments_by_ref: dict[str, dict[str, Any]] | None = None,
) -> list[dict[str, Any]]:
    arguments_by_ref = arguments_by_ref or {}
    agent: dict[str, Any] = {"team_id": team_id, "instruction": "", "model": None, "reasoning_effort": None, "max_iterations": 1}
    tools = registry.load_for_refs(tool_refs=tool_refs, team_id=team_id)
    context = {"account_id": account_id}

    results: list[dict[str, Any]] = []
    with trace.run(agent_id=None, session_id=None, parent_run_id=None) as run_trace:
        for tool_ref in tool_refs:
            if tool_ref in _CHECK_EXCLUDED_TOOLS:
                results.append({"tool_ref": tool_ref, "tool_name": tool_ref, "status": "SKIPPED",
                                 "detail": "여기서는 확인하지 않습니다 — 프로젝트의 업무 추출 화면을 쓰세요."})
                continue
            try:
                tool = registry.resolve(tools, tool_ref)
            except ToolNotAllowed as exc:
                results.append({"tool_ref": tool_ref, "tool_name": tool_ref, "status": "FAILED",
                                 "error_code": "ToolNotAllowed", "detail": str(exc)})
                continue

            arguments = arguments_by_ref.get(tool_ref) or {}

            if tool.side_effect:
                results.append({"tool_ref": tool_ref, "tool_name": tool.name, "status": "SIMULATED", "arguments": arguments})
                continue

            try:
                with trace.tool_call(run_id=run_trace.run_id, tool_ref=tool_ref, arguments=arguments):
                    output = tool.handler(**{**arguments, **_injected(tool, agent, context)})
            except Exception as exc:  # noqa: BLE001 - 하나 실패해도 나머지를 계속 확인한다
                logger.exception("도구 개별 확인 실패: %s", tool_ref)
                results.append({"tool_ref": tool_ref, "tool_name": tool.name, "status": "FAILED", "error_code": exc.__class__.__name__})
            else:
                results.append({"tool_ref": tool_ref, "tool_name": tool.name, "status": "OK", "output": output})
    return results


def _forward(events: Iterator[dict[str, Any]], tool_ref: str, tool_call_id: str | None):
    while True:
        try:
            event = next(events)
        except StopIteration as stop:
            return stop.value
        yield {**event, "tool_ref": tool_ref, "tool_call_id": tool_call_id}


def _injected(tool: Tool, agent: dict[str, Any], context: dict[str, Any]) -> dict[str, Any]:
    if tool.ref == "document_search" or tool.ref.startswith("mcp:"):
        return {"team_id": agent["team_id"]}
    if tool.ref == "task_extraction":
        return {"proj_id": context.get("proj_id"), "account_id": context.get("account_id")}
    if tool.ref in _ACCOUNT_SCOPED_TOOLS:
        account_id = context.get("account_id")
        if not account_id:
            raise ValueError(f"{tool.ref} 는 요청자 계정(account_id)이 필요합니다.")
        return {"account_id": account_id}
    return {}


_ACCOUNT_SCOPED_TOOLS = frozenset(
    {"workload_report", "jira_create_issues", "jira_get_issues", "jira_update_issue", "task_status", "team_member_info"}
)


def _assistant_turn(decision: ModelDecision) -> list[dict[str, Any]]:
    if decision.raw_items:
        return list(decision.raw_items)
    return [{"role": "assistant", "content": decision.text or ""}]


def _tool_turn(call: dict[str, Any], output: Any) -> dict[str, Any]:
    return {"type": "function_call_output", "call_id": call.get("id"), "output": json.dumps(output, ensure_ascii=False, default=str)}


def _default_model(agent: dict[str, Any]) -> ModelClient:
    from openai import OpenAI

    api_key = settings.OPENAI_API_KEY
    if not str(api_key).strip():
        raise RuntimeError("OPENAI_API_KEY 가 없습니다.")

    client = OpenAI(api_key=api_key, timeout=300, max_retries=1)
    model_name = agent.get("model") or settings.OPENAI_MODEL
    effort = agent.get("reasoning_effort") or settings.OPENAI_REASONING_EFFORT

    def call(system: str, messages: list[dict[str, Any]], tools: list[Tool]) -> ModelDecision:
        response = client.responses.create(
            model=model_name, service_tier=settings.OPENAI_SERVICE_TIER, reasoning={"effort": effort},
            tools=[_tool_spec(tool) for tool in tools] or None,
            input=[{"role": "system", "content": system}, *messages],
        )
        usage = response.usage
        return ModelDecision(
            text=response.output_text or None,
            tool_calls=[
                {"id": item.call_id, "tool_ref": item.name, "arguments": json.loads(item.arguments or "{}")}
                for item in response.output if item.type == "function_call"
            ],
            token_in=getattr(usage, "input_tokens", 0) or 0,
            token_out=getattr(usage, "output_tokens", 0) or 0,
            raw_items=[_echoable(item) for item in response.output],
        )

    return call


def _echoable(item: Any) -> dict[str, Any]:
    return item.model_dump(exclude={"status"}, exclude_none=True)


def _tool_spec(tool: Tool) -> dict[str, Any]:
    return {"type": "function", "name": tool.ref, "description": tool.description, "parameters": tool.input_schema}

def _write_todos(*, todos: list[dict[str, Any]]) -> dict[str, Any]:
    normalized: list[dict[str, str]] = []

        status = item.get("status")

[근거]
- **근거 없이 추측하지 않는다.** 문서나 도구 결과로 확인한 것만 말한다.
- 확인하지 못한 것은 비워 두고 "확인하지 못했다"고 적는다. 그럴듯한 값을 채우지 않는다.
- 사실을 말할 때는 어느 문서·어느 도구에서 나온 것인지 함께 밝힌다.
- 쓸 수 있는 도구가 있는데 하나도 안 부르고 사실을 단정하면 안 된다. 도구 없이
  바로 답해도 되는 건 일반적인 설명이나 확인이 필요 없는 질문뿐이다.

[외부 변경]
- 외부 시스템을 바꾸는 도구(이슈 생성 등)는 사용자 승인 없이 부르지 않는다.
  무엇을 만들지 먼저 보여주고 확인을 받는다.
"""


def compose(*, instruction: str, max_iterations: int) -> str:
    system = COMMON_SCAFFOLD.format(max_iterations=max_iterations)
    if instruction.strip():
        system = f"{system}\\n[이 에이전트의 지시]\\n{instruction.strip()}\\n"
    return system
```

> v4 이전(pre-v4)에는 `[진행 방식]`의 write_todos 관련 두 줄과 `[근거]`의 마지막 줄("쓸 수 있는 도구가 있는데...")이 없었다 — 3~4단락짜리 더 짧은 문구였다. 위가 v4까지 반영된 최종본이다.

```python
"""빌더 에이전트 — BuilderInput 한 건을 검토한다.

behavior(자연어 행동 지시)를 instruction으로 다듬는 일과, description/behavior가
명확한지·선택한 도구가 behavior와 맞는지 확인하는 일을 한 번의 구조화 출력으로 묶는다.

**pass/warn은 저장을 막지 않는다.** 단, reject는 다르다 — description/behavior가
사실상 비어 있거나 위임 표현뿐이라 다듬어서 쓸 지시문이 나오지 않는 수준이면
reject다. 호출하는 화면이 다음 단계 진행을 막는 데 쓴다.
"""

from __future__ import annotations

from typing import Any, Literal

from django.conf import settings
from openai import OpenAI
from pydantic import BaseModel, Field

from services.document_pipeline.errors import PipelineConfigurationError
from services.harness.scaffold import COMMON_SCAFFOLD

# 빌더가 생성하는 에이전트는 항상 max_iterations=6 고정값을 쓴다.
_SCAFFOLD_TEXT = COMMON_SCAFFOLD.format(max_iterations=6)


class DescriptionCheck(BaseModel):
    note: str | None = None


class InstructionCheck(BaseModel):
    note: str | None = None


class ToolMatchCheck(BaseModel):
    missing_tools: list[str] = Field(default_factory=list)
    unused_tools: list[str] = Field(default_factory=list)


class BuilderCheckResult(BaseModel):
    refined_instruction: str
    description_check: DescriptionCheck
    instruction_check: InstructionCheck
    tool_match_check: ToolMatchCheck
    overall: Literal["pass", "warn", "reject"]
    reject_reason: str | None = None


_SYSTEM_PROMPT = (
    "에이전트 빌더 검토 담당이다. 사용자가 자연어로 적은 행동 지시(behavior)를 다듬어 "
    "실행용 지시문으로 만들고, 설명·행동 지시·도구 선택이 서로 맞는지 확인한다.\\n\\n"
    "아래는 이 팀의 모든 에이전트에 이미 공통으로 적용되는 스캐폴드 문구다 — 개별 "
    "behavior가 이 내용을 반복하거나 이 내용과 모순되는지 판단할 때 참고하라:\\n"
    "---\\n" + _SCAFFOLD_TEXT + "\\n---\\n\\n"
    "네 가지를 본다.\\n"
    "(1) refined_instruction — behavior 문장을 정리한다. 위 스캐폴드가 이미 다루는 "
    "내용(계획 안내, 도구 호출 상한, 근거 원칙, 외부 변경 승인)은 다시 적지 않는다. "
    "behavior에 없는 지시를 새로 지어내지 않는다. overall이 reject면 이 필드는 빈 "
    "문자열로 둔다 — 다듬을 실질 내용이 없다는 뜻이다.\\n"
    "(2) description_check — description에 동사(뭘 하는지) · 대상(뭐에 대해) · 산출물"
    "(뭘 내는지) 세 요소가 있는지 본다. 있으면 note는 null, 애매하면 무엇이 부족한지 "
    "한 문장으로 적는다.\\n"
    "(3) instruction_check — behavior에 다음 네 가지가 실질적으로 있는지 본다: "
    "① 트리거 조건(언제/어떤 요청에 반응하는지), ② 절차(무엇을 어떤 순서로 확인·처리"
    "하는지), ③ 도구 사용 기준(선택된 도구가 있다면 어떤 상황에서 그 도구를 쓰는지), "
    "④ 판단 기준(이 업무 도메인에서 무엇을 '문제/막힘/승인 필요'로 볼지 같은 구체적 "
    "기준값). 도구가 선택되지 않았으면 ③은 보지 않는다. 있으면 note는 null, 일부만 "
    "애매하면 무엇이 부족한지 한 문장으로 적는다. behavior가 스캐폴드 원칙과 모순되면"
    "(예: 근거 없이 답하라, 승인 없이 바로 실행하라) 그 모순도 note에 적는다.\\n"
    "(4) tool_match_check — behavior 문장에서 필요해 보이는 행위와 선택된 도구를 대조한다. "
    "behavior가 요구하는데 선택하지 않은 도구가 있으면 missing_tools에, 선택했는데 "
    "behavior에서 쓰일 것 같지 않은 도구가 있으면 unused_tools에 그 도구 이름을 적는다. "
    "확실하지 않으면 비워 둔다.\\n\\n"
    "overall 판정:\\n"
    "- reject — description과 behavior 중 하나라도 사실상 비어 있거나, '알아서', "
    "'적절히', '필요하면 처리' 같은 위임 표현뿐이라 위 ①~④ 중 단 하나도 구체적으로 "
    "추출할 수 없는 수준. 이건 다듬어서 고칠 문제가 아니라 사용자가 내용을 다시 써야 "
    "하는 문제다. reject_reason에 무엇을 채워야 하는지 한두 문장으로 적는다.\\n"
    "- warn — description_check/instruction_check/tool_match_check 중 하나라도 걸리지만 "
    "그래도 다듬어서 실행 가능한 지시문을 만들 수 있는 수준.\\n"
    "- pass — 셋 다 문제없음.\\n"
    "reject가 아니면 reject_reason은 null로 둔다."
)


def _tool_view(row: dict[str, Any]) -> dict[str, str]:
    return {"name": row["name"], "description": row.get("description") or ""}


def check_builder_input(
    *, name: str, description: str, behavior: str,
    selected_tools: list[dict[str, Any]], unselected_tools: list[dict[str, Any]],
) -> BuilderCheckResult:
    if not str(settings.OPENAI_API_KEY).strip():
        raise PipelineConfigurationError("필수 OpenAI 설정이 없습니다: OPENAI_API_KEY")

    client = OpenAI(api_key=settings.OPENAI_API_KEY, timeout=120, max_retries=1)
    response = client.responses.parse(
        model=settings.OPENAI_PLAN_MODEL,
        service_tier=settings.OPENAI_SERVICE_TIER,
        reasoning={"effort": "low"},
        input=[
            {"role": "system", "content": _SYSTEM_PROMPT},
            {"role": "user", "content": (
                f"name={name}\\ndescription={description}\\nbehavior={behavior}\\n"
                f"선택된 도구={[_tool_view(row) for row in selected_tools]}\\n"
                f"선택 안 한 도구={[_tool_view(row) for row in unselected_tools]}"
            )},
        ],
        text_format=BuilderCheckResult,
    )
    result = response.output_parsed
    if result is None:
        raise ValueError("빌더 검토 모델이 구조화 결과를 반환하지 않았습니다.")
    return result
```

def _repository_error_response(exc: Exception) -> Response:
    if isinstance(exc, RecordNotFound):
        return Response({"detail": str(exc)}, status=status.HTTP_404_NOT_FOUND)
    if isinstance(exc, PermissionDenied):
        return Response({"detail": str(exc)}, status=status.HTTP_403_FORBIDDEN)
    if isinstance(exc, ReferenceNotFound):
        return Response({"detail": str(exc)}, status=status.HTTP_409_CONFLICT)
    if isinstance(exc, RepositoryError):
        return Response({"detail": str(exc)}, status=status.HTTP_400_BAD_REQUEST)
    return Response({"detail": "데이터베이스 요청을 처리할 수 없습니다.", "error": exc.__class__.__name__}, status=status.HTTP_503_SERVICE_UNAVAILABLE)


class AuthenticatedAPIView(APIView):
    authentication_classes = [BearerTokenAuthentication]
    permission_classes = [IsAuthenticated]


def _split(data: dict) -> tuple[dict, list[str]]:
    fields = dict(data)
    return fields, fields.pop("tool_refs")


class AgentListCreateAPIView(AuthenticatedAPIView):
    def get(self, request):
        try:
            rows = AgentCrudRepository.list_for_team(request.user.account_id)
        except (RepositoryError, psycopg.Error) as exc:
            return _repository_error_response(exc)
        return Response([agent_response(row) for row in rows])

    def post(self, request):
        serializer = AgentWriteSerializer(data=request.data)
        serializer.is_valid(raise_exception=True)
        fields, tool_refs = _split(serializer.validated_data)
        try:
            row = AgentCrudRepository.create(account_id=request.user.account_id, fields=fields, tool_refs=tool_refs)
        except (RepositoryError, psycopg.Error) as exc:
            return _repository_error_response(exc)
        return Response(agent_response(row), status=status.HTTP_201_CREATED)


class AgentDetailAPIView(AuthenticatedAPIView):

            row = AgentCrudRepository.get(agent_id=agent_id, account_id=request.user.account_id)
        except (RepositoryError, psycopg.Error) as exc:
            return _repository_error_response(exc)
        return Response(agent_response(row))

    def put(self, request, agent_id):

class AgentBuilderCheckAPIView(AuthenticatedAPIView):
    def post(self, request):
        serializer = BuilderCheckSerializer(data=request.data)
        serializer.is_valid(raise_exception=True)
        data = serializer.validated_data
        account_id = request.user.account_id

        try:
            mcp = AgentCrudRepository.team_tool_refs(account_id)
        except (RepositoryError, psycopg.Error) as exc:
            return _repository_error_response(exc)

        catalog = {row["tool_ref"]: row for row in builtin_tool_response() + mcp_tool_response(mcp)}
        selected_refs = set(data["tool_refs"])
        selected = [row for ref, row in catalog.items() if ref in selected_refs]
        unselected = [row for ref, row in catalog.items() if ref not in selected_refs]

        try:
            result = check_builder_input(
                name=data["name"], description=data["description"], behavior=data["behavior"],
                selected_tools=selected, unselected_tools=unselected,
            )
        except PipelineConfigurationError as exc:
            return Response({"detail": str(exc)}, status=status.HTTP_503_SERVICE_UNAVAILABLE)
        except ValueError as exc:
            return Response({"detail": str(exc)}, status=status.HTTP_502_BAD_GATEWAY)

        return Response(builder_check_response(result))


def _builder_test_events(*, draft: dict, user_input: str, account_id: str):
    try:
        for event in run_agent(None, user_input, {"account_id": account_id}, draft=draft, dry_run=True):
            yield json.dumps(event, ensure_ascii=False, default=str) + "\n"
    except Exception as exc:  # noqa: BLE001 - 스트림 중에는 500을 낼 수 없다
        logger.exception("빌더 테스트 실행 중 오류")
        yield json.dumps({"type": "error", "detail": f"테스트 실행에 실패했습니다: {exc.__class__.__name__}"}, ensure_ascii=False) + "\n"

```ts
import { clearSession, loadSessionToken } from '../utils/session';

export const API_BASE_URL = import.meta.env.VITE_API_BASE_URL ?? 'http://localhost:8000/api';

export class ApiError extends Error {
  readonly status: number;
  readonly fieldErrors: Record<string, string>;

  constructor(message: string, status: number, fieldErrors: Record<string, string> = {}) {
    super(message);
    this.name = 'ApiError';
    this.status = status;
    this.fieldErrors = fieldErrors;
  }
}

export function parseErrorBody(body: unknown, status: number): ApiError {
  if (body && typeof body === 'object') {
    const record = body as Record<string, unknown>;
    if (typeof record.detail === 'string') {
      return new ApiError(record.detail, status);
    }
    const fieldErrors: Record<string, string> = {};
    for (const [field, value] of Object.entries(record)) {
      if (Array.isArray(value) && typeof value[0] === 'string') {
        fieldErrors[field] = value[0];
      } else if (typeof value === 'string') {
        fieldErrors[field] = value;
      }
    }
    const first = Object.values(fieldErrors)[0];
    if (first) return new ApiError(first, status, fieldErrors);
  }
  return new ApiError('요청을 처리하지 못했습니다.', status);
}

interface RequestOptions {
  method?: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE';
  body?: unknown;
  token?: string | null;
}

export async function apiRequest<T>(path: string, options: RequestOptions = {}): Promise<T> {
  const { method = 'GET', body, token } = options;
  const headers: Record<string, string> = {};
  if (body !== undefined) headers['Content-Type'] = 'application/json';
  if (token) headers.Authorization = `Bearer ${token}`;

  let response: Response;
  try {
    response = await fetch(`${API_BASE_URL}${path}`, { method, headers, body: body === undefined ? undefined : JSON.stringify(body) });
  } catch {
    throw new ApiError('서버에 연결할 수 없습니다. 백엔드가 실행 중인지 확인해 주세요.', 0);
  }

  if (response.status === 401 && token && token === loadSessionToken()) {
    clearSession();
  }
  if (response.status === 204) return undefined as T;

  const text = await response.text();
  const payload = text ? JSON.parse(text) : null;
  if (!response.ok) throw parseErrorBody(payload, response.status);
  return payload as T;
}

/** NDJSON 스트림을 한 줄씩 읽어 콜백으로 넘긴다. v2에서 신규 추가. */
export async function streamNdjson<TEvent>(
  path: string, token: string | null | undefined, body: unknown,
  onEvent: (event: TEvent) => void, signal?: AbortSignal,
): Promise<void> {
  const headers: Record<string, string> = { 'Content-Type': 'application/json' };
  if (token) headers.Authorization = `Bearer ${token}`;

  const response = await fetch(`${API_BASE_URL}${path}`, { method: 'POST', headers, body: JSON.stringify(body), signal });

  if (!response.ok || !response.body) {
    const failure = await response.json().catch(() => null);
    throw parseErrorBody(failure, response.status);
  }

  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop() ?? '';
    for (const line of lines) {
      if (!line.trim()) continue;
      onEvent(JSON.parse(line) as TEvent);
    }
  }
}

export async function apiUpload<T>(
  path: string, file: File,
  options: { method?: 'POST' | 'PUT'; token?: string | null; field?: string } = {},
): Promise<T> {
  const { method = 'PUT', token, field = 'file' } = options;
  const form = new FormData();
  form.append(field, file);
  const headers: Record<string, string> = {};
  if (token) headers.Authorization = `Bearer ${token}`;

  let response: Response;
  try {
    response = await fetch(`${API_BASE_URL}${path}`, { method, headers, body: form });
  } catch {
    throw new ApiError('서버에 연결할 수 없습니다. 백엔드가 실행 중인지 확인해 주세요.', 0);
  }
  if (response.status === 401 && token && token === loadSessionToken()) {
    clearSession();
  }
  if (response.status === 204) return undefined as T;

  const text = await response.text();
  const payload = text ? JSON.parse(text) : null;
  if (!response.ok) throw parseErrorBody(payload, response.status);
  return payload as T;
}

    }
  }, [open]);

  async function run() {
    if (!token || !userInput.trim() || running) return;
    setRunning(true); setSteps([]); setResultText(null); setResultComplete(false);
    setResultGrounded(null); setError(null); setStatusLine('시작하는 중…');
    let stepId = 0;
    try {
      await runBuilderTest(token, {
        instruction, tool_refs: toolRefs, model, reasoning_effort: reasoningEffort,
        max_iterations: maxIterations, user_input: userInput.trim(),

            break;
          case 'tool_call_started':
            stepId += 1;
            setSteps((prev) => [...prev, { key: String(stepId), toolRef: event.tool_ref, toolName: event.tool_name, status: 'running' }]);

            정합니다 — 모델이 안 부른 도구는 여기서 확인되지 않습니다. 승인이 필요한 도구(Jira
            등록·수정 등)는 실제로 부르지 않고 어떤 값으로 부르려 했는지만 보여줍니다.</p>
          <div className={styles.inputRow}>

              onChange={(event) => setUserInput(event.target.value)} />
            <Button onClick={run} disabled={running || !userInput.trim()}>{running ? '실행 중…' : '실행'}</Button>
          </div>
          {error && <p className={pageStyles.error}>{error}</p>}
          {(statusLine || steps.length > 0) && (
            <div className={styles.trace}>
              {statusLine && <p className={styles.statusLine}>{running && <Icon name="loader" size={14} spin />}{statusLine}</p>}
              {steps.length === 0 && !running && <p className={pageStyles.help}>도구를 하나도 부르지 않고 바로 답했습니다.</p>}

                return (

                      {step.arguments && Object.keys(step.arguments).length > 0 && <pre className={styles.args}>{JSON.stringify(step.arguments, null, 2)}</pre>}
                    </div>

import { useEffect, useState } from 'react';
import { Badge, Button } from '../../components';
import type { BadgeTone } from '../../components';
import { checkBuilderInput } from '../../api/agents';
import type { BuilderCheckResult } from '../../api/agents';
import { ApiError } from '../../api/client';
import pageStyles from './AgentEditPage.module.css';
import styles from './TestRunModal.module.css';

export interface InstructionCheckPanelProps {
  token: string | null;
  name: string;
  toolRefs: string[];
  description: string;
  instruction: string;
  onAdvance: (description: string, instruction: string) => void;
}

const OVERALL_LABEL: Record<BuilderCheckResult['overall'], { tone: BadgeTone; label: string }> = {
  pass: { tone: 'success', label: '통과' },
  warn: { tone: 'warning', label: '확인해 볼 점이 있습니다' },
  reject: { tone: 'danger', label: '반려 — 내용을 다시 써야 합니다' },
};

export function InstructionCheckPanel({ token, name, toolRefs, description, instruction, onAdvance }: InstructionCheckPanelProps) {
  const [draftDescription, setDraftDescription] = useState(description);
  const [draftInstruction, setDraftInstruction] = useState(instruction);
  const [checking, setChecking] = useState(false);
  const [result, setResult] = useState<BuilderCheckResult | null>(null);
  const [error, setError] = useState<string | null>(null);

  async function run(desc: string, instr: string) {
    if (!token || checking) return;
    setChecking(true); setError(null);
    try {
      const response = await checkBuilderInput(token, { name, description: desc, behavior: instr, tool_refs: toolRefs });
      setResult(response);
      if (response.overall !== 'reject') {
        // reject일 때는 빈 문자열로 덮어쓰지 않는다 — 사용자가 이미 쓴 초안을 지우면 안 된다.
        setDraftInstruction(response.refined_instruction);
      }
    } catch (exc) {
      setError(exc instanceof ApiError ? exc.message : '검증에 실패했습니다.');
    } finally {
      setChecking(false);
    }
  }

  useEffect(() => { void run(description, instruction); }, []); // eslint-disable-line

  return (
    <div>
      <p className={pageStyles.help}>이름·설명·지시문·도구 선택이 서로 맞는지 검토합니다. 경고(확인해 볼 점)는 다음 단계로 넘어가는 걸 막지 않지만, 반려는 막습니다 — 내용을 다시 쓰고 재검증해야 합니다.</p>
      {!name.trim() && <p className={pageStyles.help}>이름을 먼저 적어 주세요.</p>}
      {error && <p className={pageStyles.error}>{error}</p>}
      {checking && !result && <p className={pageStyles.help}>검증하는 중…</p>}
      {result && (
        <p className={styles.statusLine}>
          {/* result.overall이 서버 버전과 안 맞아 매핑에 없는 값이 와도 화면이 안 죽게 방어 처리. */}
          <Badge tone={(OVERALL_LABEL[result.overall] ?? { tone: 'neutral' as BadgeTone }).tone}>
            {OVERALL_LABEL[result.overall]?.label ?? result.overall}
          </Badge>
        </p>
      )}
      {result?.overall === 'reject' && result.reject_reason && <p className={pageStyles.error}>{result.reject_reason}</p>}
      <label className={pageStyles.field}>
        <span className={pageStyles.fieldLabel}>설명</span>
        <textarea className={pageStyles.textarea} style={{ minHeight: 60 }} rows={2}
          value={draftDescription} onChange={(event) => setDraftDescription(event.target.value)} />
      </label>
      {result && <span className={pageStyles.help}>검증 의견: {result.description_check?.note || '동사·대상·산출물이 잘 드러나 명확합니다.'}</span>}
      <label className={pageStyles.field}>
        <span className={pageStyles.fieldLabel}>지시문 (검증 결과가 다듬어서 자동으로 채웁니다)</span>
        <textarea className={pageStyles.textarea} rows={7} value={draftInstruction}
          onChange={(event) => setDraftInstruction(event.target.value)} />
      </label>
      {result && (
        <div className={styles.step}>
          <div className={styles.stepBody}>
            <span className={styles.stepName}>지시문 내용</span>
            <span className={pageStyles.help}>{result.instruction_check?.note || '트리거 조건·절차·도구 사용 기준·판단 기준이 잘 드러나 있습니다.'}</span>
          </div>
        </div>
      )}
      {result && (
        <div className={styles.step}>
          <div className={styles.stepBody}>
            <span className={styles.stepName}>도구 선택</span>
            {(result.tool_match_check?.missing_tools?.length ?? 0) === 0 && (result.tool_match_check?.unused_tools?.length ?? 0) === 0
              ? <span className={pageStyles.help}>지시문과 도구 선택이 잘 맞습니다.</span>
              : (<>
                  {(result.tool_match_check?.missing_tools?.length ?? 0) > 0 && <span className={pageStyles.help}>지시문에 필요해 보이는데 안 고른 도구: {result.tool_match_check.missing_tools.join(', ')}</span>}
                  {(result.tool_match_check?.unused_tools?.length ?? 0) > 0 && <span className={pageStyles.help}>골랐는데 지시문에서 안 쓰일 것 같은 도구: {result.tool_match_check.unused_tools.join(', ')}</span>}
                </>)}
          </div>
        </div>
      )}
      <div className={styles.stepActions}>
        <Button variant="outline" onClick={() => run(draftDescription, draftInstruction)} disabled={checking || !name.trim()}>
          {checking ? '검증하는 중…' : '수정한 내용으로 다시 검증하기'}
        </Button>
        <Button onClick={() => onAdvance(draftDescription, draftInstruction)} disabled={checking || !result || result.overall === 'reject'}>
          다음 단계: 도구 확인
        </Button>
      </div>
    </div>
  );
}
```

> `result.instruction_check?.note`, `result.tool_match_check?.missing_tools?.length ?? 0` 같은 옵셔널 체이닝은 처음부터 있던 게 아니다 — 프런트가 v3 필드(`instruction_check` 등)를 기대하는데 백엔드가 재시작 전이라 옛 응답 모양을 주는 경우, 이 방어 코드가 없으면 렌더링 중 예외가 나서 **앱 전체가 흰 화면이 된다**(이 저장소엔 ErrorBoundary가 어디에도 없다 — §7 참고). 메인에 처음 만들 때부터 이 옵셔널 체이닝을 그대로 넣을 것.

### 6.13 `frontend/src/pages/AgentEditPage/ToolCheckPanel.tsx` (전체, v3 신규)

```tsx
import { useState } from 'react';
import { Badge, Button, Input } from '../../components';
import type { BadgeTone } from '../../components';
import { checkBuilderTools } from '../../api/agents';
import type { ToolChoice, ToolCheckResult } from '../../api/agents';
import { ApiError } from '../../api/client';
import pageStyles from './AgentEditPage.module.css';
import styles from './TestRunModal.module.css';

export interface ToolCheckPanelProps {
  token: string | null;
  allTools: ToolChoice[];
  toolRefs: string[];
}

type FieldKind = 'string' | 'number' | 'json';

function fieldKind(type: string | undefined): FieldKind {
  if (type === 'string') return 'string';
  if (type === 'integer' || type === 'number') return 'number';
  return 'json';
}

const STATUS_LABEL: Record<ToolCheckResult['status'], { tone: BadgeTone; label: string }> = {
  OK: { tone: 'success', label: '성공' },
  FAILED: { tone: 'danger', label: '실패' },
  SIMULATED: { tone: 'warning', label: '시뮬레이션 (실제로 부르지 않음)' },
  SKIPPED: { tone: 'neutral', label: '건너뜀' },
};

export function ToolCheckPanel({ token, allTools, toolRefs }: ToolCheckPanelProps) {
  const [rawArgs, setRawArgs] = useState<Record<string, string>>({});
  const [checking, setChecking] = useState(false);
  const [results, setResults] = useState<ToolCheckResult[] | null>(null);
  const [error, setError] = useState<string | null>(null);

  const toolByRef = new Map(allTools.map((tool) => [tool.tool_ref, tool]));

  async function run() {
    if (!token || toolRefs.length === 0 || checking) return;
    setChecking(true); setResults(null); setError(null);

    const argumentsByRef: Record<string, Record<string, unknown>> = {};
    for (const ref of toolRefs) {
      const properties = toolByRef.get(ref)?.input_schema?.properties ?? {};
      const built: Record<string, unknown> = {};
      for (const prop of Object.keys(properties)) {
        const raw = rawArgs[`${ref}::${prop}`];
        if (raw === undefined || raw === '') continue;
        const kind = fieldKind(properties[prop].type);
        if (kind === 'number') {
          const parsed = Number(raw);
          if (!Number.isNaN(parsed)) built[prop] = parsed;
        } else if (kind === 'json') {
          try { built[prop] = JSON.parse(raw); } catch { /* 잘못된 JSON은 그냥 뺀다 */ }
        } else {
          built[prop] = raw;
        }
      }
      argumentsByRef[ref] = built;
    }

    try {
      const response = await checkBuilderTools(token, { tool_refs: toolRefs, arguments: argumentsByRef });
      setResults(response.results);
    } catch (exc) {
      setError(exc instanceof ApiError ? exc.message : '도구 확인에 실패했습니다.');
    } finally {
      setChecking(false);
    }
  }

  return (
    <div>
      <p className={pageStyles.help}>선택한 도구 전부를 모델 판단 없이 순서대로 직접 불러 봅니다. 모델이 안 불러서 확인이 안 되는 상황을 없애려는 것입니다. 승인이 필요한 도구는 여기서도 실제로 실행하지 않고 시뮬레이션만 합니다.</p>
      {toolRefs.length === 0 && <p className={pageStyles.help}>먼저 도구를 선택해 주세요.</p>}

      {toolRefs.map((ref) => {
        const tool = toolByRef.get(ref);
        const properties = tool?.input_schema?.properties ?? {};
        const propNames = Object.keys(properties);
        const required = new Set(tool?.input_schema?.required ?? []);
        return (
          <div key={ref} className={styles.step}>
            <div className={styles.stepBody}>
              <span className={styles.stepName}>{tool?.name ?? ref}</span>
              {propNames.length === 0 && <span className={pageStyles.help}>입력 값이 필요 없습니다.</span>}
              {propNames.map((prop) => {
                const key = `${ref}::${prop}`;
                const kind = fieldKind(properties[prop].type);
                return (
                  <Input key={key} label={`${prop}${required.has(prop) ? ' *' : ''}`} id={`tool-check-${key}`} name={key}
                    placeholder={kind === 'json' ? '{ } 또는 [ ] 형식의 JSON' : properties[prop].description || ''}
                    value={rawArgs[key] ?? ''}
                    onChange={(event) => setRawArgs((prev) => ({ ...prev, [key]: event.target.value }))} />
                );
              })}
            </div>
          </div>
        );
      })}

      <Button onClick={run} disabled={checking || toolRefs.length === 0}>{checking ? '확인하는 중…' : '전체 도구 확인'}</Button>
      {error && <p className={pageStyles.error}>{error}</p>}

      {results && (
        <div className={styles.trace}>
          {results.map((result, index) => {
            const chip = STATUS_LABEL[result.status];
            return (
              <div key={`${result.tool_ref}-${index}`} className={styles.step}>
                <span className={styles.stepOrder}>{index + 1}</span>
                <div className={styles.stepBody}>
                  <span className={styles.stepName}>{result.tool_name}<Badge tone={chip.tone}>{chip.label}</Badge></span>
                  {result.detail && <span className={pageStyles.help}>{result.detail}</span>}
                  {result.status === 'FAILED' && result.error_code && <span className={pageStyles.help}>오류: {result.error_code}</span>}
                  {result.arguments && Object.keys(result.arguments).length > 0 && <pre className={styles.args}>{JSON.stringify(result.arguments, null, 2)}</pre>}
                  {result.status === 'OK' && result.output !== undefined && <pre className={styles.args}>{JSON.stringify(result.output, null, 2)}</pre>}
                </div>
              </div>
            );
          })}
        </div>
      )}
    </div>
  );
}
```

## 8. 실제로 겪은 문제와 검증 — 메인에서 재현할 때 미리 알아둘 것

- **`NotNullViolation`(v2)**: `DB/migrations/2026-08-11_chat_agentless.sql`이 파일로는 있어도 실제 DB에 적용 안 되어 있으면, `agent_id=None`으로 실행 기록을 남기는 모든 경로(에이전트 없는 채팅, 빌더 테스트 실행)가 이 에러로 죽는다. **파일 존재를 마이그레이션 완료로 착각하지 말 것.**
- **흰 화면 크래시(v3 이후)**: 이 저장소 프런트에는 **ErrorBoundary가 어디에도 없다.** `InstructionCheckPanel.tsx`처럼 백엔드 응답 필드(`instruction_check`, `reject_reason` 등)를 옵셔널 체이닝 없이 읽으면, 응답 모양이 프런트 기대와 한 프레임이라도 어긋나는 순간(예: 백엔드 배포가 프런트보다 늦게 반영된 경우) 렌더링 예외가 나서 **모달이 아니라 페이지 전체가 하얗게 빈다.** §6.12의 옵셔널 체이닝을 생략하지 말 것. (근본 해결책인 ErrorBoundary 추가는 이번 범위에 없었다 — 메인에서 새로 만들 때 함께 넣는 걸 권장한다.)
- **모델이 도구를 안 부르는 문제(v3의 동기)**: 채팅식 테스트 실행은 모델이 도구 호출 여부를 스스로 판단하므로, 데이터가 없거나 모델이 그냥 안 부르면 그 도구는 영영 확인이 안 된다. 실사용("업무 지연 점검" 테스트)에서 문서 검색만 불리고 나머지 세 도구가 한 번도 안 불린 사례가 실제로 있었다 — 그래서 `check_tools()`(§3.1, §6.1)가 별도로 필요했다.
- **샌드박스 제약(이 문서를 쓴 환경 한정)**: 이 명세를 정리한 Cowork 세션은 Django·psycopg·openai 등 프로젝트 의존성이 설치되어 있지 않고 저장소 루트에 `requirements.txt`도 없어(`runpod_worker/requirements.txt`만 있음) `python manage.py test`를 실제로 돌리지 못했다. 이 문서의 코드는 **원본 파일을 그대로 옮겨 적은 것**이지 새로 검증한 것이 아니다 — 메인에 반영한 뒤 반드시 `python manage.py test tests.test_harness`와 `npx tsc -b --noEmit`을 실제 환경에서 돌려 확인할 것.
- **`Tool` dataclass 필드 추가 시 테스트도 같이 고칠 것**: `category`(v1), 이후 `write_todos`가 모든 도구 목록에 무조건 섞여 들어가는 것(v4) 둘 다 `tests/test_harness.py`의 기존 기대값을 깨뜨린다 — §4.3 참고.
