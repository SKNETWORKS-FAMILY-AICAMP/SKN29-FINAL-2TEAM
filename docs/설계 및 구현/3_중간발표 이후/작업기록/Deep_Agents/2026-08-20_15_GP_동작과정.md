# GP(general-purpose) 동작 과정

Root 에이전트가 general-purpose(이하 GP)를 부르기로 판단하는 순간부터, GP가
일하고 결과를 Root에게 돌려주기까지 실제로 무슨 일이 일어나는지 순서대로
설명한다.

## 1. Root가 보는 것 — `task` 도구의 설명

Root의 도구 목록에는 `task`라는 도구가 하나 있다. 이게 위임 버튼이다.
Root는 이 도구를 부를지 말지 판단할 때 이 도구의 설명(description)을 읽는다.
실제 문구:

```
여러 단계의 조사·처리·종합이 필요하거나, 독립적인 컨텍스트에서 별도로
수행하는 것이 적절한 작업을 서브 에이전트에게 위임한다. 서브 에이전트는
지금까지의 대화를 보지 못하고, description 하나로 전달한 내용만 안다.

사용 가능한 에이전트와 각자 쓸 수 있는 도구:
- general-purpose: 조사·검색이나 여러 단계에 걸친 복합 작업을 맡기는 범용
  보조 에이전트다. 전용 서브 에이전트가 없거나 요청이 여러 영역에 걸칠 때
  사용한다. 조회·검색 도구만 쓸 수 있고, 외부를 바꾸거나 데이터를 남기는
  도구는 없다 — 그런 작업이 필요하면 Root가 결과를 넘겨받아 직접 처리하고
  사람 승인을 받는다.

## 언제 위임할지
- 도구 한두 번으로 바로 끝나는 단순 조회·등록은 위임하지 않고 직접 그
  도구를 호출한다.
- 여러 출처나 도구를 사용해 조사·처리·종합해야 하거나, 한 번의 시도로
  결과를 얻기 어려운 작업은 general-purpose에게 맡긴다.
- 지금 요청과 설명이 맞는 전용 서브 에이전트가 있으면 general-purpose보다
  그 서브 에이전트를 우선한다.

## 위임할 때 description에 쓸 내용
필요한 경우 아래 내용을 포함해 하나의 지시문으로 작성한다.
1. 목표: 무엇을 만들거나 찾거나 처리해야 하는지
2. 배경: 이 요청이 왜 필요한지, 지금까지 확인된 사실
3. 허용 범위: 무엇을 해도 되고 무엇은 하면 안 되는지
4. 기대 출력: 결과를 어떤 형식과 수준으로 받고 싶은지
5. 출처 요구: 근거나 출처를 같이 받아야 하는지

## 그 외
- 서로 독립적으로 수행할 수 있는 작업은 가능한 경우 여러 건을 동시에
  호출한다.
- 서브 에이전트의 응답은 사용자에게 그대로 보이지 않는다. 필요한 내용을
  직접 정리해 전달한다.
- 이미 처리한 것과 같은 목적으로 다시 위임하거나 같은 도구를 반복
  호출하지 않는다.
- 외부를 바꾸거나 데이터를 남기는 작업은 general-purpose에 위임하지
  않는다. 그 결과가 필요하면 Root가 직접 그 도구를 불러 사용자 승인을
  받는다.
```

`- general-purpose: ...` 줄은 GP 자신의 description을 그대로 가져와 자동으로
끼워 넣은 것이다(child 서브 에이전트가 있으면 그 목록도 같이 나열된다).
Root는 이 문구 하나만 보고 "지금 이 요청이 위임할 만한가, 위임한다면 뭐라고
써서 보낼까"를 스스로 판단한다 — 위임 여부를 강제로 결정하는 코드는 없다.

## 2. Root가 실제로 GP를 부르는 방법

Root가 위임하기로 하면 `task` 도구를 두 개의 값과 함께 호출한다.

- `subagent_type`: `"general-purpose"` (GP를 선택했다는 표시)
- `description`: 위 "description에 쓸 내용" 기준을 참고해 Root가 직접 쓴
  지시문 — 목표, 배경, 허용 범위, 기대 출력 형식 등을 한 번에 담은 글 하나

이 호출 하나가 GP의 실행을 시작시킨다.

## 3. GP가 실제로 받는 것

GP는 완전히 새로운 대화로 시작한다. Root와 사용자가 지금까지 나눈 대화는
전혀 보지 못하고, 딱 하나 — Root가 써서 보낸 `description` 텍스트 하나만
첫 메시지로 받는다. 그래서 Root가 이 description에 필요한 맥락을 다 담아야
한다 — GP는 "그거 뭔지 알지?"처럼 되묻지 못한다(대화 자체가 없으므로).

단, 파일(가상 파일시스템) 같은 공유 상태는 이어받는다 — Root가 지금까지
만든 파일이 있으면 GP도 그걸 읽을 수 있다. 이어받지 않는 건 대화 메시지
뿐이다.

## 4. GP의 system_prompt — 실제로 어떤 지시를 받는가

GP도 이 팀의 공통 규칙을 그대로 따라야 하므로, 아래 두 덩어리를 이어붙인
글을 system_prompt로 받는다.

**첫 번째 — 이 앱 공통 규칙**(Root·Child·GP 모두 동일하게 받음):
"사용자의 요청을 먼저 이해하고 필요한 경우에만 도구를 쓴다", "확인한 사실만
말하고 추측하지 않는다", "표·제목·코드블록을 쓰지 않는다", "외부를 바꾸는
도구는 승인 없이 실행되지 않는다" 같은 이 팀의 실행 원칙·근거 표시·답변
형식 규칙 전체.

**두 번째 — GP 전용 기본 지시**(deepagents가 원래 갖고 있는 문구, 그대로
사용):
```
In order to complete the objective that the user asks of you, you have
access to a number of standard tools.

The calling agent only sees your final assistant message, not your
intermediate work, tool results, or status tracking. Ensure your final
response contains the complete answer.
```
번역하면: "너는 여러 표준 도구를 쓸 수 있다. 너를 부른 쪽은 네 최종 답변만
보고 중간 작업·도구 결과·진행 상황은 못 본다. 그러니 최종 답변에 완전한
내용을 담아라." — 이 한 문장이 GP의 행동을 사실상 결정한다: 중간 과정이
아니라 **최종 답변 한 덩어리**에 결과를 다 눌러 담아야 한다는 뜻이다.

## 5. GP가 쓸 수 있는 도구

GP는 Root가 가진 도구 전체를 받지 않는다. 그중에서 **조회·검색용(부작용
없는) 도구만** 받는다 — 문서 검색, 목록 조회 같은 것들. 업무 등록·Jira
이슈 생성·삭제처럼 외부를 바꾸거나 데이터를 남기는 도구는 GP에게 아예
주어지지 않는다. 그런 도구는 GP의 도구 목록에 없으니 부르고 싶어도 부를
방법이 없다.

호출 횟수 상한도 따로 있다 — 모델 호출 최대 50번, 도구 호출 최대 100번.
이 상한을 넘기면 GP는 그 시점에서 실행을 강제로 멈춘다.

## 6. GP 내부에서 실제로 일어나는 일

GP는 이때부터 하나의 독립된 에이전트로 돈다 — Root와 똑같은 구조로, 받은
description을 목표 삼아 스스로 여러 번 모델을 호출하고 필요하면 그 사이사이
도구(문서 검색 등)를 호출하며 조사·정리를 진행한다. 몇 번 도구를 부르고
몇 번 다시 생각하는지는 그때그때 다르다 — 정해진 단계 수는 없고, 위 4번의
"최종 답변에 완전한 내용을 담아라"는 지시에 따라 스스로 판단해서 충분하다
싶을 때 마지막 답변을 작성하고 끝낸다.

## 7. GP가 결과를 Root에게 돌려주는 방법

GP의 실행이 끝나면, GP가 그동안 만든 여러 메시지(생각 과정, 도구 호출,
중간 답변 등) 중에서 **맨 마지막에 나온, 비어 있지 않은 최종 답변 하나만**
골라낸다. 그 텍스트 하나가 Root의 대화 속에 `task` 도구의 결과값으로
들어간다.

즉 Root는 GP가 무슨 도구를 몇 번 불렀는지, 중간에 뭘 시도했다가 접었는지
같은 과정은 전혀 못 본다 — 딱 GP의 마지막 한마디만 받는다. 그래서 GP
입장에서는 그 마지막 답변 안에 필요한 내용을 다 정리해서 담아야 하고
(4번 지시), Root 입장에서는 그 결과를 통째로 사용자에게 보여주지 않고
직접 정리해서 전달해야 한다(1번 "그 외" 항목).

## 8. 정리 — 전체 흐름 한 줄씩

1. Root가 `task` 도구 설명을 보고 지금 요청이 위임할 만한지 판단한다.
2. 위임하기로 하면 `subagent_type="general-purpose"`와 직접 쓴
   `description`으로 `task`를 호출한다.
3. GP는 그 description 하나만 가진 새 대화로 시작한다(이전 대화는 못 봄,
   파일 등 공유 상태는 이어받음).
4. GP는 "이 팀 공통 규칙 + 최종 답변에 완전한 내용을 담으라"는 지시를
   system_prompt로 받는다.
5. GP는 조회·검색 도구만 쓸 수 있다 — 쓰기·전송·삭제 도구는 없다.
6. GP는 스스로 여러 번 모델·도구를 호출하며 작업하다가 최종 답변을 쓰고
   끝낸다.
7. Root는 GP의 마지막 답변 한 덩어리만 돌려받고, 그걸 직접 정리해서
   사용자에게 전달한다.
