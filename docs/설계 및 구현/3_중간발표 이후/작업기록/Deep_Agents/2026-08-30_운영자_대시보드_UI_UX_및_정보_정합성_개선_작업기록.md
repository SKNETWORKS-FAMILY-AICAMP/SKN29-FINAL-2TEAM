## 2. 문제와 변경 이유

### 외부 연결 범위

- 변경 전: Drive·Jira 외에 커스텀 모델과 People DB까지 `플랫폼 연결` 한 수치로 합쳤다. 배포 화면에서는 연결 목록이 2개인데 현황은 5개여서 같은 말이 서로 다른 대상을 가리켰다.
- 변경 후: 운영 현황의 외부 연결 집계는 현재 연결 관리 화면에서 다루는 Drive·Jira로 제한하고, 모델과 People DB는 포함하지 않는다.
- 이유: 운영자가 수치를 눌러 이동했을 때 같은 대상 집합을 확인할 수 있어야 한다. 모델과 HR 데이터 소스는 별도 운영 자원이며 외부 연결 수에 섞지 않는다.

### 계정 상태와 Person 매핑

- 변경 전: ACTIVE 미매핑 계정이 `정상`과 `확인 필요`에 동시에 들어갈 수 있어 합계와 필터가 중첩됐다.
- 변경 후: 계정 상태는 활성·잠김·탈퇴로, 직원 매핑은 연결·미연결·중복 연결로 독립 표시·필터링한다.
- 이유: 로그인 계정과 향후 HR 시스템에서 들어오는 Person은 다른 개념이다. 미매핑의 허용 여부는 온보딩 정책 문제이며 계정 자체의 활성 상태와 합쳐 판정하면 안 된다.

### 연결 상태와 진단 문구

- 변경 전: `connected_at`을 `최근 확인`으로, 자격정보가 저장된 CONNECTED를 `정상`으로 표시했다.
- 변경 후: `연결 시각`, `연결 정보가 저장돼 있습니다`로 사실 수준을 낮추고 REVOKED를 `해제됨`으로 별도 표시한다.
- 이유: 현재 Drive·Jira에는 지속적인 health probe와 `last_checked_at`이 없다. 실제 통신 성공을 확인하지 않았는데 정상이라고 단정하지 않는다.

### 감사와 정책 편집

- 최근 운영 활동에서 로그인·인증 이벤트를 제외해 실제 설정 변경을 우선 노출한다.
- 감사 로그에 전체·운영 변경·로그인·인증 구분과 누락된 한글 작업명을 추가했다.
- 정책 값이 바뀌지 않았을 때 저장을, 값과 사유가 모두 원래 상태일 때 취소를 비활성화했다.
- 이유: 반복 로그인과 원시 상수명은 운영 변경을 찾는 비용을 키우고, 변화 없는 활성 버튼은 불필요한 조작 가능성을 만든다.

## 3. 실행 실패 발견 경로

- 배포 사용 현황에는 최근 30일 실행 실패와 도구 실패가 있었지만 운영 현황의 `오늘 확인할 일`은 0이었다.
- 운영 현황 기존 집계에 최근 30일의 실행·실패·토큰·완료된 도구 호출을 함께 집계한다. 별도 API와 새 화면은 만들지 않았다.
- 실행 또는 도구 실패가 있으면 `운영 점검 항목`에 한 항목으로 표시하고 `/ops/usage`로 연결한다.
- `오늘 확인할 일`은 현재 상태와 30일 기록을 함께 담을 수 없으므로 `운영 점검 항목`으로 바꿨다.
- 로컬 실측: AI 실행 144건, 실행 실패 3건, 측정 토큰 6,416,581, 토큰 미측정 실행 3건, 완료된 도구 호출 233회, 도구 실패 9회.

## 4. 메인 대시보드 정보 순서

- 변경 전: 요약 카드 → 계정·연결 상태 → 조치 목록 순서라 좁은 화면에서 장애를 보려면 여러 카드를 지나야 했다.
- 변경 후: 페이지 제목 → 운영 점검 항목 → 핵심 요약 → 상태 분포 → 최근 30일 AI 사용·최근 운영 활동 순서다.
- 이유: 채팅 UI 보정과 같은 원칙을 적용했다. 사용자가 먼저 결과·예외를 보고, 그다음 근거와 세부 상태를 읽게 한다. 반복 설명은 줄이고 모든 경고에는 다음 행동 링크를 둔다.

## 5. 그래프와 사용 지표 판단

### 그래프

- 원형 차트는 추가하지 않았다. 작은 비율 비교가 어렵고 모바일·사이드 패널에서 면적을 크게 차지한다.
- 계정·연결 상태처럼 전체 대비 분포가 중요한 정보에는 기존 누적 막대·수평 막대를 유지한다.
- 실행·토큰·도구 호출은 현재 한 기간의 절대값만 있으므로 숫자 카드가 더 빠르다. 일별 추세 데이터와 전 기간 비교가 생길 때 선 그래프를 검토한다.

### 지표 정의

- `AI 실행`: 최근 30일 `agent_run` 수. 대화와 빌더 에이전트 실행을 포함하지만 실제 모델 API 요청 횟수와 같다고 단정하지 않는다.
- `측정된 토큰`: `token_in + token_out`. 제공자가 usage를 주지 않은 실행 수를 함께 표시해 누락을 숨기지 않는다.
- `완료된 도구 호출`: 상태가 OK 또는 FAILED인 `tool_call` 수. 승인 대기 PENDING과 사용자 거부 REJECTED는 실행 완료 수에서 제외한다.
- `대화 수`: `chat_session`은 새 대화방 수일 뿐 재사용·실제 요청량을 반영하지 않아 메인 지표에서 제외했다.
- `모델 호출 수`: 한 AI 실행 안에서 모델이 여러 번 호출될 수 있으나 현재 개별 호출 이력이 없어 표시하지 않았다.
- `도구 생성량`: 커스텀 도구 등록 재고와 실제 호출량이 다른 개념이다. 메인 사용량에는 호출만 표시하고 등록 현황은 커스텀 도구 화면에 둔다.
- `오늘 활성`: 계정 상태의 `활성`과 당일 사용을 혼동하기 쉽고 자정·시간대에 따라 크게 흔들리는 비조치 지표라 제외했다. 채택할 때는 `최근 30일 실행 계정`처럼 기간과 실제 행동을 명시하고 제품 사용 분석 지표로 분리한다.

## 6. 문구 정리

- `현재 상태와 최근 실행 기록에서 확인할 항목입니다`처럼 제목을 반복하는 안내는 제거했다.
- `사용 중인 팀`은 실제로 사용 여부가 아니라 전체 팀 수를 세므로 `등록된 팀`으로 바꿨다.
- `플랫폼을 쓰는 단위`는 `계정·설정 관리 단위`로 구체화했다.
- `최근 30일 AI 사용`은 `최근 30일 사용 현황`으로 줄이고, 대화방과 실행의 차이를 화면에서 길게 변명하던 문장은 문서의 지표 정의로 옮겼다.
- CONNECTED 진단은 실제 통신 정상을 뜻하지 않는 `연결 정보 저장됨`으로 짧게 유지했다.
