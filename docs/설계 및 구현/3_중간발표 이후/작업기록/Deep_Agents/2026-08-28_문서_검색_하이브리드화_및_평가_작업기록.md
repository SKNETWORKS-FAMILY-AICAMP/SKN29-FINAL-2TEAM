### 수행 내용과 변경 전후

- 기존 `document_search`는 임베딩 코사인 유사도만 사용하고 모델이 `top_k`를
  1~20 사이로 바꿀 수 있었다. 도구 입력을 `query` 하나로 단순화하고 결과 수를
  서버에서 20개로 고정했다.
- `chunk.raw_text` 컬럼을 새로 만들지 않았다. 키워드 검색은 제목 경로 등 청킹
  문맥이 붙은 기존 `chunk.search_text`를 사용하고, 모델에 돌려주는 실제 근거
  본문은 이미 파싱 결과로 보관 중인 `doc_block.content`를 사용한다.
- lexical 후보는 PostgreSQL `simple` 전문검색, `pg_trgm` 부분어절 유사도,
  정확 포함 보너스로 구성한다. 후보군 안에서 각 점수를 정규화하고 lexical
  0.5 + 코사인 0.5로 최종 순위를 계산한다. lexical 내부 초기 가중치는
  FTS 0.55 + trigram 0.25 + 정확 포함 0.20이다.
- 벡터·FTS·trigram에서 각각 60개 후보를 모아 합친 뒤 Top-20을 반환한다.
  팀·개인·공유·프로젝트 문서 범위, 현재 revision, active/deleted/access 필터와
  미색인 문서를 결과에 명시하는 기존 정책은 유지했다.
- `pg_trgm` 확장과 `search_text`의 FTS·trigram GIN 인덱스를 멱등 마이그레이션으로
  추가하고, 공식 마이그레이션 검사기가 확장과 비고유 인덱스도 확인하도록 했다.
  업무 추출이 쓰는 기존 순수 벡터 검색은 변경하지 않아 역할별 검색 경로를 분리했다.

### 검증 결과와 제한

- 로컬 PostgreSQL에 마이그레이션을 적용했고 공식 검사 52개 항목 모두 통과했다.
- 실제 PostgreSQL에서 새 하이브리드 쿼리를 실행해 FTS·pg_trgm 연산자와 psycopg
  파라미터 결합이 정상임을 확인했다. 현재 로컬 DB에는 색인 문서가 없어 결과
  품질 자체는 측정하지 못했고 빈 범위 실행으로 SQL 호환성을 검증했다.

  수집 전에 중단되므로 의존성이 갖춰진 `web` 컨테이너에서 검증했다.
- 0.5:0.5 및 lexical 내부 가중치는 합리적인 초기값이지 품질 실험으로 확정된

### 재평가와 운영 가중치

- 정답지 보정 후 모든 후보에 한 단계 회귀가 하나씩 남았다. 0.4/0.6은 Q07을

  지표를 함께 보면 0.5/0.5가 더 안정적이어서 운영 가중치를 같은 비중으로 바꿨다.
- 벡터 대비 선택 하이브리드는 Evidence Recall@20 0.933→1.0,
  Precision@5 0.343→0.386, Precision@8 0.250→0.304,
  Precision@20 0.129→0.154, MRR 0.756→0.851로 개선됐다.
- 유형별 Evidence Recall@20은 모두 1.0이었다. MRR은 정확 용어·숫자 조건 1.0,
  교차 문서 0.883, 유사 문서 혼동 0.735, 자연어 변형 0.715였다. 사람·역할은
  표본 2개뿐이라 0.667을 일반화하지 않고 추가 실문서 질의 우선 대상으로 둔다.
- Q04·Q07의 기존 회귀 판정은 잘못된 정답지에서 비롯됐고, 보정 후 남은 회귀는
  Q10 한 건이다. 실제 문서 정답 세트가 생기기 전 별도 reranker는 추가하지 않는다.

### 정답 보정 감사 이력

- Q04·Q07 보정은 하이브리드 점수를 높이기 위한 사후 라벨 변경이 아니다. 순위
  하락 원인을 조사하다 정답 목록에 없던 `과업지시서 3.3`을 발견했고, 원문에
  실패율 임계치 기반 자동 전환·복귀와 중복 결제 방지가 명시된 것을 사람이 직접
  확인한 뒤 검색 점수와 무관하게 relevant evidence로 판정했다.
- 보정 날짜, 대상 질의, 추가 근거, 발견 사유, 원문 검수 내용, 평가 영향까지
  Golden Set의 `label_corrections`에 구조화해 남겼다. 이후 라벨 변경도 같은
  형식으로 근거와 영향을 기록한다.

### 개발·holdout 분리 보장

- Q01~Q10 development와 Q11~Q14 holdout 구성을 Golden Set의 `splits` 계약으로
  옮겼다. 평가기는 두 집합이 겹치거나 어느 쪽에도 속하지 않은 질의가 있으면
  즉시 실패한다.
- 가중치 후보의 회귀 검사와 선택은 development만 사용한다. holdout은 선택 완료
  후 최종 검증에만 사용하며, 전체 보고서에도 `holdout_used_for_selection: false`를
  명시한다.
- 현재 0.5/0.5는 **합성 development 평가에서 가장 안정적인 값**이지 일반적인
  최적 가중치가 아니다. 유형별 수치도 표본이 작으므로 방향성 진단으로만 쓴다.
