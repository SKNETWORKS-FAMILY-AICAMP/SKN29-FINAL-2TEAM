### 수행 내용과 변경 전후

- 기존 `document_search`는 임베딩 코사인 유사도만 사용하고 모델이 `top_k`를
  1~20 사이로 바꿀 수 있었다. 도구 입력을 `query` 하나로 단순화하고 결과 수를
  서버에서 20개로 고정했다.
- `chunk.raw_text` 컬럼을 새로 만들지 않았다. 키워드 검색은 제목 경로 등 청킹
  문맥이 붙은 기존 `chunk.search_text`를 사용하고, 모델에 돌려주는 실제 근거
  본문은 이미 파싱 결과로 보관 중인 `doc_block.content`를 사용한다.
- lexical 후보는 PostgreSQL `simple` 전문검색, `pg_trgm` 부분어절 유사도,
  정확 포함 보너스로 구성한다. 후보군 안에서 각 점수를 정규화하고 lexical
  0.5 + 코사인 0.5로 최종 순위를 계산한다. lexical 내부 초기 가중치는
  FTS 0.55 + trigram 0.25 + 정확 포함 0.20이다.
- 벡터·FTS·trigram에서 각각 60개 후보를 모아 합친 뒤 Top-20을 반환한다.
  팀·개인·공유·프로젝트 문서 범위, 현재 revision, active/deleted/access 필터와
  미색인 문서를 결과에 명시하는 기존 정책은 유지했다.
- `pg_trgm` 확장과 `search_text`의 FTS·trigram GIN 인덱스를 멱등 마이그레이션으로
  추가하고, 공식 마이그레이션 검사기가 확장과 비고유 인덱스도 확인하도록 했다.
  업무 추출이 쓰는 기존 순수 벡터 검색은 변경하지 않아 역할별 검색 경로를 분리했다.

### 검증 결과와 제한

- 로컬 PostgreSQL에 마이그레이션을 적용했고 공식 검사 52개 항목 모두 통과했다.
- 실제 PostgreSQL에서 새 하이브리드 쿼리를 실행해 FTS·pg_trgm 연산자와 psycopg
  파라미터 결합이 정상임을 확인했다. 현재 로컬 DB에는 색인 문서가 없어 결과
  품질 자체는 측정하지 못했고 빈 범위 실행으로 SQL 호환성을 검증했다.
- `tests.test_document_search`, `tests.test_document_pipeline` 46개가 통과했고
  `git diff --check` 오류가 없다. 호스트 Miniconda는 `python-docx`가 없어 테스트
  수집 전에 중단되므로 의존성이 갖춰진 `web` 컨테이너에서 검증했다.
- 0.5:0.5 및 lexical 내부 가중치는 합리적인 초기값이지 품질 실험으로 확정된
  값은 아니다. 다음 작업은 대표 질의·정답 근거 세트를 만들고 벡터 단독 대비
  Recall@20, Precision@20, MRR 및 정확 용어 질의 성공률을 비교하는 것이다.

### 최신 main 통합 판단

- 작업 시작 HEAD `7178cf5`는 최신 `origin/main` `91eae62`보다 66커밋 뒤였고
  독자 커밋은 0개였다. 최신 main이 이미 기존 Reasoning UI 커밋을 포함하므로

  검색 평가를 먼저 끝낸 뒤 병합하는 것보다 최신 구조 위에서 평가하는 편이

  공식 검사 60개 항목이 모두 통과했다.

### 한국어 lexical 보정

- 초기 `simple` FTS + `websearch_to_tsquery`는 한국어 조사와 AND 결합 때문에
  예시 질의에서 95개 절 중 양성 0건이었다. 이 상태의 FTS 0.55는 실제 검색에
  기여하지 않는 명목상 가중치였다.
- 한글·영문·숫자만 허용한 토큰을 prefix OR tsquery로 만들고, 조사 제거형을
  원형과 함께 추가했다. `정산 금액을 계산하는 단계와 중간값 보존` 질의는
  FTS 양성 36건으로 회복됐고 정답인 요구사항 3장과 과업지시서 3.2가 FTS
  최상위에 올랐다. tsquery 연산 문자는 제거해 검색 문법 주입을 막았다.

### 비교 평가와 최종 선택

- 합격 기준은 Query Recall@20 0.90 이상, Precision@20·MRR 벡터 단독 이상,
  정확 용어 질의 성공률 1.0, 금지 문서 Top-3 잠식률 0으로 정했다.
- 벡터 단독은 Evidence Recall@20 0.929, Precision@20 0.121, MRR 0.720이었다.
- 0.5/0.5 하이브리드는 Recall 1.0, Precision 0.146, MRR 0.767로 통과했다.
- 같은 임베딩으로 벡터 비중 0.4/0.5/0.6/0.7을 Q01~Q10 개발 세트에서 비교했다.
  Recall 1.0 후보 중 개발 MRR이 가장 높은 벡터 0.4 + lexical 0.6을 선택했다.
- 선택값의 전체 Evidence Recall@20은 1.0, Precision@20은 0.139, MRR은 0.780,
  정확 용어 성공률은 1.0, 금지 문서 Top-3 잠식률은 0이다. Q11~Q14 홀드아웃도
  Evidence Recall@20 1.0, MRR 1.0으로 기준을 통과했다.
- 따라서 별도 `document_search_hybrid`를 추가하지 않고 기존 `document_search`를
  개선한다. 같은 목적의 두 도구를 동시에 노출하면 모델과 사용자의 선택만
  모호해지고, 기존 도구 교체가 벡터 기준선보다 수치상 우수하기 때문이다.
- 최신 카탈로그·API·프론트 Tool Picker·기본 채팅 도구 마이그레이션에서
  `document_search` 노출을 확인하고 회귀 테스트로 고정했다.
