# 13. 7단계 세부 05 — 미들웨어 조립

## 핵심 구분

최종 Graph의 미들웨어는 두 곳에서 조립된다.

```text
우리 MiddlewareFactory
→ 프로젝트 전용 미들웨어 생성

Deep Agents create_deep_agent()
→ Deep Agents 기본 미들웨어 생성
```

## 프로젝트에서 직접 조립하는 미들웨어

Root와 일반 Child에는 다음 순서로 만든다.

```text
1. ModelCallLimitMiddleware
2. ToolCallLimitMiddleware
3. TodoListMiddleware              조건부
4. McpToolCallTimeoutMiddleware
5. BuiltinWriteLockMiddleware      RuntimeContext가 있을 때
```

| 미들웨어 | 역할 | 핵심 설계 |
|---|---|---|
| `ModelCallLimitMiddleware` | 모델 호출 횟수 제한 | 에이전트의 `max_iterations`와 역할별 정책으로 상한을 정하며 초과하면 오류로 끝낸다. |
| `ToolCallLimitMiddleware` | 도구 호출 횟수 제한 | 모델이 도구를 반복 호출하는 것을 막으며 역할별 상한 초과 시 오류로 끝낸다. |
| `TodoListMiddleware` | 에이전트 내부 계획 관리 | `enable_todo=True`일 때만 추가한다. `write_todos`는 대화용 계획이며 팀 업무 DB의 `task_register`와 다르다. |
| `McpToolCallTimeoutMiddleware` | MCP 응답 대기 제한 | `mcp:` 도구에만 timeout을 적용한다. timeout은 외부 작업 취소가 아니라 결과 미확인이다. |
| `BuiltinWriteLockMiddleware` | 내장 쓰기 도구 충돌 방지 | 같은 팀·프로젝트의 내장 쓰기 도구를 DB 잠금으로 직렬화한다. 읽기와 MCP에는 적용하지 않는다. |

## 모델 호출 제한과 도구 호출 제한

```text
ModelCallLimitMiddleware
→ 모델을 몇 번 호출할 수 있는가

ToolCallLimitMiddleware
→ 도구를 총 몇 번 실행할 수 있는가
```

두 제한 모두 상한 초과 시 `exit_behavior="error"`로 실행을 종료한다.

## TODO 미들웨어

```text
write_todos
→ 현재 대화에서 사용하는 에이전트 실행 계획

task_register / task_update
→ 팀원이 확인하는 실제 업무 데이터
```

TODO 상태는 Checkpointer를 통해 같은 대화에서 이어질 수 있지만 팀 업무 DB에는
저장되지 않는다.

## MCP timeout 미들웨어

```text
MCP 실행
    ↓
설정된 시간까지 대기
    ↓
├─ 응답 도착
│  → 정상 결과 반환
│
└─ timeout
   → 응답 대기 중단
   → 결과 미확인 ToolMessage 반환
```

```text
timeout
≠ 외부 작업 취소
```

따라서 timeout 결과에는 외부 결과를 확인하기 전 자동 재시도하지 말라는 안내를
포함한다.

## 내장 쓰기 잠금 미들웨어

잠금 대상은 다음 내장 쓰기 도구다.

```text
task_register
task_update
jira_create_issues
```

잠금 범위는 다음과 같다.

```text
builtin-write:{team_id}:{project_id}
```

같은 팀·프로젝트의 쓰기는 직렬화하고 서로 다른 프로젝트의 쓰기는 병렬 실행을
허용한다. MCP는 오래 실행될 수 있어 DB 잠금으로 묶지 않고 HITL 카드에서 동시
실행 경고를 제공한다.

## GP 서브에이전트 미들웨어

GP에는 다음 두 개만 직접 조립한다.

```text
ModelCallLimitMiddleware
ToolCallLimitMiddleware
```

GP는 side-effect 도구와 MCP 도구를 받지 않으므로 TODO, MCP timeout과 내장 쓰기
잠금을 붙이지 않는다.

## Deep Agents 기본 미들웨어

다음 기본 미들웨어는 우리 `MiddlewareFactory`에서 직접 만들지 않는다.

```text
PatchToolCallsMiddleware
SummarizationMiddleware
SubAgentMiddleware
```

전달한 설정에 따라 다음 기능도 Deep Agents가 내부에서 구성한다.

```text
MemoryMiddleware
FilesystemMiddleware
HumanInTheLoopMiddleware
```

우리 코드가 기본 미들웨어를 다시 만들면 요약, 도구 호출 보정과 Child 상태 배선이
중복될 수 있으므로 Deep Agents 내부 생성에 맡긴다.

## 실제 조립 시점

프로젝트 미들웨어 객체는 `MiddlewareFactory.build()`에서 먼저 준비한다. Deep
Agents 기본 미들웨어는 Child 또는 Root Graph를 실제로 생성하는 시점에 조립된다.

```text
프로젝트 custom_middleware 준비
    ↓
Child 설정 준비
    ↓
create_child_graph()
    ↓
create_deep_agent()
    ↓
Child 기본 미들웨어 + custom_middleware 결합
    ↓
Compiled Child Graph
```

```text
프로젝트 custom_middleware 준비
    ↓
Root 설정 준비
    ↓
create_root_graph()
    ↓
create_deep_agent()
    ↓
Root 기본 미들웨어 + custom_middleware 결합
    ↓
Compiled Root Graph
```

## 전체 호출 흐름

```text
AgentRuntimeFactory.build()
    ↓
MiddlewareFactory.build()
    ↓
custom_middleware 생성
    ↓
create_child_graph() 또는 create_root_graph()
    ↓
Deep Agents create_deep_agent()
    ↓
기본 미들웨어 생성
    ↓
custom_middleware와 결합
    ↓
Compiled Graph
```

Deep Agents 기본 미들웨어 조립은 8단계가 아니라 7단계 안에서 완료된다.
