# 05. 4단계 — 가드레일 합류와 차단 판단

## 4단계에서 하는 일

1. 백그라운드 가드레일 검사가 끝날 때까지 기다린다.
2. 가드레일 검사 결과를 가져온다.
3. 사용자 입력이 차단됐는지 확인한다.
4. 차단됐으면 요청을 종료한다.
5. 차단되지 않았으면 5단계로 넘긴다.

결과는 두 가지다.

```text
차단
→ HTTP 400 반환
→ 사용자 메시지 저장 안 함
→ 런타임 실행 안 함

통과
→ 5단계로 이동
```

## 전체 동작 흐름

```text
3단계에서 생성한 guard_check
    ↓
검사 완료까지 대기
    ↓
가드레일 결과 가져오기
    ↓
입력이 차단됐는지 확인
    ↓
├─ 차단됨
│      ↓
│  차단 기록 저장
│      ↓
│  사용자에게 차단 사유 반환
│      ↓
│  HTTP 400으로 요청 종료
│
└─ 차단되지 않음
       ↓
   5단계로 이동
```

## 통과로 처리되는 경우

다음 경우에는 채팅 요청을 막지 않는다.

```text
가드레일 공급자가 등록되지 않음
가드레일 상태가 CONNECTED가 아님
가드레일 공급자 호출 실패
가드레일 검사 결과가 허용
```

외부 가드레일 호출이 실패해도 채팅을 계속 진행하는 `fail-open` 방식이다.

## 차단됐을 때 처리

```text
가드레일 차단 이벤트 기록
+ 사용자에게 차단 사유 반환
+ 사용자 원문 저장하지 않음
+ AgentExecutor.run() 호출하지 않음
```
