# 07. 6단계 — 실행기 구성과 스트림 준비

## 6단계에서 하는 일

1. 실제 실행에 필요한 기본 `AgentExecutor`를 만든다.
2. 1~3단계에서 준비한 정보를 `AgentExecutor.run()`에 전달한다.
3. 실행 이벤트를 기록할 `trace_events()`를 연결한다.
4. 이벤트를 화면으로 보낼 스트리밍 응답을 만든다.
5. 화면이 스트림을 읽기 시작하면 실제 제너레이터 실행을 시작한다.

이 단계에서 만들어지는 구조는 다음과 같다.

```text
StreamingHttpResponse
└─ _relay
   └─ _run_deep_agent
      └─ trace_events
         └─ AgentExecutor.run
```

## 전체 동작 흐름

```text
5단계 사용자 원문 저장 완료
    ↓
기본 AgentExecutor 생성
    ↓
런타임 입력값 전달
    ↓
AgentExecutor.run() 제너레이터 생성
    ↓
trace_events()로 실행 이벤트 감싸기
    ↓
_relay()로 화면 전송과 결과 저장 준비
    ↓
StreamingHttpResponse 생성
    ↓
클라이언트가 스트림 읽기 시작
    ↓
제너레이터 실제 실행 시작
    ↓
7단계 정의 로딩·그래프 조립
```

## `AgentExecutor.run()`에 전달하는 정보

```text
agent_id
+ agent_version_id
+ user_input
+ RuntimeContext
+ conversation_messages
+ tool_refs_override
```

이 정보는 1~3단계에서 이미 준비된 값이다.

## 제너레이터 실행 방식

`AgentExecutor.run()`은 호출 즉시 전체 실행을 완료하는 일반 함수가 아니라
이벤트를 하나씩 반환하는 제너레이터다.

```text
run() 호출
→ 실행 결과가 아니라 이벤트 제너레이터 생성

스트림 소비 시작
→ run() 내부 로직 실제 실행
```

따라서 `StreamingHttpResponse`가 이벤트를 읽기 시작해야 에이전트 정의 로딩과
그래프 조립도 실제로 시작된다.

## 실행 추적 시작 시점

6단계에서는 `trace_events()`를 연결하지만 DB의 `agent_run` 실행 기록은 아직
생성하지 않는다. 실제 실행 기록은 7단계의 정의 로딩과 그래프 조립이 성공한 뒤
생성되는 `agent_started` 이벤트를 `trace_events()`가 받았을 때 시작된다.

```text
AgentExecutor.run() 실행 시작
    ↓
7단계 정의 로딩·그래프 조립
    ↓
agent_started 이벤트 생성
    ↓
trace_events()가 이벤트 확인
    ↓
agent_run 실행 기록 생성
```

## 다음 단계와의 경계

6단계는 실행기와 이벤트 스트림을 준비하는 단계다. 에이전트 정의를 읽고 모델,
도구, 미들웨어, 프롬프트와 Child 에이전트를 조합해 Runtime Graph를 만드는 작업은
7단계에서 다룬다.

6·7단계의 통합 아키텍처는 7단계 학습이 끝난 뒤 별도로 정리한다.
