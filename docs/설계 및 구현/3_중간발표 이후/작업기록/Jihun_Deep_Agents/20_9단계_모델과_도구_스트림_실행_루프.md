# 9단계 — 모델·도구 스트림 실행 루프

## 이 단계에서 하는 일

Root Agent가 요청을 판단하고, 필요한 도구나 서브에이전트를 호출하고, 결과를 다시 읽어 최종 답변을 만들 때까지 반복한다.

```text
모델 판단 → 작업 실행 → 결과 반영 → 모델 재판단
```

## 전체 동작

```text
사용자 메시지
     ↓
Root 모델 호출
     ↓
직접 답변 또는 Tool Call
     ├─ 직접 답변 → 최종 결과
     └─ Tool Call
          ├─ 일반 Tool 실행
          └─ GP·Child Agent 위임
                  ↓
             결과를 상태에 추가
                  ↓
             Root 모델 재호출
```

이 루프는 최종 답변, 실행 오류 또는 HITL 승인 대기가 발생할 때까지 계속된다.

## 모델 호출과 미들웨어

모델 호출 전후로 조립된 미들웨어가 현재 상태와 설정에 따라 프롬프트, Memory, Skills, 대화 요약과 실행 정책을 적용한다.

Root 모델은 현재 메시지와 도구 목록을 보고 직접 답변, 일반 Tool 호출, GP·Child 위임 또는 복수 Tool Call을 결정한다. GP와 Child 위임도 모델 입장에서는 `task` Tool 호출이다.

## 일반 Tool 실행

```text
AIMessage의 Tool Call
        ↓
Tool 실행 어댑터와 권한 확인
        ↓
실제 Handler 호출
        ↓
ToolMessage 생성
        ↓
Graph 상태에 추가
```

Tool 결과는 바로 최종 답변이 되지 않는다. Root 모델이 결과를 다시 읽고 추가 행동이나 최종 답변을 결정한다.

## GP·Child Agent 위임

```text
Root의 task 호출
        ↓
GP 또는 Child Graph 실행
        ↓
서브에이전트 내부의 모델·Tool 루프
        ↓
서브에이전트 결과
        ↓
Root에 task 결과로 반환
```

Root는 위임 결과를 받은 뒤 다시 판단한다.

## 병렬 실행

모델 응답 하나에 Tool Call이 여러 개 있으면 병렬 실행할 수 있다. 동시 실행 수는 `max_concurrency`를 넘지 않으며 초과 호출은 버리지 않고 기다린다.

## 상태 저장

Checkpointer는 같은 `thread_id`에 사용자 메시지, 모델 응답, Tool Call과 결과, 서브에이전트 결과와 중단 위치를 저장한다. 다음 요청과 HITL 재개는 이 상태를 이어서 사용한다.

## 원시 이벤트

`runtime.stream()`은 실행 중 다음 형태를 반환한다.

```text
(namespace, mode, payload)
```

- `namespace`: Root, GP 또는 Child 중 이벤트 발생 위치
- `mode`: `updates`, `custom`, `messages`
- `payload`: 모델 메시지, 도구 결과 또는 진행 정보

이 값은 아직 우리 서비스의 공통 이벤트가 아니다.

## HITL 분기

승인 대상 Tool Call이면 HITL 미들웨어가 실제 Tool 실행 전에 Graph를 중단한다. Checkpointer가 중단 상태를 저장하고 interrupt 원시 이벤트를 만든다.

## 종료 조건

- Tool Call 없는 최종 AIMessage가 나오면 정상 종료한다.
- 승인 대상 Tool이면 중단하고 사용자 결정을 기다린다.
- 실행 예외가 발생하면 오류 경로로 종료한다.

다음 단계에서 `EventMapper`가 원시 이벤트를 서비스 공통 이벤트로 변환한다.
