# 10. 7단계 세부 02 — Root 모델 해석과 생성

## 이 단계에서 하는 일

1. Root 정의에서 모델 이름과 추론 강도를 가져온다.
2. 팀에 등록된 커스텀 모델인지 확인한다.
3. 사용할 모델 공급자와 접속 설정을 결정한다.
4. 필요한 API 키가 있는지 확인한다.
5. 결정된 설정으로 LangChain 모델 객체를 만든다.
6. 실제 사용한 모델 설정을 `resolved_model`로 보관한다.

## 전체 동작 흐름

```text
Root AgentDefinition
├─ model
└─ reasoning_effort
    ↓
team_id와 함께 모델 설정 해석
    ↓
모델 공급자 결정
    ↓
ResolvedModelConfig 생성
    ↓
API 키와 접속 정보 확인
    ↓
공급자별 LangChain 모델 객체 생성
    ↓
다음 도구 로딩 단계로 이동
```

## 모델 공급자 결정 순서

```text
1. 팀 커스텀 모델 확인
2. 모델명이 claude-로 시작하는지 확인
3. 나머지는 OpenAI 모델로 처리
```

### 팀 커스텀 모델

```text
팀에 해당 모델의 커스텀 엔드포인트가 있음
    ↓
provider = openai_compatible
    ↓
팀에 저장된 API Key와 base_url 사용
```

모델 이름이 `claude-`로 시작해도 팀 커스텀 모델로 등록되어 있으면 커스텀
설정이 우선한다.

### Anthropic 모델

```text
팀 커스텀 모델이 아님
+ 모델명이 claude-로 시작함
    ↓
provider = anthropic
    ↓
ANTHROPIC_API_KEY 사용
```

### OpenAI 모델

```text
팀 커스텀 모델이 아님
+ claude-로 시작하지 않음
    ↓
provider = openai
    ↓
OPENAI_API_KEY 사용
```

## `ResolvedModelConfig`

```text
ResolvedModelConfig
├─ provider
├─ model_id
├─ api_key
├─ base_url
└─ reasoning_effort
```

| 값 | 의미 |
|---|---|
| `provider` | `anthropic`, `openai`, `openai_compatible` 중 하나 |
| `model_id` | 실제 호출할 모델 이름 |
| `api_key` | 모델 호출에 사용할 인증 키 |
| `base_url` | 팀 커스텀 엔드포인트 주소 |
| `reasoning_effort` | 모델에 적용할 추론 강도 |

## 실제 모델 객체 생성

```text
provider = anthropic
→ ChatAnthropic

provider = openai
→ ChatOpenAI
→ Responses API 사용

provider = openai_compatible
→ ChatOpenAI
→ 커스텀 base_url 사용
→ Responses API 사용 안 함
```

## 추론 강도 적용 방식

### Anthropic

```text
reasoning_effort
→ output_config.effort
```

### OpenAI

```text
reasoning_effort
→ reasoning.effort
+ reasoning.summary = auto
```

`summary = auto`를 함께 설정하여 화면에서 사용할 reasoning 요약을 받을 수 있게
한다.

### OpenAI 호환 모델

```text
reasoning_effort를 전달하지 않음
```

OpenAI 호환 서버마다 추론 파라미터 지원 여부가 다르기 때문이다.

## 커스텀 모델 처리

```text
model_id
+ API Key
+ base_url
+ stream_usage = True
```

`stream_usage=True`는 커스텀 엔드포인트에서도 입력·출력 토큰 사용량을 받을 수
있도록 설정한다.

## 실패하는 경우

```text
Root에 모델이 설정되지 않음
Anthropic API Key가 없음
OpenAI API Key가 없음
커스텀 모델 API Key가 없음
알 수 없는 provider
```

위 경우 모델 객체를 만들지 않고 Runtime Graph 조립을 중단한다. 팀 커스텀 모델
설정 DB 조회 자체가 실패한 경우에는 전체 실행을 막지 않고 기본 Anthropic 또는
OpenAI 설정으로 넘어간다.

## 아직 모델 API는 호출하지 않는다

```text
모델 객체 생성
≠ 모델 API 호출
```

실제 사용자 입력을 모델에 보내는 작업은 9단계의 `runtime.stream()`에서 일어난다.

## 이 단계의 결과

```text
model
→ Runtime Graph에 연결할 LangChain 모델 객체

resolved_model
→ 실제 선택된 공급자와 접속 설정
```

`resolved_model`의 공급자와 커스텀 엔드포인트 해시는 이후 `agent_started` 이벤트와
`agent_run` 기록에 사용한다. API Key와 원본 커스텀 주소는 실행 로그에 저장하지
않는다.
