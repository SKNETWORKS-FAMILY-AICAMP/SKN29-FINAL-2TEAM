# 7단계 세부 10 — Graph 조립 완료와 실행 시작 기록

## 이 단계에서 하는 일

Root Graph 조립이 성공했음을 `agent_started` 이벤트로 알리고, 현재 실행을 `agent_run` 테이블에 기록한다.

아직 `runtime.stream()`은 호출하지 않는다.

## 전체 동작

```text
Root Graph 조립 성공
        ↓
agent_started 이벤트 생성
        ↓
trace_events()가 이벤트 확인
        ↓
agent_run 행 생성
        ↓
이벤트를 변경하지 않고 채팅 스트림으로 전달
```

## `agent_started` 생성

이 이벤트는 Agent 정의, 모델, 도구, Child Graph, GP, Memory·Skills와 Root Graph 조립이 모두 성공한 뒤에만 생성된다.

이벤트에는 다음 정보가 들어간다.

| 정보 | 의미 |
|---|---|
| `run_id` | 이번 실행의 고유 ID |
| `agent_id` | 실행 중인 Root Agent |
| `agent_version_id` | 사용한 Agent 버전 |
| `resolved_provider` | 실제 선택된 모델 제공자 |
| `resolved_endpoint_hash` | 실제 모델 엔드포인트 식별값 |
| `complete` | 실행이 끝나지 않았으므로 `False` |

Graph 조립 중 오류가 발생하면 `agent_started`는 생성되지 않는다.

## 실행 이력 생성

채팅 계층은 `executor.run()`의 이벤트 스트림을 `trace_events()`로 감싼다.

`trace_events()`가 `agent_started`를 확인하면 다음 순서로 실행 이력을 생성한다.

```text
_record()
    ↓
_start_run()
    ↓
AgentRunRepository.start_with_id()
```

저장되는 핵심 정보는 `run_id`, Agent와 버전, 세션, 부모 실행, Runtime 프로필, 실제 모델 제공자와 엔드포인트 식별값이다.

## 열린 실행 상태 관리

실행이 시작되면 추적기는 `run_id`와 시작 시각을 기억한다.

- `result`가 오면 `DONE`으로 종료한다.
- `error`가 오면 `FAILED`로 종료한다.
- 승인을 기다리면 `PENDING`으로 전환한다.
- 스트림이 비정상 종료되면 열린 실행을 `FAILED`로 정리한다.
- 시작 시각을 이용해 `duration_ms`를 계산한다.

## 실행과 기록의 분리

실행 이력 저장이 실패해도 오류만 로그에 남기고 같은 이벤트를 그대로 내보낸다. 관측 데이터 저장 실패가 실제 사용자 응답을 중단하지 않도록 한 구조다.

## 단계 종료 상태

Root Graph, 실행 ID, 실제 모델 정보와 실행 이력은 준비됐지만 LLM, Tool, Child Agent는 아직 실행되지 않았다.
