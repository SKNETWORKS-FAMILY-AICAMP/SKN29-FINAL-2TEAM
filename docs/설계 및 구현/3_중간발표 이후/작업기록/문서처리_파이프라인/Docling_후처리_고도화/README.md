# Docling 후처리 고도화 문서 안내

## 목적과 현재 결론

이 폴더는 중간발표 이후 진행한 Docling 후처리 실험 가운데 팀 공유와 Git 이력에
필요한 문서만 선별한 기록이다. 개인 실험 폴더의 모든 로그·중간 ZIP·코퍼스를
복제하지 않고 다음 세 가지 흐름을 남긴다.

1. 동일 page·동일 parent의 인접 sibling 국소 순서 역전 보정
2. 인계받은 헤딩 후보 규칙의 교차문서·AutoResearch-lite 검증
3. 완성 Docling JSON 이후 순서보정·헤딩 후처리를 결합하기 위한 병합 준비 범위와
   Worker 계약

현재 기능은 Docling 내부 모델이나 OCR을 대체하지 않는다. 순서 보정은 확실한
국소 관계만 최소 변경하고, 헤딩 승격은 독립 양성 HOLDOUT이 부족해 기본 비활성
실험 기능으로 전달한다.

이미지를 각 관련 폴더에 함께 두었다.

## AutoResearch 적용 범위

- **헤딩:** 고정 DEV 라벨에서 broad 23,328조합과 list-item 전용 96조합을 실제
  전수 평가했다.
- **순서보정:** AutoResearch-lite 평가 골격과 증거 준비도 검사는 만들었지만,
  DEV·사후검토·합성·독립 근거가 섞여 있어 threshold 자동탐색은 실행하지 않았다.
  결과 상태는 `EVIDENCE_NOT_READY_FOR_THRESHOLD_AUTORESEARCH`였다.

따라서 “두 영역 모두 AutoResearch로 최적화했다”가 아니라, **헤딩에는 제한적
전수탐색을 적용했고 순서보정에는 데이터 누수 방지를 위해 탐색을 차단했다**가
정확한 설명이다.

## 현재 핵심 지표

| 영역 | 현재 결과 | 해석 제한 |
|---|---|---|
| 국소 순서 AUTO | 누적 `60 TP / 0 FP` | 후보 Precision이며 전체 문서 Recall이 아님 |
| 순서 Precision Wilson 95% 하한 | `93.9828%` | 엄밀한 `>94%`에는 0.0172%p 부족 |
| 헤딩 list-item DEV | `12 TP / 0 FP / 6 FN / 126 TN` | DEV 결과이며 HOLDOUT 운영 성능이 아님 |
| 헤딩 최종 실험 threshold | 들여쓰기 `0~25pt`, 세로 `0~35pt` | 36개 동률 정책 중 재현값 |
| 헤딩 운영 상태 | `default-off` | 신규 양성 HOLDOUT에서 후보 반복 재현이 필요 |

## 문서 선별 기준

- 같은 내용을 반복하는 문서는 파라미터 감사·전체 이력·최종 지표 정본만 포함했다.
- 약 450KB의 canonical 전체 로그는 시행착오와 시점별 판단을 보존하기 위해 원문
  그대로 포함하고, 날짜·결정·검증·한계를 재구성한 상세 작업기록도 함께 두었다. 처음 읽을 때는
  요약 기록을 우선하고, 세부 시행착오·날짜별 근거가 필요할 때 전체 로그를 본다.
- PDF 원문, RunPod 결과 전체, 라벨 원본과 코드는 이 폴더에 넣지 않았다. 설명에
  직접 필요한 대표 증거 이미지만 포함했으며, 제품 병합에는 별도 handoff 패키지의
  코드와 테스트를 사용한다.
- 민감정보와 `.env`, API key, RunPod 인증정보는 포함하지 않는다.

## 통합 전 주의사항

- 이 폴더에서 말하는 통합은 **사용자 담당 범위인 국소 순서보정과 헤딩 개선의
  결합·Worker 병합 준비**를 뜻한다. 원빈님이 담당한 표·이미지 정보 보완,
  PaddleOCR-VL 검토 등 다른 문서처리 작업까지 합쳐진 전체 파이프라인 통합 완료를
  뜻하지 않는다.
- 실험·재현 기준은 Docling `2.119.0`이다. 과거 `2.117.0` 문서는 역사 기록이다.
- 헤딩 AutoResearch의 최종 기록값은 `0~25pt / 35pt`지만 일부 실험 코드 기본값은
  과거 `4~40pt / 25pt`가 남아 있다. 병합 시 최종 정책을 명시적으로 주입하거나
  담당 코드에서 불일치를 해소해야 한다.
- parent/group 관계 오류와 텍스트 추출 누락은 이 순서 swap 규칙의 수정 대상이
  아니다.
