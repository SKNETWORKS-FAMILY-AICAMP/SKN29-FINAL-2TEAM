# Heading 파라미터 조정 감사 보고서

작성일: 2026-08-25
대상 환경: Docling 2.119.0
성격: 실제 산출물 기반 사후 감사. 기록이 없는 중간 실험은 재구성하지 않았다.

## 1. 결론부터

헤딩 개선은 하나의 threshold를 계속 미세 조정한 단일 실험이 아니었다. 실제 기록은 다음 세 단계로 나뉜다.

1. 인계받은 density 4신호 규칙의 잠정값을 교차문서에서 검증했다.
2. 숫자 threshold만으로는 Precision과 Recall을 함께 확보할 수 없음을 확인하고 구조 guard/관계 분기로 전환했다.
3. 팀원 지침에 따라 최종 문제를 `raw label=list_item`인 whole element의 안전한 승격으로 좁히고, 별도 DEV 144행에서 96개 관계 threshold 조합을 비교했다.

최종 재현 정책은 아래와 같다.

```text
raw_layout_label == list_item
AND 명시적 목차 페이지가 아님
AND 날짜 반복 카드 페이지가 아님
AND 바로 다음 raw element의 label == text
AND next_indent_delta ∈ [0, 25] pt
AND next_vertical_delta ∈ [0, 35] pt
→ section_header 승격 후보
```

DEV에서는 `12 TP / 0 FP / 6 FN / 126 TN`, Precision 100%, Recall 66.7%, F1 0.80이었다. 그러나 독립 신규 문서에서 양성 자동승격이 재현되지 않았으므로 운영 기본 활성화가 아니라 **default-off 실험 기능**으로 동결됐다.

## 2. 최초 인계 파라미터

최초 density 규칙은 다음 네 조건을 모두 만족하면 `text/list_item`을 헤딩 후보로 보았다.

| 파라미터 | 최초값 | 의미 |
|---|---:|---|
| `WINDOW_PT` | 120.0pt | 후보 위·아래 텍스트 밀도 창 |
| `SIZE_MARGIN` | 1.15 | 로컬 본문 글자 높이 대비 최소 배율 |
| `SHORT_TEXT_MAX_CHARS` | 60자 | 짧은 텍스트 상한 |
| `MIN_GAP_ABOVE` | 4.0pt | 후보 위 최소 공백 |
| `MIN_DENSITY_SCORE` | 0.0 | `density_below - density_above` 하한 |

이 값은 한화 1문서 사례 기반의 잠정치였다. 특히 `Americas`는 고정 120pt 창에 이전 섹션 본문이 들어와 density score가 음수가 되면서 놓쳤다.

## 3. 1차 교차문서: 숫자 threshold의 한계 확인

### 데이터

- Docling 2.119 추출 sample: 15개
- 표적 CSV 행: 26행
- 이 중 `is_candidate=true`이고 TP/FP가 확정된 실제 탐색 입력: 22행
- 클래스: TP 8 / FP 14

26행과 22행의 차이는 오류가 아니다. `crossdoc_119_v2_target_results.csv`에는 감사용 표적 행도 함께 있고, 탐색기는 `gold_label ∈ {TP,FP}`이면서 `is_candidate=true`인 행만 사용한다.

### 네 숫자 threshold 탐색

구조 후보 조건을 고정한 뒤 아래 조합 1,120개를 전수 비교했다.

| 파라미터 | 탐색값 |
|---|---|
| size ratio | `0.0, 0.75, 0.8, 0.85, 0.9, 0.95, 1.0, 1.05, 1.10, 1.15` |
| max chars | `20, 40, 60, 80` |
| min gap | `0, 4, 8, 12`pt |
| min density | `-1.0, -0.6, -0.3, -0.1, 0, 0.1, 0.5` |

결과:

| 선택 기준 | TP | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| 최고 F1 | 8 | 10 | 0 | 44.4% | 100% | 0.615 |
| Precision ≥95%에서 최고 Recall | 2 | 0 | 6 | 100% | 25% | 0.400 |

즉 네 숫자를 조절하는 것만으로는 목표였던 높은 Precision과 유의미한 Recall을 함께 얻지 못했다. 이 결과 때문에 숫자 조정이 아니라 목차·카드·key-value·중복 이미지 텍스트 차단과 구조 관계 분기로 방향을 바꿨다.

## 4. 구조 분기와 AutoResearch-lite 1차

같은 DEV 22행을 관찰해 다음 구조 분기를 진단적으로 추가했다.

- 차단: key-value, 목차/index, 반복 카드, 기존 heading과 겹치는 이미지 텍스트
- 승격 가설: sparse uppercase divider, 큰 짧은 소제목, list heading 뒤 들여쓴 본문, text heading 뒤 연속 list

같은 DEV에서는 `8 TP / 0 FP / 0 FN / 14 TN`이었지만, 이 규칙 자체가 같은 DEV에서 만들어졌으므로 HOLDOUT 성능이 아니다.

그 뒤 AutoResearch-lite가 아래 10개 파라미터의 23,328개 조합을 한 번에 전수 평가했다.

| 파라미터 | 탐색 범위 |
|---|---|
| `large_size_ratio` | 1.6, 1.8, 2.0, 2.2 |
| `large_max_chars` | 30, 45, 60 |
| `sparse_candidate_max` | 4, 6, 8 |
| `uppercase_latin_share` | 0.5, 0.65 |
| `uppercase_share` | 0.75, 0.85 |
| `list_indent_min` | 2, 4, 6pt |
| `list_indent_max` | 30, 40, 50pt |
| `list_vertical_max` | 20, 25, 30pt |
| `text_to_list_count` | 2, 3 |
| `text_to_list_vertical_max` | 60, 70, 80pt |

기준선 파라미터는 `1.8 / 60 / 6 / 0.5 / 0.75 / 4~40pt / 25pt / 3 / 70pt`였다. v2 기준선은 8/0이었으며, 동일한 8/0을 만든 설정이 10,368개였다.

이 결과의 의미는 “최적 threshold를 정밀하게 찾았다”가 아니다. 22행으로는 1만 개 이상의 설정을 구분하지 못하므로, 성능이 같은 경우 기존 기준선을 유지하는 것이 가장 재현 가능하다는 결론이다.

또한 `results/heading/summary.json`의 초기 기준선은 7/0이고 `heading_v2/summary.json`은 8/0이다. 차이는 숫자 탐색 성과가 아니라 `PROMOTE_LARGE_SHORT_SUBHEADING` 구조 분기가 추가되어 `Dick & Carey 모형` 1건을 회수한 코드 변화다. 이를 threshold 개선량으로 보고하면 안 된다.

## 6. list-item threshold 탐색과 최종 선택

탐색 범위는 다음 96개 조합이다.

- `indent_min`: 0, 4, 8, 12pt
- `indent_max`: 25, 30, 35, 40pt
- `vertical_max`: 20, 25, 30, 35, 40, 50pt
- `repeated_date_min=3`은 고정 guard이며 탐색하지 않았다.

선정 우선순위는 다음이었다.

1. 양성 문서별 Recall 최솟값
2. 전체 Recall
3. Precision Wilson 95% 하한

비교 가능한 주요 지점:

| 정책 | TP/FP/FN/TN | Precision | Recall | F1 |
|---|---|---:|---:|---:|
| 이전 broad baseline의 list 관계값 `4~40, v≤25` | 11/0/7/126 | 100% | 61.1% | 0.759 |
| `4~40, v≤35` | 12/0/6/126 | 100% | 66.7% | 0.800 |
| 최종 기록값 `0~25, v≤35` | 12/0/6/126 | 100% | 66.7% | 0.800 |

중요한 감사 결과: 96개 조합 모두 이 DEV에서 FP가 0이었고, 최상위 `12/0/6/126` 성능을 만든 조합도 36개였다. 따라서 `0~25/35`는 유일하게 식별된 과학적 최적값이 아니다. 현재 검색 순서와 보수적인 폭의 재현값으로 선택된 동률 정책이다. 최종 문서에서는 “AutoResearch가 유일한 최적값을 발견했다”가 아니라 “안전성 guard 아래에서 36개 동률 정책 중 재현값을 동결했다”고 설명해야 한다.

## 7. HOLDOUT과 현재 상태

| 단계 | 문서·페이지 | 결과 | 해석 |
|---|---|---|---|
| broad HOLDOUT v1 | 8문서·24페이지 | 0 TP / 1 FP | 한국어 목차 카드 오승격, 실패 후 회귀 DEV 전환 |
| broad HOLDOUT v2 | 10문서·69페이지 | 0 TP / 6 FP | broad policy 운영 승격 거부 |
| list-item HOLDOUT v1 | 3문서·13페이지, 67 list-item | 0 TP / 0 FP / 67 TN | 정상 보존은 확인, 양성 효용은 미검증 |
| 신규 양성 표적 HOLDOUT | 3문서·7페이지, 36 list-item | 자동 후보 0 | 목표 구조가 희소함 |
| 공동 신규 HOLDOUT | 5문서·9페이지, 97 list-item | 자동 후보 0 | 두 번째 독립 no-hit |
| 실제 적용 데모 | 한화 1문서 | 3건 적용·schema PASS | 기능 경로 증거, 범용 효용 증거 아님 |

최종 판단:

- whole-element `list_item -> section_header` 후보 생성만 default-off로 전달한다.
- 요소 내부 제목/본문 분할은 하지 않는다.
- heading level은 기존 담당자의 level 보정 단계에 맡긴다.
- 실제 자동 활성화는 신규 문서 양성 재현과 별도 운영 기준 충족 후 다시 판단한다.

## 8. 팀원에게 30초 설명

> 처음에는 짧음·크기·여백·밀도 네 숫자를 조절했지만 15개 교차문서 DEV에서 높은 정밀도와 재현율을 동시에 만들 수 없었습니다. 그래서 구조 오탐을 막고 문제를 `list_item 뒤에 별도 본문 text가 이어지는 경우`로 좁혔습니다. 최종 DEV는 9문서 ID, 144개 라벨이고 96개 조합을 비교해 12 TP·0 FP, Recall 66.7%인 `indent 0~25pt, vertical 0~35pt`를 재현값으로 동결했습니다. 다만 동률 정책이 36개이고 신규 HOLDOUT 두 번에서 자동 후보가 0건이라, 현재는 기능 경로만 검증된 default-off 실험 기능입니다.
