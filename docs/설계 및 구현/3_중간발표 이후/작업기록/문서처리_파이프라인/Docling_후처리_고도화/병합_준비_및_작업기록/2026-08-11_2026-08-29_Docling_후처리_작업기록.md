## 1. 시작 상태와 문제 정의

기존 팀원이 작성한 Docling 노트북과 한화 PDF 결과를 인계받아, 페이지 내부의
읽기 순서가 시각적 순서와 다르게 배열되는 사례를 확인했다. 대표 사례는 한화
문서에서 문단이 아래로 내려갔다가 오른쪽으로 돌아오는 흐름, History와 적용산업
카드의 순서 불일치였다.

초기에는 전체 reading order를 고치는 문제처럼 보였지만, 멘토링과 full-page
라벨링을 거치며 다음 세 오류를 분리했다.

- 같은 부모의 sibling 순서만 틀린 국소 오류
- parent/card/table/form 관계 자체가 틀린 구조 오류
- PDF 텍스트 추출 누락·깨짐

이후 자동 보정 범위는 첫 번째 오류로 한정했다. 서로 다른 원인을 하나의 좌표
규칙으로 고치면 정상 구조를 훼손할 가능성이 크기 때문이다.

## 2. 국소 순서 보정 개발

### 수행 내용

- Docling JSON의 `page`, `parent_ref`, body 인접성, bbox를 사용한 관계 feature 구성
- 같은 page·같은 parent·인접 sibling만 비교하는 fail-closed detector 작성
- 좌우 정렬 `≤0.035`, 세로 차이 `0.005~0.08`, 시각적 중간 sibling 0개를 자동
  적용 대역으로 고정
- `0.08~0.18`은 자동 변경이 아닌 REVIEW 탐지 대역으로 분리
- 교환 작업을 `SWAP_ADJACENT` 하나로 제한하고 ref·cycle·dangling·멱등성 검사
- 한국어/영어 텍스트 연속성은 보조 신호로만 사용

### 변경 이유

문서 전체를 다시 정렬하는 방식은 다단·표·카드에서 큰 회귀를 만들 수 있었다.
따라서 좌표·부모·인접성이 모두 일치하는 두 요소만 바꾸는 최소 변경 방식으로
범위를 축소했다.

### 검증

- 브로슈어, 한국 기업 보고서, 기술 문서, IPO·금융 다단, 양식·RFP 코퍼스 사용
- 어려운 full-page 35쪽에서 sibling 오류·parent 오류·정상·판정불가를 분리 라벨링
- 여러 신규 frozen HOLDOUT을 Docling 2.119에서 실행
- 누적 AUTO `60 TP / 0 FP`, 관측 Precision 100%
- Precision Wilson 95% 하한 `93.9828%`
- 신규 최종 문서에서 2건 TP를 찾았고 1건 자동 swap, 1건은 중간 sibling으로 보존

### 생긴 변화

기능 정의가 “전체 문서 순서 복원”에서 “고정밀 Local Sibling Order Correction”으로
명확해졌다. 자동화할 수 없는 관계도 버리지 않고 audit에 기록하되 무인 운영에서는
원본을 유지하도록 계약했다.

## 3. 범용성·효율성 보강

한화 문서에 과적합하지 않기 위해 외부 PDF와 Docling 이슈·PR, DocLayNet 계열
복잡 문서, 한국 기업 보고서, 공개 브로슈어를 추가했다. 좌표는 페이지 너비·높이
기준 0~1로 정규화해 용지 크기 차이를 줄였다.

PaddleOCR-VL/PP-Layout의 `block_order`도 shadow 비교했지만, OCR·layout 경로가
팀원 작업에 따라 바뀔 수 있어 주 파서를 대체하지 않았다. 현재 순서 보정은 파서와
독립된 JSON 후처리로 유지한다.

적용기 검증에서는 반복 실행 시 추가 변경이 발생하지 않는지, ref 집합과 개수가
유지되는지, 관계 cycle이 생기지 않는지를 확인했다. Docling/VLM 재실행보다 훨씬
낮은 로컬 후처리 비용을 유지했다.

## 4. 헤딩 규칙 인계와 기준선 재검증

### 최초 인계 규칙

- 위·아래 밀도 창 `120pt`
- 본문 대비 글자 높이 `1.15배 이상`
- 텍스트 `60자 이하`
- 위 공백 `4pt 이상`
- 아래 밀도와 위 밀도의 차이 `≥0`

### 교차문서 진단

Docling 2.119의 15개 sample, 확정 후보 22행(TP 8/FP 14)에서 네 숫자 threshold
1,120조합을 비교했다. 최고 F1 설정도 FP 10건이었고 FP 0을 요구하면 Recall이
25%로 감소했다.

숫자만 미세 조정하는 방식이 부족하다는 결론을 내리고 목차/index, 반복 카드,
key-value, 기존 헤딩 중복을 차단하는 구조 guard를 추가했다.

## 5. AutoResearch-lite와 헤딩 범위 축소

### AutoResearch-lite 계약

AutoResearch-lite는 모델 학습이 아니라 고정 JSON과 사람 라벨에서 threshold 조합을
결정론적으로 전수 평가하는 로컬 실험기다. DEV만 탐색에 사용하고 HOLDOUT은 수정하지
않으며 입력·정책 hash와 모든 결과를 저장했다.

### broad 정책 실패

초기 구조 분기 10개 파라미터의 23,328개 설정을 평가했으나, 동일한 8 TP/0 FP를
만든 설정이 10,368개였다. 이는 최적값을 찾았다는 의미가 아니라 데이터가 여러
threshold를 구분하지 못한다는 의미였다. broad HOLDOUT v1·v2에서는 각각 1 FP와
6 FP가 발생해 운영 승격을 중단했다.

### list-item 전용 정책

팀원 지침을 반영해 전체 요소의 원본 label이 `list_item`이고 바로 다음 별도 요소가
`text`인 경우만 대상으로 축소했다. 요소 내부 제목/본문 분할은 하지 않았다.

- DEV: 9개 문서 ID, 144행(TP 18/FP 126)
- 탐색: 들여쓰기 최소·최대와 세로 거리 96개 조합
- 최종 기록값: 들여쓰기 `0~25pt`, 세로 `0~35pt`, 반복 날짜 3개 이상 차단
- DEV 결과: `12 TP / 0 FP / 6 FN / 126 TN`, Precision 100%, Recall 66.7%, F1 0.80

최상 결과 동률 정책이 36개였으므로 최종값을 유일한 최적값으로 표현하지 않는다.
신규 양성 HOLDOUT 두 번에서 자동 후보가 0건이어서 현재는 `default-off` 실험
기능으로 동결했다.

### 순서보정 AutoResearch 적용 여부

순서보정용 평가 스크립트와 입력 hash 동결 골격도 만들었지만 threshold 자동탐색은
실행하지 않았다. 당시 28건 근거에는 DEV·사후검토·합성·독립 문서가 섞여 있었고,
이를 한 DEV로 탐색하면 HOLDOUT 독립성을 훼손하기 때문이다. 준비도 결과는
`EVIDENCE_NOT_READY_FOR_THRESHOLD_AUTORESEARCH`였으며, 순서 threshold는 교차문서
검증과 fail-closed 회귀를 거친 휴리스틱으로 동결했다.

## 6. 담당 후처리 병합 설계와 인수인계

두 후처리는 Docling 완성 JSON 다음에서 각각 proposal을 만든다. coordinator는
heading 구조 보정과 reading-order 보정의 충돌을 검사하고, 검증된 최소 patch만
적용한다. 외부 결과는 보정 JSON 또는 원본 유지 JSON이며 내부 audit에는 사유,
threshold, 대상 ref와 검증 결과를 남긴다.

Heading level 결정은 기존 헤딩 담당 단계에 남기고, 순서 보정은 OCR·PaddleOCR-VL
변경과 독립적으로 재계산할 수 있게 했다. 최종 handoff에는 코드, 테스트, Worker
adapter, 지표, 발표 이미지와 병합 가이드를 포함했다.

여기서 병합은 국소 순서보정과 헤딩 개선 사이의 처리 순서·충돌 계약 및 최신
Worker에 이식할 준비를 뜻한다. 원빈님이 작업한 표·이미지 정보 보완과
OCR/PaddleOCR-VL 경로를 포함한 전체 문서처리 파이프라인 통합은 아직 별도 단계다.

## 7. 알려진 제한과 차단 요인

- 전체 문서 reading order Recall은 측정되지 않았다.
- parent/group 오류는 sibling swap으로 고치지 않는다.
- 텍스트 추출 누락은 OCR/upstream 문제로 분리한다.
- 순서 보정 전후 VLM description 품질 A/B는 아직 실행하지 않았다.
- 헤딩 자동승격은 독립 신규 양성 재현이 부족하다.
- 헤딩 실험 코드 일부의 기본값 `4~40pt/25pt`와 최종 기록값 `0~25pt/35pt`가
  다르므로 병합 시 명시적 정리가 필요하다.
