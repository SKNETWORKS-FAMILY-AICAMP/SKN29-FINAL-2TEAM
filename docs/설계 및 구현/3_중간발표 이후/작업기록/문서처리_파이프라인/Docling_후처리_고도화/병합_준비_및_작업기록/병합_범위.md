# 국소 순서보정·헤딩 후처리 병합 범위

> 이 문서는 사용자 담당 범위인 국소 순서보정과 헤딩 개선의 Worker 병합 준비만
> 다룬다. 원빈님 작업본의 표·이미지 정보 보완, OCR/PaddleOCR-VL 경로 등 다른
> 문서처리 구성요소까지 통합됐다는 의미가 아니다. 최종 파이프라인 병합은 해당
> 작업본을 함께 대조한 뒤 별도로 수행해야 한다.

## 이 담당 작업본에서 병합 준비가 된 항목

- Reading Order `validated-local-v1.1` 탐지·guard·최소 교환 코드
- Worker 인메모리 DoclingDocument 어댑터
- 구조 신호가 복잡할 때 원본을 보존하는 fail-closed 경로
- 적용 후 Docling core schema gate
- 출력 validation에 남길 Reading Order 요약 audit
- Docling 2.119 기준 결합 회귀 테스트

## 팀원 정본을 우선 유지할 항목

- `density_heading_correction.py`
- Heading 후보 조건과 threshold
- Heading level 결정 책임
- 표·OCR·이미지 설명 설정
- HybridChunker와 embedding 로직

## 이 담당 작업본에서 제외

- 부모-자식 관계 복구
- 문서 전체 reading order 재구성
- OCR 누락·잘못된 bbox 복구
- REVIEW_REQUIRED 후보의 자동 적용
- Heading 요소 내부 텍스트 분할
- Docling 변환 과정 안에서 이미 생성된 picture description 재생성
- 실험 코퍼스·오버레이 생성기·웹 조사 자료를 Worker 이미지에 포함하는 작업

## 충돌 시 우선순위

1. 팀원의 최신 Worker 파이프라인과 Heading 구현
2. 이 패키지의 Reading Order 동작 계약과 테스트
3. 현재 프로젝트 안의 `runpod_worker/` 읽기용 사본

Reading Order 코드를 맞추기 위해 팀원의 최신 Heading 코드를 이전 버전으로 되돌리면 안 된다.
원빈님 작업본을 결합할 때도 표·이미지·OCR 설정을 이 패키지의 과거 사본으로
덮어쓰지 않고 최신 Worker를 기준으로 후처리 hook만 이식한다.
