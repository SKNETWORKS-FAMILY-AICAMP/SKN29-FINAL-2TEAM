## 반복된 실제 결함

1. 세 답변 모두 W-07 총 160인시와 전체 기간은 말했지만 로그·대시보드·분산추적·경보의
   세부 계획 날짜를 빠뜨렸다.
2. 세 답변 모두 계획과 실제 실적, 미정과 확정은 올바르게 구분했다.
3. 두 답변은 Judge evidence로 확인되지 않은 `선행 과업 없음`, `우선순위 중` 같은 부가
   속성을 단정했다.
4. 한 답변은 현재 평가 범위 밖의 다른 문서 상태를 보고 `일부 관련 파일은 색인 중`이라고
   덧붙였다. fixture 범위를 넘어선 실행환경 상태를 사용자 답변에 섞은 것이다.

## 인프라 사고와 처리

첫 시도는 `skill_catalog_revision` 테이블이 없어 Agent 시작 전에 중단됐다. 이는 Candidate
실패가 아니므로 원시 run은 보존하고 `INVALID_EVALUATION_INFRA` disposition을 추가했다.
누락된 2026-08-26~27 skill migration 7개를 적용한 뒤 `_apply.py --check` 50개 항목이
전부 통과한 상태에서 위 3회를 새로 실행했다.

인프라 실패 시도는 장애율과 이력에는 남기지만 readiness 복구 뒤 동결한 DEV 3개 slot의
분모에는 넣지 않는다. 공식 round에서는 별도 round manifest의 planned slot을 사용한다.

## 다음 조치

- S01은 현재 Candidate의 재현 가능한 답변 품질 결함으로 본다.
- Gold나 Judge를 완화해 통과시키지 않는다.
- Candidate 개선 시에는 세부 계획 일정 누락과 fixture 밖 부가 주장 억제를 함께 고친다.
- 같은 DEV 3회를 새 candidate cohort로 다시 실행하고 기존 결과를 덮어쓰지 않는다.
