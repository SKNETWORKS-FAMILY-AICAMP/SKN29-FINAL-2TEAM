# Agent 평가 V2 — S01 보류·S07 유지 결정

## 1. 결정

- S01은 현재 Candidate를 더 수정해 통과시키지 않는다.
- S01 상태는 `KNOWN_LIMITATION`·`DEFERRED_DOCUMENT_PREPROCESSING`으로 기록한다.
- S07의 평가용 도구 설명 수정은 유지한다.
- S01 실험 전 Candidate 정의로 복원한 `AG004/AV072`를 다음 freeze 검토 대상으로 쓴다.
- Phase 9와 HOLDOUT은 시작하지 않는다.

## 2. S01을 지금 해결하지 않는 이유

실제 PDF에서 상위 WBS 행과 그 하위 상세 일정표가 서로 다른 chunk로 분리돼 있다.
현재 검색만으로는 두 표의 구조 관계를 안정적으로 복원하기 어렵다. 이를 Candidate
prompt만으로 보완하면 특정 문서와 질문에 과적합될 수 있고, 관련 없는 표 행까지 답변에
포함해 S05A 같은 범위 최소화 평가를 악화시킬 위험도 있다.

실험 과정에서는 Candidate prompt뿐 아니라 검색, fixture, gold, Judge 입력과 실행
budget까지 함께 바뀌었다. 따라서 `AV067`~`AV071`의 결과는 동일 조건의 개선 비교로
사용할 수 없다. 이 버전과 결과는 원인 분석용 `DIAGNOSTIC_ONLY`로 보존하고 공식
cohort와 점수에서는 제외한다.

## 3. S01 재개 조건

다음 조건을 만족한 뒤 S01 개선을 다시 시작한다.

1. PDF 전처리가 절·표·행의 parent-child 관계를 보존한다.
2. 관련 상세표 전체를 가져오면서 무관한 행은 포함하지 않는 검색이 가능하다.
3. 여러 실제 PDF 표를 대상으로 한 회귀 fixture가 있다.
4. Candidate·fixture·gold·Judge·budget을 실행 전에 고정한다.
5. 고정된 조건으로 3회 반복 실행해 결과를 비교한다.

## 4. 유지하는 S07 수정

S07 fixture가 금지 도구를 의도적으로 노출할 때, `task_register`를 Jira 실행의 필수
선행 도구처럼 설명하지 않도록 registry를 수정했다. Jira 요청에는
`jira_create_issues`만 필요하며, `task_register`는 사용자가 플랫폼 내부 작업 등록도
명시적으로 요구한 경우에만 필요하다고 구분한다.

이 변경은 현재 배포 Candidate의 실제 도구 목록을 고친 것이 아니라 적대적 평가 환경의
도구 의미를 정확하게 만든 것이다. 환경 identity는 `EVAL_S07_TOOL_PROFILE_V2`, 종류는
`ADVERSARIAL_TOOL_SELECTION`, `deployment_equivalent: false`로 기록한다.

## 5. Candidate 복원 상태

`AG004/AV072`는 `AV035`의 다음 정의를 그대로 복제해 발행했다.

- model: `gpt-5.6-luna`
- reasoning: `low`
- max iterations: `6`
- tool 10개, subagent 없음
- S01 실험용 prompt와 검색 변경 없음
- S07 registry 수정 적용

과거 버전과 실행 결과는 불변 기록으로 남긴다. 삭제하거나 덮어쓰지 않는다.
