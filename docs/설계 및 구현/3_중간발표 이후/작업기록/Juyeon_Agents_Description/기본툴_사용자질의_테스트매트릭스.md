# 기본 툴 비-RunPod 사용자 질의 테스트 매트릭스

작성 기준: 2026-08-28 코드의 `services/harness/registry.py`

## 1. 범위와 판정 기준

- 사용자가 선택할 수 있는 기본 툴은 `DEFAULT_CHAT_TOOL_REFS` 기준 30개다. 항상 켜지는 시스템 툴 `skill_register`, `skill_creator_ask_followup`은 이 30개에 포함되지 않는다.
- RunPod를 직접 또는 간접 호출하는 `document_search`와 `task_extraction`은 제외한다. 둘 다 `services.document_pipeline.runpod_client.embed_queries` 경로를 사용한다.
- 따라서 이번 대상은 28개다.
- 여기서 “모든 경로”는 사용자가 선택할 수 있는 공개 입력 스키마의 operation/enum 경로, 읽기/쓰기 및 승인 분기, 주요 선행조건·입력 오류, 서로 비슷한 툴 사이의 라우팅 충돌 경로를 뜻한다. 라이브러리 내부 예외나 저장소 장애의 모든 조합까지 전수조합하는 의미는 아니다.

각 질의는 다음 네 항목을 확인한다.

1. 기대한 툴만 선택되는가.
2. 질의의 파일·기간·열·작업 값이 올바른 인자로 전달되는가.
3. 쓰기 작업은 승인 카드 이후 실행되고, 조회 작업은 승인 없이 실행되는가.
4. 성공 결과 또는 사람이 고칠 수 있는 오류가 최종 답변에 정확히 반영되는가.

### 공통 테스트 데이터 기호

- `[현재 프로젝트]`: Jira가 연결되고 플랫폼 업무가 등록된 프로젝트
- `[프로젝트 없음 대화]`: 프로젝트를 선택하지 않은 일반 대화
- `[PDF-A]`, `[PDF-B]`: 정상 PDF 파일 ID
- `[PDF-WM]`: 1페이지짜리 워터마크 PDF 파일 ID
- `[DOCX-A]`, `[DOCX-B]`: 정상 DOCX 파일 ID
- `[XLSX-A]`, `[XLSX-B]`: 정상 XLSX 파일 ID
- `[CSV-A]`, `[JSON-A]`, `[PARQUET-A]`: 정상 표 파일 ID
- `[MD-A]`: UTF-8 Markdown 파일 ID
- `[ZIP-A]`: 정상 ZIP 파일 ID
- `[TASK-A]`: 현재 프로젝트에 실제로 존재하는 task ID

`[이름으로 지칭한 파일]` 질의는 먼저 `document_list`로 ID를 찾아야 하는 연쇄 경로이고, `[...-A]`처럼 ID가 이미 제공된 질의는 처리 툴을 바로 호출해야 한다.

## 3. 복합 질의 10개

복합 질의는 한 번의 사용자 요청에서 여러 툴이 올바른 순서로 연결되는지 검사한다. 쓰기 툴마다 승인 카드가 필요하며, 선행 조회가 실패하면 뒤의 쓰기 작업을 실행하지 않아야 한다.

| ID | 사용자 질의 | 기대 툴 순서 | 핵심 판정 |
|---|---|---|---|
| MIX-01 | 현재 프로젝트의 플랫폼 업무와 Jira 이슈를 모두 조회해서 출처를 구분한 하나의 엑셀 현황표로 만들어줘. | `task_list` + `jira_get_issues` → `table_export` | 두 출처를 섞어 누락하지 않고 Excel 생성 전에 승인 |
| MIX-02 | 앞으로 4주 업무량, 팀원 기술, 휴가 일정을 함께 보고 다음 업무를 맡기기 좋은 후보 3명을 근거와 함께 추천해줘. | `workload_report` + `people_list` + `absence_list` | 사람을 자동 배정하지 않고 세 근거를 교차 사용 |
| MIX-03 | 내 파일의 ‘매출 원본’ 엑셀을 찾아 데이터 품질을 검사하고, 문제가 없으면 부서별 매출 합계를 집계해 막대 차트로 만들어줘. | `document_list` → `data_quality_check` → `table_transform` → `chart_create` | 품질 실패 시 후속 작업 중단, 성공 시 차트 승인 |
| MIX-04 | ‘계약서 이전본’과 ‘계약서 최신본’을 찾아 변경점을 비교하고, 변경 요약을 워드 보고서로 만들어줘. | `document_list` → `file_compare` → `document_create` | 비교 결과만 근거로 DOCX 작성 |
| MIX-05 | 방금 연결 폴더의 운영 가이드를 수정했어. 최신 내용을 반영한 뒤 현재 문서 목록에서 그 파일을 찾아 Word 원문을 읽고 PDF로 변환해줘. | `document_sync` → `document_list` → `document_read` → `document_convert` | 동기화 실패 시 중단, 변환 전 승인 |
| MIX-06 | 현재 프로젝트 플랫폼 업무를 조회해 마감이 이번 주 금요일 이전인 업무를 골라 확정 처리하고, 같은 제목으로 Jira에도 등록해줘. | `get_current_datetime` + `task_list` → `task_update` → `jira_create_issues` | 실제 task_id만 수정, 플랫폼 수정과 Jira 생성 각각 승인·부분실패 보고 |
| MIX-07 | `[PDF-A]`와 `[PDF-B]`를 합친 뒤 메타데이터를 제거하고, 최종 PDF의 해시와 페이지 수를 확인해줘. | `pdf_edit(merge)` → `file_sanitize` → `file_inspect` | 각 생성 단계 승인, 마지막 파일 ID를 다음 단계에 전달 |
| MIX-08 | `[CSV-A]`와 `[XLSX-B]`를 사번으로 결합해 공수 합계를 계산하고 XLSX로 저장한 다음, 부서별 공수 비율 파이 차트도 만들어줘. | `table_transform(join+output)` → `table_transform(aggregate+output)` → `chart_create` | 첫 결합 결과를 파일로 저장해 다음 호출에 전달하고 생성 단계마다 승인 |
| MIX-09 | 우리 팀 프로젝트별 진행률을 조회해 낮은 순으로 정리한 엑셀을 만들고, 같은 값으로 선 차트도 만들어줘. | `project_list` → `table_export` + `chart_create` | null 진행률을 0으로 조작하지 않으며 두 생성물 승인 |
| MIX-10 | `[MD-A]`를 Word와 PDF 두 형식으로 각각 변환하고 두 결과와 원본을 ‘제출 패키지’ ZIP으로 묶어줘. | `document_convert(docx)` + `document_convert(pdf)` → `archive_manage(create)` | 두 변환 결과 ID를 ZIP 입력으로 전달, 단계별 승인·부분실패 시 중단 |

## 4. 실행 기록 권장 형식

각 케이스 실행 결과는 아래 열로 기록하면 라우팅 문제와 실제 핸들러 문제를 분리하기 쉽다.

| case_id | selected_tools | arguments_ok | approval_ok | tool_status | output_ok | note |
|---|---|---|---|---|---|---|
| 예: PDF-05 | `pdf_edit` | PASS | PASS | OK | PASS | 3페이지만 90도 회전 |

- `selected_tools`: 실제 `tool_started.tool_ref` 순서
- `arguments_ok`: operation, 파일 ID, 날짜, 열 이름 등이 기대값과 같은지
- `approval_ok`: 조회는 승인 없음, 쓰기는 승인 후 실행인지
- `tool_status`: 각 `tool_completed.status`
- `output_ok`: 생성 파일, 조회 값, 오류 메시지가 기대 계약과 맞는지
- `note`: 실패 원인을 `라우팅`, `인자 생성`, `승인`, `핸들러`, `외부 연결` 중 하나로 분류
