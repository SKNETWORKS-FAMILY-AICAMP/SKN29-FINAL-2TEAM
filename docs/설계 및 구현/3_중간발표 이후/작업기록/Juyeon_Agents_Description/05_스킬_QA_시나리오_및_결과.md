# 스킬 QA 시나리오 및 결과

> 이 문서는 실행 결과를 보기 전에 테스트 시나리오와 합격 기준을 먼저 고정한다. 실패한 항목은 기대값을 바꾸지 않고 제품을 수정한 뒤 같은 항목을 다시 실행한다.

## 판정 원칙

- 단위 테스트의 mock 성공만으로 통과시키지 않는다. HTTP API, DB, 검증 워커, 실제 에이전트 스트림을 함께 확인한다.
- 스킬 사용 여부는 답변 문장으로 추측하지 않고 실행 이벤트와 도구 호출 기록에서 해당 `SKILL.md`를 읽었는지 확인한다.
- 답변 정확성은 입력의 핵심 사실 보존, 요구 형식, 금지 행동, 근거 없는 내용 추가 여부로 판정한다.
- LLM 출력이 달라질 수 있는 항목은 의미 기준으로 판정하되, 상태·권한·저장·활성 여부는 정확히 일치해야 한다.
- QA 데이터에는 `qa-20260827-` 접두사를 사용하고 시험 종료 후 제거한다.

## B. 실제 채팅 스킬 선택·답변 시나리오 20개

등록 QA에서 만든 후보는 검증기가 실제로 부적합 판정을 내렸으므로 억지로 게시하지 않았다. 채팅 QA는 같은 계약을 가진 기존 활성 개인 스킬 `korean-to-english-japanese-translation`을 대상으로 진행했다. 계약은 “사용자가 제공한 한국어 안내문을 영어와 일본어 두 언어로 함께 번역하고, 숫자·날짜·고유명사를 보존한다. 한 언어만 요구하거나 번역 외 작업에는 사용하지 않는다.”이다.

## 발견한 사용자 불편 판정 항목

- 실패 후 재수정할 때 기존 입력과 부족한 정보가 함께 보이는가.
- 재실패 때 같은 안내만 반복하지 않고 이번 실패 원인을 구분하는가.
- 이전 실패 카드가 최신 재시도를 가리거나 중복 알림으로 남지 않는가.
- 백그라운드 검증 중 화면 이동·새로고침 후에도 현재 작업을 찾을 수 있는가.
- 내부 코드, JSON, 재현율·정밀도 같은 구현 용어를 사용자에게 노출하지 않는가.
- 취소와 삭제, 공유 중지와 개인 스킬 삭제의 차이를 버튼 문구와 결과로 이해할 수 있는가.

R09처럼 검증 결과 자체가 성공이어야만 확인 가능한 부분은 부적합 후보를 강제로 통과시키지 않았다. 실제 데이터 변경 위험이 있는 공유 삭제 경로는 권한별 API 회귀 테스트와 읽기 실측을 결합했다.

### 채팅 20건 결과

- 답변 내용: 20건 모두 기능적으로 올바름. 숫자·시간·금액·고유명사를 보존했고, 원문이 없는 C14는 원문을 요청했으며, C16의 삽입 문장은 명령으로 실행하지 않고 번역 대상으로 처리했다.
- 선택 판정: 18/20 통과. `read_file` 또는 명시 실행의 `skill_applied` 이벤트로 판정했다.
- 미선택 2건: C05(정중한 두 언어 번역), C14(원문 없는 두 언어 번역). 답은 올바르지만 기존 스킬 파일을 읽지 않았다. 이는 API 고장이 아니라 기존 스킬 설명의 적용 범위가 두 표현을 충분히 포함하지 못한 선택 품질 문제다.
- 비활성/재활성: C18에서 비활성 스킬을 읽지 않았고 C19에서 다시 읽었다. 시험 종료 시 원래 활성 상태를 복원했다.
- 단일 언어, 교정, 요약, 스킬 생성, 설명 요청 같은 음성 사례 8건은 모두 번역 스킬을 읽지 않았다.

### QA에서 새로 발견해 고친 결함

1. 진행 센터가 상태 변경마다 polling timer를 다시 만들어 API를 초당 수십~수백 회 호출하던 문제를 안정된 ref 기반 주기로 수정했다.
2. 문맥형 검증 질문의 이전 대화를 미니 에이전트가 버리던 문제를 격리 실행 입력에 포함하도록 수정했다.
3. 실행 중 취소가 영구히 `CANCEL_REQUESTED`에 남는 문제를 워커의 취소 우선 처리로 수정했다.
4. 실패 재시도에서 원본 frontmatter·비활성 상태가 사라지고 일반 실패에서도 이름이 자동으로 바뀌던 문제를 수정했다.
5. 잘못된 YAML의 내부 파서 오류, 재설명 화면의 내부 도구명·범위명이 사용자에게 보이던 문제를 사용자 문장으로 교체했다.
6. 재설명 입력칸에 직전 답변이 남아 실수로 그대로 재전송될 수 있던 문제를 수정했다.

### 최종 회귀 확인

- 백엔드 전체: 1,548개 통과, 실패 0개
- 프론트엔드: TypeScript 검사 및 production build 통과(497 modules)
- 실제 브라우저: 새 스킬 되묻기, 초안 확인, 다시 설명하기, 실패/취소/워커 대기 목록 복원 확인
- 실제 워커: 정상 실행, 중단 중 대기, 재시작 복구, 실행 중 취소 확인
- QA 전용 계정 2개, job 6개, 채팅 세션 6개와 단일 탐색 세션은 시험 후 삭제했다. 제품 데이터는 삭제하지 않았다.

## 남은 품질 과제

- 기존 번역 스킬의 C05·C14 선택 누락은 그 스킬의 설명을 보완하고 정식 검증을 다시 통과시켜야 해결된다. 플랫폼이 미검증 기존 스킬을 임의 수정하거나 강제 게시해서는 안 된다.
- LLM 응답은 확률적이므로 이번 20건 통과율은 영구 보장이 아니다. 이 스크립트를 고정 회귀 세트로 CI 또는 배포 전 QA에서 반복 실행해야 한다.
- “모든 가능한 자연어”를 유한한 40개로 증명할 수는 없다. 이번 범위는 생성, 확인, 업로드, 실패, 다중 재시도, 취소, 워커 장애, 수정 충돌, 활성화, 공유, 권한, 문맥, 명시 실행, 유사 음성 요청까지 서로 다른 주요 상태 전이를 포함한다.
