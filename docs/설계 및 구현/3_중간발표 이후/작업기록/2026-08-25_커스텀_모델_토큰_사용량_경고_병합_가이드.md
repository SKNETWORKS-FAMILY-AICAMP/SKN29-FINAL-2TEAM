# 2026-08-25 — 커스텀 모델 토큰 사용량 경고, `main` 병합 가이드

> 브랜치: `jihun`. **DB 마이그레이션 없음** — 스키마·`_apply.py` 변경 없이
> 코드만으로 끝나는 변경이다. 다만 운영자 콘솔이 **외부 서버로 실제 네트워크
> 호출을 한 번 더** 하게 되므로, 병합 뒤 §2의 수동 확인만 챙길 것.

## 0. 무엇을 왜 고쳤나

멘토 지적: 팀이 커스텀 OpenAI 호환 엔드포인트(사내 서버, Gemini 호환 주소 등)를
쓰면 토큰 사용량이 영구히 안 잡히는 것 아니냐는 우려.

**확인 결과, 처음 걱정한 경로는 이미 막혀 있었다.** `langchain_openai`
1.3.0 소스(`chat_models/base.py:1231-1250`)를 직접 읽어 보면, "base_url이
있으면 `stream_usage`를 자동으로 못 켠다"는 규칙은 **`stream_usage`를 아무도
명시하지 않았을 때만** 적용된다. `services/agent_runtime/models/factory.py`의
`_create_openai_compatible()`은 이미 `stream_usage=True`를 **명시적으로**
넘기고 있어서 이 자동 판단 자체가 건너뛰어진다 — "명시적으로 켰는데도
base_url 때문에 막힌다"는 경로는 실제로 없다.

**진짜 남는 문제**는 다르다. `stream_usage=True`는 요청에
`stream_options={"include_usage": true}`를 얹을 뿐이고, 그 옵션을 실제로
지원하는지는 **상대 서버 마음**이다. 이걸 지원 안 하는 서버를 등록하면
`agent_run.token_in`/`token_out`이 영원히 `NULL`로 남는데, 지금 있는
연결 확인(`apps/ops/views/models.py`의 `_verify()`)은 스트리밍이 아니라서
이 사실을 등록 시점에 못 잡는다 — 실제 대화가 쌓인 뒤에야 발견된다.

**정책 결정**: 이런 서버라도 채팅 기능 자체는 정상 작동하므로 **등록을 막지
않는다.** 대신 등록 시점에 한 번 확인해서 안 되면 **경고만** 보여준다.

## 1. 바뀐 파일 목록

| `tests/test_ops.py` | 기존 `_verify` patch 테스트 4개에 `_check_usage_support` patch 추가(안 하면 테스트가 실제 네트워크 호출을 시도한다) + 경고 유무를 확인하는 신규 테스트 2개 |

**DB 변경 없음.** 사용량 지원 여부를 팀의 등록 행에 영구히 남기는 컬럼/플래그는
만들지 않았다 — 만들려면 `connector_conn.encrypted_credential_ref`의 암호화된
JSON 안에 새 필드를 넣어야 해서(`CustomModelRepository`가 `custom_model` 전용
테이블 없이 이 표를 재사용한다, `DB/schema.sql:191-206`), 암호화할 이유가
없는 값을 굳이 암호화된 필드에 얹는 부자연스러움이 생긴다. 이번 범위는
**등록하는 그 순간 한 번 보여주는 응답 메시지**로 그친다 — 등록된 표에는
영구 배지가 남지 않는다(§4).

## 2. `main` 병합 뒤 확인할 것

1. **마이그레이션 없음** — `DB/migrations/_apply.py --check`에 새로 걸리는
   항목이 없다. 배포 절차상 추가로 손댈 것이 없다.
2. **실제 네트워크 호출이 하나 늘었다.** 등록(`POST /api/ops/models/`) 한 번에
   `_verify()`(기존) + `_check_usage_support()`(신규) 두 번 외부 서버를 부른다
   — 등록이 살짝 느려진다(각 최대 25초 timeout). 운영 배포 뒤 `/ops/models`에서
   **실제로 하나 등록해서** 등록 자체가 여전히 되는지, 사용량 미지원 서버로는
   경고가 뜨는지 눈으로 확인할 것(단위 테스트는 `_check_usage_support`를
   patch로 대체하므로 실제 스트리밍 파싱까지는 안 본다).
3. 전체 테스트: `tests/test_ops.py`(신규 케이스 포함) 확인.

      "미지원"으로만 처리하고 등록을 막지 않음)

## 4. 이번에 안 한 것 (넘기는 것)

- **등록 표에 영구 "사용량 미지원" 배지 없음.** 지금은 등록하는 순간 1회성
  경고만 보여준다. 나중에 그 팀 모델이 정말 사용량을 못 재고 있는지 다시
  확인하려면 `/ops/usage`에서 그 팀의 `token_in`/`token_out`이 계속 `NULL`인
  실행이 쌓이는지로 간접 확인해야 한다(2026-08-21 관측성 작업에서 이미
  "못 잰 실행 수를 숨기지 않는다"는 원칙으로 화면에 노출 중).
- **등록 자체를 막는 옵션은 채택 안 함.** 채팅 기능과 사용량 측정은 별개
  능력이라, 후자가 없다고 정상 작동하는 모델을 등록 못 하게 막을 이유가
  없다고 판단했다(팀 회의에서 재검토될 수 있음).
