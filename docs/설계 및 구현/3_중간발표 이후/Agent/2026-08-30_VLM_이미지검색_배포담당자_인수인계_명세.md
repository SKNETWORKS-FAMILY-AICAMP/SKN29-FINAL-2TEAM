# VLM 이미지 검색·원본 Crop 배포 담당자 인수인계 명세

## 1. 배포 대상

이 문서는 `wonbin` 브랜치에 구현된 이미지 검색 결과의 원본 PDF crop 역추적 기능을
`main`에 병합하고 Backend·Frontend에 배포하기 위한 단일 인수인계 문서다.

| 항목 | 값 |
|---|---|
| 저장소 | `SKNETWORKS-FAMILY-AICAMP/SKN29-FINAL-2TEAM` |
| 작업 브랜치 | `wonbin` |
| 대상 커밋 | `44b34a9a99434a60c0c60cfe4dee0deefe171ccd` |
| 커밋 제목 | `feat: add VLM document image evidence` |
| 작성 시점 최신 `origin/main` | `18179cc` |
| DB migration | 없음 |
| RunPod Worker 추가 수정 | 없음 |
| RunPod Endpoint 변경 | 없음 |

`wonbin` 원격 브랜치가 위 커밋을 가리키는 것은 확인했다. `main`은 작업 시작 이후
변경됐으므로 병합 담당자는 최신 `main`을 받은 후 충돌을 검토해야 한다.

## 2. 배포 결과로 제공되는 기능

### 2.1 검색 도구 분리

| 도구 | 대상 모델 | 동작 |
|---|---|---|
| `document_search` | 모든 모델 | 검색 상위 청크의 본문 또는 이미지 description만 반환 |
| `document_search_with_images` | 이미지 입력 지원 모델 | description 검색 결과와 해당 원본 PDF crop 이미지를 함께 모델에 전달 |

기본 `top_k`는 `10`이고 허용 범위는 `1~20`이다. 이미지 검색도 description을 임베딩한
기존 벡터 인덱스를 사용한다. 이미지 자체를 별도 임베딩하거나 이미지 전용 DB를 추가하지
않는다.

### 2.2 원본 이미지 역추적

검색 결과가 `PICTURE` 청크이면 다음 식별자를 따라 원본을 찾는다.

```text
검색된 chunk
→ 연결 block_id
→ doc_id + revision
→ 원본 PDF storage_key
→ src_locator.prov[].page_no + bbox
→ 해당 PDF 페이지 영역을 PNG로 동적 crop
→ 단기 서명 URL을 VLM ToolMessage에 포함
```

문서 제목과 페이지만으로 이미지를 찾지 않는다. `block_id + doc_id + revision`이 현재
문서의 `PICTURE` block과 일치해야 하며 삭제·접근 철회 문서와 과거 revision은 거부한다.

crop은 4pt 여백을 포함해 2배율 PNG로 만든다. Docling의 `BOTTOMLEFT`와 `TOPLEFT`
좌표계를 모두 처리한다. 현재 원본 crop 대상은 PDF다. DOCX 등은 페이지 좌표 정합성을
보장할 수 없어 이미지 URL을 만들지 않는다.

### 2.3 모델 선택과 권한

- 기본 OpenAI·Anthropic 모델에는 모델 선택 화면에서 `이미지` 표시가 붙는다.
- OpenAI-compatible 커스텀 모델 등록 화면에는 `이미지 입력 지원` 체크 항목이 생긴다.
- 체크값은 기존 `connector_conn.encrypted_credential_ref` payload에 저장한다.
- 기존 커스텀 모델은 값이 없으므로 텍스트 전용으로 취급한다.
- 텍스트 전용 모델에서는 이미지 검색 도구를 선택할 수 없다.
- 이미지 도구 선택 후 텍스트 모델로 변경하면 해당 도구가 자동 제거된다.
- 프론트 우회 요청도 에이전트 저장·활성화 API에서 거부한다.
- 기존 저장 데이터를 우회한 경우에도 실제 ToolLoader가 실행 직전에 다시 거부한다.

## 3. 저장 구조와 DB 영향

DB migration은 필요 없다. 기존 컬럼을 사용한다.

| 데이터 | 기존 저장 위치 또는 처리 방식 |
|---|---|
| 이미지 검색 문장 | `chunk.search_text`의 VLM description |
| 이미지 block 종류 | `doc_block.block_type = 'PICTURE'` |
| 페이지 | `doc_block.page`, `src_locator.prov[].page_no` |
| 좌표 | `doc_block.src_locator.prov[].bbox` |
| 원본 PDF | `doc.storage_key` |
| 현재 개정 식별 | `doc.cur_revision`, `doc_block.revision` |
| 커스텀 모델 이미지 capability | 암호화된 connector payload |
| crop PNG | 영구 저장하지 않고 요청 시 메모리에서 생성 |

따라서 이미지 crop을 위해 DB 컬럼, 객체 저장소 버킷, RunPod Network Volume을 새로 만들지
않는다.

5. crop 조회는 현재 revision의 `PICTURE` block만 허용한다.

## 6. Backend 배포

### 6.1 의존성

다음 의존성이 추가됐다.

```text
PyMuPDF>=1.26,<2.0
```

Backend image를 다시 빌드하거나 운영 가상환경에서 `requirements/production.txt`를 다시
설치해야 한다. `requirements/production.txt`는 `base.txt`를 포함하므로 별도 파일 수정은
필요 없다.

### 6.2 환경변수

| 변수 | 필수 여부 | 값과 의미 |
|---|---|---|
| `PUBLIC_BACKEND_BASE_URL` | 이미지 도구 사용 시 필수 | 외부 OpenAI/Anthropic 서버가 접근 가능한 Backend HTTPS 주소 |
| `DOCUMENT_PICTURE_CROP_TOKEN_MAX_AGE_SECONDS` | 선택 | crop URL 유효시간, 기본 `900`초 |

`PUBLIC_BACKEND_BASE_URL`이 HTTPS가 아니면 이미지 crop URL 생성을 명시적으로 실패시킨다.
`localhost`, 사설 IP, 내부 Docker service name은 외부 모델이 접근할 수 없으므로 사용할 수
없다.

### 6.3 Backend 확인

- Backend 기동 시 PyMuPDF import 오류가 없어야 한다.
- 기존 문서 검색 API와 에이전트 API가 정상 응답해야 한다.
- 서명이 없거나 변조된 crop URL은 `403`이어야 한다.
- 삭제 문서, 과거 revision, 존재하지 않는 picture block은 `404`여야 한다.
- 정상 서명 URL은 `image/png`를 반환해야 한다.

## 7. Frontend 배포

프런트를 프로덕션 설정으로 다시 빌드하고 기존 정적 파일 배포 절차를 수행한다.

```powershell

```

확인할 화면은 다음 두 곳이다.

1. 운영자 커스텀 모델 등록 화면
   - `이미지 입력 지원` 체크 항목 표시
   - 등록 후 목록에 지원 여부 표시
2. 에이전트 편집 화면
   - 모델 이름에 `이미지` 표시
   - 텍스트 모델에서는 `문서 검색 · 원본 이미지` 비활성화
   - 이미지 모델에서는 해당 도구 선택 가능
   - 이미지 도구 선택 후 텍스트 모델로 변경하면 도구가 제거됨

## 8. RunPod 영향

이번 커밋은 기존 파싱 Worker가 이미 저장하는 다음 값만 사용한다.

- 이미지 description 청크
- `PICTURE` block
- source ref
- page
- `src_locator.prov[].bbox`
- revision

따라서 이번 이미지 역추적 기능만을 위해 RunPod Worker 저장소를 다시 수정하거나
Serverless Endpoint·Template을 변경할 필요는 없다. 단, 최종 파싱 Worker 자체가 아직
운영에 배포되지 않았다면 description-only 이미지 청크와 bbox가 생성되도록 기존 파싱
Worker 배포를 먼저 완료해야 한다.

## 10. 배포 후 E2E

### 텍스트 모델

1. 텍스트 전용 커스텀 모델을 등록한다.
2. 에이전트 편집 화면에서 이미지 검색 도구가 비활성화되는지 확인한다.
3. API로 이미지 도구를 강제 지정했을 때 저장이 거부되는지 확인한다.
4. 일반 `document_search`로 이미지 description 근거가 텍스트로 검색되는지 확인한다.

### 이미지 입력 모델

1. 이미지가 있는 PDF를 최종 파싱 Worker로 색인한다.
2. 이미지 입력 지원 모델에 `document_search_with_images`를 연결한다.
3. 이미지 내용과 관련된 질문을 한다.
4. 상위 검색 결과에 해당 이미지 description이 포함되는지 확인한다.
5. 모델 입력에 PNG URL이 전달되는지 확인한다.
6. crop 이미지가 원본 문서의 제목·페이지·bbox와 일치하는지 확인한다.
7. 답변이 description만 반복하지 않고 실제 crop의 시각 정보를 활용하는지 확인한다.
8. URL을 변조하거나 유효시간 이후 다시 열었을 때 접근이 거부되는지 확인한다.

## 11. 장애 확인표

| 증상 | 우선 확인 |
|---|---|
| `PyMuPDF`/`fitz` import 오류 | Backend image가 새 requirements로 다시 빌드됐는지 |
| 이미지 도구 실행 시 HTTPS 설정 오류 | `PUBLIC_BACKEND_BASE_URL` 값 |
| 외부 모델이 이미지를 읽지 못함 | 공개 DNS, TLS 인증서, 방화벽, URL 만료 여부 |
| crop API `404` | 현재 revision, block type, storage key, 원본 PDF 존재 여부 |
| 엉뚱한 영역 crop | `coord_origin`, page 번호, bbox 값, PDF 페이지 크기 |
| 이미지 도구가 화면에서 비활성 | 선택 모델의 capability 또는 커스텀 모델 체크값 |
| 기존 커스텀 VLM이 텍스트로 표시 | 기존 payload에는 capability가 없으므로 모델 재등록 필요 |
| 이미지 설명은 검색되지만 이미지가 없음 | top-k 결과가 PICTURE인지, 원본 MIME이 PDF인지 |

## 12. 롤백

문제가 이미지 검색 기능에 한정되면 먼저 에이전트 정의에서
`document_search_with_images`를 제거하고 기존 `document_search`만 사용한다. 이 조치는
DB 변경 없이 즉시 가능하며 기존 텍스트 검색을 유지한다.

코드 롤백이 필요한 경우 `44b34a9`을 되돌린 Backend·Frontend image를 배포한다. DB
migration이 없고 crop 이미지를 영구 저장하지 않으므로 별도 DB rollback과 데이터 정리는
필요 없다. PyMuPDF가 남아 있어도 기존 기능에는 영향을 주지 않는다.
