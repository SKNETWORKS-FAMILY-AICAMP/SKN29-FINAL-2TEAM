현재 revision, 삭제·접근 철회 차단 조건을 그대로 유지한다.

## 2. 최종 동작 계약

### 2.1 이미지 description의 역할

PICTURE의 승인된 VLM description 또는 기본 Picture serializer fallback은 다음에만
사용한다.

- `chunk.search_text` 저장
- embedding 생성
- FTS·trigram·exact match 검색
- 하이브리드 검색 순위 계산

PICTURE의 검색 문장은 모델의 텍스트 evidence로 반환하지 않는다. 이미지 입력 지원
모델에는 description을 다시 보여 주는 대신 원본 PDF bbox Crop PNG를 전달한다.

### 2.2 도구별 동작

| 도구 | 동작 |
|---|---|
| `document_search` | 일반 본문 근거만 텍스트로 반환한다. PICTURE description은 순위 계산에만 사용한다. |
| `document_search_with_images` | 같은 하이브리드 검색을 사용하고 상위 PICTURE를 원본 PDF Crop으로 첨부한다. |

두 도구 모두 모델 입력은 `query` 하나다. 결과 개수는 모델이 바꾸지 못하며 서버에서
하이브리드 상위 20개로 고정한다.

이미지는 다음 정책을 적용한다.

- `block_id` 기준 중복 제거
- 검색 순위가 높은 순서 유지
- 한 번의 도구 호출에서 최대 5개
- PDF 원본만 Crop
- 이미지 URL·문서명·페이지·점수만 모델에 전달
- bbox와 전체 vector metadata는 모델에 전달하지 않음

### 2.3 원본 Crop 역추적

```text
hybrid search hit
→ chunk.block_id
→ doc_id + current revision
→ doc.storage_key
→ doc_block.src_locator.prov[].page_no + bbox
→ 원본 PDF 동적 Crop
→ 단기 서명 HTTPS URL
→ LangChain image content block
```

문서명이나 페이지만으로 원본을 찾지 않는다. 서명에 포함된 `block_id + doc_id +
revision`이 현재 문서의 `PICTURE` block과 모두 일치해야 한다.

## 3. Description 검증 탈락 fallback

검증을 통과한 Picture는 기존과 같이 승인된 `meta.description.text`만 청크에 사용한다.
caption, classification, 다른 meta, heading, 인접 본문은 이 청크에 섞지 않는다.

description이 없거나 품질 검증에서 탈락한 Picture는 Docling 기본 Picture serializer와
기본 meta serializer를 사용한다. 따라서 caption 또는 기본 annotation이 있으면 검색용
fallback 청크로 남고, 해당 `#/pictures/N` source ref와 page/bbox도 유지된다.

Picture 청크는 description/fallback 여부와 관계없이 merge 경계다. `merge_peers=true`여도
인접 본문과 합치지 않는다.

주의: description도 없고 기본 serializer가 만들 caption·annotation도 없는 Picture는
질의와 연결할 텍스트가 없으므로 검색 청크가 생성되지 않을 수 있다. 임의의 가짜 설명을
만들지는 않는다.

## 4. 검색 SQL 계약

`VectorSearchRepository.search_hybrid()`는 다음 점수를 유지한다.

```text
final = vector 0.50 + lexical 0.50
lexical = FTS 0.55 + trigram 0.25 + exact 0.20
```

PICTURE도 `c.search_text`로 후보 생성과 점수 계산을 하지만 최종 텍스트 필드는 `NULL`로
반환한다. Crop 생성에 필요한 다음 식별자만 검색 결과에 추가한다.

- `file_name`
- `mime_type`
- `block_id`
- `block_type`
- `page`
- `revision`

`picture_crop_source()`는 current revision, `PICTURE`, 미삭제, 접근 미철회, storage key
존재 조건을 다시 검사한다.

## 6. 설정과 배포

### Backend 환경변수

| 변수 | 필수 | 설명 |
|---|---|---|
| `PUBLIC_BACKEND_BASE_URL` | 이미지 도구 사용 시 필수 | 외부 모델이 접근할 수 있는 공개 HTTPS Backend 주소 |
| `DOCUMENT_PICTURE_CROP_TOKEN_MAX_AGE_SECONDS` | 선택 | Crop URL 유효시간, 기본 900초 |

`PUBLIC_BACKEND_BASE_URL`은 `https://`로 시작해야 한다. localhost, 사설 IP, Docker
내부 서비스명은 외부 OpenAI·Anthropic 서버가 접근할 수 없다.

### 배포 순서

1. 최신 main의 하이브리드 검색 인덱스 migration 적용 여부를 확인한다.
2. PyMuPDF가 포함되도록 Backend image를 다시 빌드한다.
3. Backend를 배포하고 공개 HTTPS URL을 확인한다.
4. Frontend를 다시 빌드·배포한다.
5. 최신 Worker image가 RunPod Endpoint에 연결됐는지 확인한다.
6. 실제 PDF로 검색→Crop→VLM 답변 E2E를 수행한다.

이미지 기능 자체의 신규 DB migration은 없다. 다만 최신 하이브리드 검색은
`2026-08-28_document_search_hybrid_indexes.sql`의 FTS·trigram 인덱스를 전제로 한다.

완료한 로컬 검증:

- 변경 Python 파일 compile 검사 통과
- Picture serializer 테스트 6개 통과
- 승인 description의 caption 누출 방지 확인

- `git diff --check` 통과

현재 로컬 Python 환경에는 `psycopg_pool`, `botocore`가 없어 Django 전체 테스트 runner는
URL check 단계에서 시작하지 못했다. 코드 실패가 아니라 개발 환경 의존성 누락이다.

프로덕션 Frontend build는 pnpm 보안 정책이 `esbuild` 설치 스크립트를 차단해 이 PC에서
완료하지 못했다. TypeScript 컴파일은 통과했다. CI 또는 정상 의존성 환경에서 다음을
반드시 실행한다.

```powershell
python manage.py test `
  tests.test_document_search `
  tests.test_document_pipeline `
  tests.test_tool_loader `

Set-Location frontend
pnpm install --frozen-lockfile
```

## 8. 운영 E2E 체크리스트

### 텍스트 모델

- [ ] 이미지 도구가 선택 불가능하다.
- [ ] API로 강제 저장해도 거부된다.
- [ ] 일반 본문 검색은 기존과 동일하다.
- [ ] PICTURE description이 답변 텍스트 근거로 노출되지 않는다.

### 이미지 모델

- [ ] `document_search_with_images`를 선택할 수 있다.
- [ ] 이미지 관련 질의가 PICTURE 청크를 하이브리드 검색으로 찾는다.
- [ ] 모델 텍스트 evidence에 description이 포함되지 않는다.
- [ ] 실제 PNG content block이 모델에 전달된다.
- [ ] 문서·페이지·bbox가 원본과 일치한다.
- [ ] 동일 `block_id`가 중복 첨부되지 않는다.
- [ ] 이미지가 최대 5개로 제한된다.
- [ ] 변조·만료 URL은 403이다.
- [ ] 과거 revision·삭제·비PDF 원본은 404다.

### Description fallback

- [ ] 승인 description은 description-only 청크다.
- [ ] 검증 탈락 Picture의 caption/meta fallback이 검색된다.
- [ ] Picture fallback이 인접 본문과 merge되지 않는다.
- [ ] fallback 청크의 source ref와 Crop bbox가 같은 Picture를 가리킨다.

## 9. 롤백

문제가 이미지 응답에만 있으면 에이전트에서 `document_search_with_images`를 제거하고
기존 `document_search`만 사용한다. DB rollback은 필요 없다.

코드 롤백 시 이 기능 커밋을 되돌린 Backend·Frontend를 배포한다. Crop PNG는 영구
저장하지 않으므로 별도 데이터 정리는 필요 없다.
