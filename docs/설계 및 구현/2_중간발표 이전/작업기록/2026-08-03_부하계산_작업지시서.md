## A. 검증된 실측값 — 그대로 써도 된다

2026-08-03에 `DB/peopleDB/peopledb_mock.sql`과 `DB/schema.sql`을 직접 읽어 확인했다. 다시 조사하지 말 것.

### A-1. `wk_hours`에는 이미 FTE가 반영돼 있다

```
시드 실측: ('W005','PB003', wk_hours 20.00, def_wk_hours 40.00, fte 0.50)
```

`wk_hours = def_wk_hours × fte`가 이미 성립한다. **여기에 FTE를 다시 곱하면 안 된다.**

```
잘못:  COALESCE(wk_hours, def_wk_hours, 40) * COALESCE(fte, 1)   → 20 × 0.5 = 10시간
올바름: wk_hours 우선 → 없으면 def_wk_hours × fte → 둘 다 없으면 BLOCKED
```

해당자 7명: `PB003` `PF004` `PN001` `PN004` `PQ004` `PQ006` `PQ008` (전원 20/40/0.50).
개발팀 5명은 전원 40/40/1.00이라 **화면에는 안 드러난다.** 조용히 틀리는 버그다.

### A-2. 개발팀 5명 = 4주 160시간, 부재 0건

`PX002` `PB001` `PB002` `PF001` `PF002` 전원 `wk_hours 40.00 / def_wk_hours 40.00 / fte 1.00`, `absence` 행 없음.

```
EffectiveCapacity = (40 ÷ 5) × 20근무일 − 0 − 0 = 160시간
```

## C. 이 저장소의 함정 — 코드를 고치기 전에

1. **Django ORM·Migration을 쓰지 않는다.** `config/settings/base.py`에 `DATABASES = {}`. 데이터 접근은 전부 `backend/db/repositories.py`의 psycopg3 직접 SQL. `apps/*/models.py`는 빈 파일이다
2. **스키마는 수동 관리다.** `DB/schema.sql` 수정 + `DB/migrations/`에 파일 추가 + `docs/설계 및 구현/3_중간발표 이후/개발환경/DB_시작_가이드.md` §4.3에 `ALTER` 블록 추가 — **세 곳 전부.** §4.3이 팀원 4명에게 전달되는 유일한 경로다
3. **CRLF로 diff가 오염돼 있다.** `git status`는 237개 파일이 바뀐 것처럼 보인다. `git diff --ignore-all-space`로 볼 것. **`git add .` 금지** — 저장소 전체 개행 churn이 커밋된다. 바꾼 파일만 명시적으로 add
4. **테스트는 DB를 띄우지 않는다.** `django.test.SimpleTestCase` + mock. 현재 **289개**(`def test_` 기준, 2026-08-05) 전부 통과 상태를 유지할 것
5. `next_short_code(cursor, *, table, column, prefix)`의 **`prefix`는 영문 2글자 필수.** 사용 중: `CN DC MI NT PJ PM PS RN TE TM UA UL` → `exist_task`에는 **`ET`**를 쓴다

## 1. `status_category` ALTER — 10분

Jira 상태 표시 문자열은 조직마다 다르다(`'진행 중'` `'In Progress'` `'Doing'`). 한글 문자열을 코드에 박지 않기 위해 표준 카테고리를 별도 컬럼에 저장한다.

### 수정할 파일 3곳

**`DB/schema.sql`** — `exist_task` 정의에 컬럼 추가. `status` 바로 아래에 두고 주석을 남긴다

```sql
    status                VARCHAR(20),   -- Jira 표시 문자열(프로젝트마다 다름). 로직에 쓰지 말 것
    -- Jira 표준 상태 카테고리(2026-08-03 추가). 로직은 이 값만 본다.
    -- 같은 카테고리인데 KAN은 '해야 할 일', AIP는 '할 일'로 표시된다(0-2 실측).
    -- statusCategory.name도 지역화되므로 안전한 값은 key 하나뿐이다.
    -- 'TO_DO' | 'IN_PROGRESS' | 'DONE'  ← 수집 단계에서 아래 표로 변환해 넣는다

```

### Jira key → 저장값 매핑

Jira가 주는 `statusCategory.key`를 그대로 저장하지 않고 우리 어휘로 바꿔 넣는다. `indeterminate`가 SQL에 그대로 박히면 읽히지 않고, 나중에 다른 트래커를 붙일 때 경계가 된다. **변환은 수집 코드 한 곳에서만 한다.**

③ 할당 = Σ remaining
         where assignee_person_id = 대상자

           and remaining IS NOT NULL
           and (due_at < 창끝 OR status_category = 'IN_PROGRESS')
