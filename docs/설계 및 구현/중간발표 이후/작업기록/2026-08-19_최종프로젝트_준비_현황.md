## 결론

**하나가 비어 있다.** 필수 3항목 중 Multi-Agent 의 병렬 실행 · Aggregation ·
Verification 이 미구현이다. 대체 논리가 통하지 않는 자리다.

**저비용 두 건이 남아 있다.** 벡터 인덱스와 Hybrid Search. 둘 다 권장 항목을
채우면서 실제 성능도 오른다.

**발표물이 미착수다.** 발표자료 40페이지, 결과보고서 PPTX, 시연 동영상.

**산출물 3건은 발표에서 뺀다.** 자체 sLLM · ML/DL 학습 · GraphDB 는 시스템에
붙지 않는다(§4).

**마감은 9월 1일 전후다.** 8/19 기준 약 2주.

## 3. 판정 근거

적용으로 판정한 항목은 근거를 생략했다. **부분·없음·미배선만 적는다.**

### MCP — 부분

- 클라이언트를 직접 구현했다. `services/mcp/client.py` — JSON-RPC 2.0 over HTTP,
  `initialize` · `tools/list` · `tools/call`. 공식 SDK 미사용 이유는 파일 머리에
  기록돼 있다.
- 운영자 콘솔에서 등록·연결확인이 동작한다. `apps/ops/views/mcp.py`, `/ops/mcp`.
- 실서버 대상 검증용 서버가 있다. `infra/dev-mcp/server.py`.
- **내장 도구 13종은 in-process 레지스트리다.** `services/harness/registry.py`.

### Multi-Agent Orchestration — 부분

- 위임은 동작한다. `agent:*` 도구, `MAX_AGENT_DEPTH = 2` (`registry.py:1159`),
  `services/agent_runtime/subagents/`.
- 승인 게이트가 두 층을 함께 멈추고 한 번의 승인으로 재개한다.
- **병렬 실행 0건.** `asyncio.gather` · `ThreadPool` · `concurrent.futures` 가
  `services/` · `apps/` 전체에 없다.
- **코드화된 Aggregation 이 없다.** 부모 모델이 도구 결과로 읽는 것이 전부다.
- **Verification · 재시도 루프 0건.**

### Neo4j / Graph DB — 없음

- `neo4j` · `cypher` 0건.
- 대체 근거 문서 2종을 보유한다. `설계 및 구현/중간발표 이전/참고자료/pgvector선택_이유.md`,
  `산출물/벡터DB_GraphDB_구축_결과서_2Team.docx`.
- 대체 구성: 별도 Vector DB 없이 PostgreSQL 17 + pgvector 단일 인스턴스의
  `VEC_IDX` 테이블. 근거는 `VectorDB_저장대상_검증.md` 7~8장,
  구현은 `backend/services/createDB/vec_idx_setup.py`.

### Hybrid Search — 없음

- 순수 벡터 검색뿐이다. `backend/db/document_pipeline.py:610`, `:777` —
  `ORDER BY v.embedding <=> %s::vector`.
- tsvector 전문 인덱스는 설계 문서(`12_문서처리_방식_비교 §5`)와 주석에만 있다.
- **추출 원문이 이미 저장돼 있어 착수 비용이 낮다.**

### 모니터링 · 관측성 — 부분

- 자체 구현으로 실행 이력을 적재한다. `agent_run` · `tool_call` · `audit_log` ·

- **회전 수·토큰은 2026-08-21 에 채웠다.** 그전까지 새 엔진은 `iterations=0` ·

## 5. 중간평가 피드백 반영 여부 (시트 2)

시트 2 의 2팀 행은 **6~9행**이다. 미작성 칸은 **`H6:I9`** —
`H` 열이 「반영 여부」, `I` 열이 「비고(미반영 시 사유)」다.

| 셀 | 항목 | 반영 여부 |
|---|---|---|
| H6 | ① 대표 Use Case · 단일 사용자 흐름 | 반영 |
| H7 | ② 복합 문서 구조·관계 보존 + Frontend | 반영 |
| H8 | ③ VLM · Graph · 조직 데이터 · 정량평가 | **부분 반영** |
| H9 | ④ HITL · 권한 · PM 업무 흐름 | 반영 |

### ① 대표 Use Case · 단일 흐름 — 반영

문서 등록 → 기준 문서 지정 → 업무 추출 → 승인·수정 → 등록 → 근거 확인이
배포본에서 끝까지 동작한다. `QA_체크리스트_브라우저.md` §B-0 으로 확인했다.

> **단서.** 통합 도출 문구는 「대표 Use Case 를 정의하고 하나의 흐름으로 완성」
> 이므로 반영으로 판정했다. 다만 개별 의견(황용철 3번)은 「Use Case 를 **하나로
> 좁혀라**」였는데, 8/8 피벗으로 제품 범위는 Agent Platform 으로 넓어졌다.
> 발표에서는 대표 Use Case 를 「PM 의 문서 → 업무 추출·배분」으로 명시해 좁혀
> 제시하는 편이 안전하다.

### ② 복합 문서 구조·관계 보존 + Frontend — 반영

`runpod_worker/pipeline.py` 의 docling 파이프라인이 담당한다.

```python
do_picture_classification=True      # Transformers 이미지 분류
do_picture_description=True         # 이미지 설명 VLM
do_chart_extraction=True            # Granite Vision 차트 모델
heading_hierarchy_options=...       # 제목 계층
generate_parsed_pages=True          # 실측 글자 높이로 제목 깊이 보정
ocr_options=EasyOcrOptions(lang=["ko","en"], mode=OcrMode.LAYOUT_REGIONS)
```

- 표는 `_table_ref` · `_table_pages` 가 `self_ref` 기반으로 참조를 보존한다.
