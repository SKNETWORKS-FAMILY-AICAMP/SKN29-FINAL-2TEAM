# Architecture 초안

> 작성 중. 08/12 온라인 멘토링 리뷰 대상.

## 레이어

- **Data Layer** — 기존 파싱·청킹·임베딩·Vector DB (RunPod Serverless + Django 적재). 폐기 아님, Agent가 비정형 데이터를 쓰는 기반
- **Connector** — 데이터 수집·검색 통로 (Drive·Jira·HR Mock). 개수 확장 중단, 1개 이상 완전 E2E: Connection→Fetch→Parse→Chunk→Retrieve→Agent
- **Agent Harness** — Agent Loop / Tool Execution / Context 관리 / Sub-Agent 여지 / Permission / Observability
- **MCP** — Agent가 외부 시스템에 행동하는 Tool 인터페이스. 설정에서 Server 등록 → Builder에서 Agent에 연결 → Runtime 호출. Jira = 대표 Action 시나리오
- **Pre-built Agent** — 기존 업무 추출(5단계 멀티 에이전트)·업무 분배를 플랫폼 기본 Agent로 재구성

## 문서 처리 방식 (추가 설계 필요)

전체 사전 업로드→Vector DB가 아니라: Metadata 확인 → 요청 시 관련 파일 검색 → 필요한 파일만 Parsing/Chunking → Agent Context 제공. 미확정.
