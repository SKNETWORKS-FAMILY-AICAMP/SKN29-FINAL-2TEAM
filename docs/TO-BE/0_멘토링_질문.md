## 핵심 3 — 범위를 가르는 질문 (여기서 시간의 절반)

**Q1. [결정 보고] Harness = 직접 구현 + 구조 차용 — 검증 요청** [아키 §3.1·§6]
세 분석(OpenCode·Deep Agents·Claw Code)이 전부 같은 결론으로 수렴해 8/11
팀 회의에서 확정했다. 전제: 기존 orchestration은 12줄 스텁이라 어차피 신규
작성(재사용은 NDJSON 규약·이벤트 타입·실행 레코드 3종). 차용 구조:
Session/Run 분리·선기록 trace·스캐폴드+instruction·상한 2겹(기본 10)·
Registry·Loop 순수 함수화. 함께 확정: 에이전트 선택은 수동 선택기(자동
라우팅은 Future). **멘토님께**: 이 결정이 3주 일정·학습 목표 관점에서 타당한지,
빠진 위험 요소가 있는지 검증 요청.

**Q2. 업무 분배(STEP 5)를 v1 데모에서 제외** [E2E §4-1]
분배 로직은 중간발표 시점 미완(화면만 존재). 제안: E2E는 "추출→확인→Jira
등록"으로 확정하고 분배는 Future Work. 빼도 Connector·문서처리·Agent·MCP·Tool
Calling을 전부 시연할 수 있다.

**Q3. [결정 보고] 문서 처리 = 2단계 검색(A안) + 요약 품질 검증 게이트** [아키 §5, 12_문서처리]
8/11 확정: 폴더 지정 시 메타+요약 임베딩만 자동 등록(CPU 저비용), 사용 시 후보
문서만 온디맨드 풀 처리(캐시 유지) 후 청크 검색. 팀 반론("긴 문서는 요약으로
못 찾는다")을 반영해 **요약 품질을 문서 단위 Recall로 실측 검증하고, 미달 시
추출 원문의 전문 검색(tsvector) 하이브리드로 확장**하는 예비안까지 준비됨
(업계 조사: 전량 인덱싱·요약 계층·무인덱스 3갈래 실존). 콜드 스타트는 인프라
과제로 분리. **멘토님께**: 이 단계적 접근(A → 검증 → A′)이 타당한지 확인 요청.

**Q5. [결정 보고] 추출 결과 = chat_message 1차 + Jira 성공분만 task** [아키 §3.1-④, E2E §2-3]

**Q6. Jira 생성 단위** [E2E §4-2]

권한·정리 부담은 후자가 작다. 제안: 데모는 Project 생성까지, 실사용 기본값은
Issue 추가.

**Q7. [설계 반영됨] 확인 스텝 UX** [E2E §4-3]

미결은 「다시 정리해줘」 재실행 버튼뿐(Q15에 포함).

**Q15.** Figma 화면이 문서보다 앞서간 3건 일괄 확정 [9_Figma_검증 D] — 기본 에이전트 「복제」 / 공개 범위 「나만 보기」 / 확인 카드 「다시 정리해줘」 재실행. 셋 다 화면은 좋지만 구현 범위가 늘어난다 — Figma에 빨간 「멘토링 확정 필요」 주석으로 마킹되어 있음.
**Q16. [결정 보고+새 질문] Jira는 내장 tool(C안), MCP는 확장 경로 — 그리고 MCP OAuth** [개발지시_1차 단계 6]
구현 중 발견으로 방향 변경(8/11 팀 결정): 자체 Jira MCP 서버(B안)는 우리 SSRF
차단이 localhost·사설 대역을 막아 자기모순(시연하려는 방어를 시연 중에 꺼야
함), 공식 Atlassian MCP는 OAuth 액세스 토큰 요구(실측 401, 만료 약 1시간).
그래서 **Jira 등록·조회는 내장 tool**(기존 Connector OAuth 재사용, 부분 실패
그대로 반환), **MCP는 사용자가 자기 서버를 붙이는 확장 경로**로 유지(등록·
discovery·SSRF·Registry 통합은 완성). **멘토님께 새 질문**: 정적 토큰만 받는
현재 모델로 "사용자가 자기 MCP를 붙인다"가 성립하는가(호스팅형 MCP는 대개
OAuth) — MCP용 OAuth 지원을 v1에 넣을지, Future로 미룰지.
