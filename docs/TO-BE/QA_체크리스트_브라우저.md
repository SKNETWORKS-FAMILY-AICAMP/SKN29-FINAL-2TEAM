#### 처음 밟았을 때 실패한 것 (그 자리에서 고치고 재현으로 확인)

① **승인이 통째로 실패했다** — `error · InvalidDatetimeFormat`. 문서에는 절대
날짜가 잘 없어서 「조치내역 확인 요청 후 5일 이내」 같은 상대 표현이 뽑히는데,
그게 `timestamptz` 컬럼까지 그대로 내려갔다. 한 트랜잭션이라 **승인한 18건이
전부 롤백**됐다. → 못 읽는 날짜는 비우고 `dropped_dates` 로 사람에게 알린다.

② **창 전체가 스크롤됐다** — 체크박스 `.root` 에 `position: relative` 가 없어
숨김용 `<input>`(absolute)의 기준이 문서로 올라갔다. 승인 카드처럼 체크박스가
20개 깔리면 문서 높이가 **855 → 2977px** 로 밀려 셸까지 스크롤됐다.

#### 이어서 화면을 밟다 나온 것 (같은 날 전부 고침)

③ **진행 카드가 끝나도 회전했다** — `running` 과 무관하게 「실행 중」을 그렸다.
승인 카드가 떠 있는데 머리가 돌면 눌러도 되는지 알 수 없다.

④ **무관한 문서가 유일 후보로 올라왔다** — 컷이 「1등 대비 비율」이라 후보가
하나면 자기 자신이 기준이 돼 **21% 여도 통과**했다. 그 문서로 뽑은 감리 업무
7건이 실제로 등록됐다. → 요약·파일명이 **둘 다** 바닥일 때만 자른다.

⑤ **등록한 업무를 화면에서 볼 수 없었다** — 프로젝트 상세가 `exist_task`(Jira)
만 읽고 `task` 를 읽는 곳이 **화면에 하나도 없었다.** → 「추출된 업무」 별도
섹션. 진행률·담당자별 배분과는 섞지 않는다(`PROPOSED` 라서).

⑥ **대화 제목이 전부 첫 발화였다** — 「업무 뽑기」는 늘 같은 문장을 보내서
대화 둘이 글자까지 같았다. → 첫 답이 끝난 뒤 모델이 한 번만 짓는다.

⑦ **「문서 목록」 도구는 한 번도 동작한 적이 없었다** — `list_with_meta` 를
`DocMetaRepository` 가 아니라 `PipelineDocumentRepository` 로 불러 늘
`AttributeError` 였다. 도구가 13종이라 다 눌러 보지 않으면 안 드러난다.
→ 저장소 호출이 실재하는지 **이름만으로 검사하는 테스트**를 붙였다.

그 밖에 고친 것: **기준 문서 해제**가 없어 잘못 고른 문서를 되돌릴 수 없었다.
**모델이 모르는 공수를 `0` 으로 채워** 저장됐다(0 시간짜리 업무는 없다).

#### 아직 남은 것 (버그 아님 · 다음에 볼 것)

### B-2. 다중 턴 (`5eea00c` — 이번에 처음 확인 가능해진 것)

> 그전에는 **두 번째 발화가 첫 턴을 덮어썼다.** B를 그 상태로 돌렸다면
> 아래를 전부 놓쳤을 자리다.

- [ ] 한 대화에서 발화 **3번** → 3턴이 모두 화면에 남는가 (앞 턴이 사라지지 않는가)
- [ ] **새로고침** → 3턴이 **전부** 복원되는가 (마지막 답 하나만 남지 않는가)
- [ ] 특히 **확인 카드 + 승인 결과가 한 턴 안에** 복원되는가 — 승인은 실행이
      두 번이라 여기서 어긋나면 `ChatPage`의 `toTurns`를 본다
- [ ] 확인 카드가 뜬 상태에서 **입력창에 타이핑·전송이 되는가**
      (「3번은 빼고 다시 뽑아줘」) → 새 턴이 시작되고, **직전 턴 카드에
      「승인하지 않고 넘어갔습니다」**가 붙는가
- [ ] 과거 턴의 「Jira에 등록」 버튼이 **눌리지 않는가** (비활성)
- [ ] 답이 길어질 때 화면이 아래로 따라가는가 / **위로 올려 읽는 중에는
      끌려 내려가지 않는가**
- [ ] ⚠ 알려진 한계 — 과거 턴의 **체크 상태는 복원되지 않는다**(전체 선택으로
      보인다). 서버에 저장되는 곳이 없어서다. 실제 등록분은 결과 카드가 정본.
      **버그 보고 대상이 아니다**
