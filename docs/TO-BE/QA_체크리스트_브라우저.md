# 브라우저 QA 체크리스트 — 3차 실연동 확인 (준님 실행용)

> 목적: 개발 세션이 못 한 **브라우저 클릭 확인**을 사람이 대신한다.
> 이 문서의 A~C가 전부 통과하면 = **4차(G3 전환) 착수 게이트 열림.**
> 기준: E2E 9단계(`5_E2E_시나리오.md` §1) + 3차 지시서 §1·§6.
> 환경: 컨테이너 3종 기동 후 `localhost:5173`. 문제 발견 시 화면·콘솔 캡처와
> 함께 Cowork 세션에 보고 — 재지시 여부를 판단한다.

> **5차까지 반영된 상태 기준으로 고쳤다 (8/11).** 온보딩 화면 2종·Jira 프로젝트
> 선택·옛 대시보드가 없어졌고, 연결이 전부 Settings > Connector로 왔다.
> 바뀐 항목은 A·C에 표시했다.

## 착수 전제 (8/11 추가)

- **3차 보완 지시 ①(프로젝트 선택기 연동)이 먼저다** — 그 전에는 새 대화에
  proj_id가 없어 업무 추출이 시작조차 안 된다. 우회로 기존 대화(「E2E 확인」
  등, proj_id=PJ004)에서 발화하면 B의 나머지는 검증 가능하지만, "새 대화 →"
  첫 줄은 보완 후에만 체크할 수 있다.
- **Drive 토큰 마지노선 8/13** — Google 앱이 테스트 상태면 refresh token 7일
  만료(8/06 연결). A 섹션은 그 전에. 401이 뜨면 재연결.

## 미리 알아둘 것 (버그 아님 — 이미 알고 있는 상태)

- **결과 카드의 Jira 등록 결과 칸이 비어 있음** — 백엔드 `jira_result` 구조화
  이벤트가 아직 없어서 의도적으로 비워 둔 것(지어내지 않기). 등록 결과는
  `result.text` 문장으로 확인.
- **문서 선택 카드 없음** — 서버가 내보내는 경로가 없어 삭제됨(3차 판단 기록).
- **미색인 문서** — 자동 온디맨드 처리 미구현. `not_indexed` 응답이 정상.
- ⚠ **Jira 등록 대상**: KAN(실팀 보드)·AIP·LEG는 전부 앱에 소스로 등록돼
  있어 등록하면 다음 동기화 때 대시보드·부하 숫자에 섞인다. **Jira에서 임시
  프로젝트를 새로 만들어 그 키로** 등록시킬 것(미등록 키도 도구가 그대로
  보낸다 — 대조 안 함).
- ⚠ **이슈 유형은 한국어** — 이 사이트의 유형은 작업·스토리·버그 등.
  보완 지시 ②(시드 재실행) 전이라면 발화에 "이슈 유형은 '작업'으로" 한 줄.
  거꾸로 **부분 실패 카드를 보고 싶으면 한 건만 'Task'로** 시키면 된다.
- ⚠ **(8/11) Jira를 다시 연결하면 접근 가능한 프로젝트가 전부 등록된다.**
  QA용 임시 Jira 프로젝트도 딸려 들어와 프로젝트 목록·부하 숫자에 섞인다.
  버그가 아니라 5차 단계 4의 결정이다. 빼려면 프로젝트 목록에서 지운다.
- **(8/11) 새 계정으로 가입하면 Chat이 비어 있다.** 팀이 없어 에이전트도 0건이고,
  Chat은 「에이전트로 이동」만 안내한다 — 실제로 해야 하는 일은 Settings >
  Connector에서 People DB를 연결(=팀 생성)하는 것이다. **알려진 구멍이다**
  (5차 결과 블록 참조). 새로 보고할 필요 없다.

## A. 커넥터부터 밟는 경로 (QA 방침 — 예시 데이터 없이 실제 흐름)

현재 데이터가 전부 정상 상태(3건 준비됨)라 실패 경로는 **만들어서** 본다:

- [ ] **(8/11 개정)** ~~온보딩 2스텝~~ **온보딩 화면은 없어졌다.** 대신:
      **새 이메일로 가입 → 바로 /chat 인가** → Settings > Connector에서
      People DB 연결(=팀 생성) 모달이 도는가. 단 **B·C는 반드시 기존 계정으로**
      (새 계정엔 팀·문서·커넥터 없음).
- [ ] **(8/11 신규)** Settings > Connector가 **서버 상태를 그대로 말하는가** —
      세 줄(People DB · Drive · Jira)의 칩이 실제 연결 상태이고, Drive는 읽는
      폴더 수, Jira는 프로젝트 수가 붙는가
- [ ] **(8/11 신규)** 「폴더 설정」 → **모달**이 열리고, 그 안에서 「+ 폴더 추가」가
      폴더 트리 모달을 한 겹 더 여는가 → 저장 후 폴더 수가 갱신되는가
- [ ] **(8/11 신규)** Drive 「다시 연결」 → Google 동의 → **`/settings/connectors`로
      돌아오는가**(옛 온보딩 경로가 아니라). Jira도 같은 확인 + 돌아온 뒤
      프로젝트가 자동 수집됐는가
- [ ] Settings > Connector — Drive 연결 상태 확인(만료면 재연결)
- [ ] 「다시 처리」: doc_meta 한 행 삭제 → 상태 칩 내려가고 버튼 등장 →
      눌러 복구(~7초, 되돌릴 수 있는 조작)
- [ ] 실패/미지원 정직 표기: 폴더에 `.zip` 하나 넣고 동기화 → 「미지원」 칩

## B. Chat E2E — 4차 게이트의 핵심 (1회 이상 끝까지, 보완 지시 ① 반영 후)

- [ ] 상단바에서 **프로젝트(PJ004) 선택** → 새 대화 → 에이전트 선택기에 시드
      에이전트(업무 추출·부하 리포트) 표시
      — **(8/11) 부하 리포트 에이전트는 5차 단계 1에서 처음 시드됐다**(AG003).
      그전에는 이 항목이 반드시 실패했을 자리다. 상단바 선택기는 공용 `Select`로
      바뀌었으니 **열림 상태 모양도 같이** 본다(5차 단계 2)
- [ ] **(8/11 신규)** 「우리 팀원 누구누구야?」 → **팀원 목록이 답으로** 오는가
      (문서 검색으로 새지 않는가). 이어서 「누가 React 할 줄 알아?」로 스킬까지
- [ ] 「전체(팀)」 상태로 추출 발화 → "프로젝트를 먼저 고르세요" 오류 카드
      (정직 오류 — 설계대로)
- [ ] "○○ 문서에서 업무 뽑아서 Jira 등록해줘" 입력
- [ ] 진행 카드: 파이프라인 단계가 순서대로 (Loop 회전과 도구 진행이 섞여
      1/4→1/5처럼 **튀지 않는가** — tool_ref 규칙 확인 포인트)
- [ ] 근거 카드: E번호·원문 발췌 토글, 근거 없는 필드는 「근거 없어 비움」
- [ ] 확인 카드: 일부만 체크 → 승인 → **체크한 것만** 등록되는가
- [ ] 결과 카드: 성공/부분 실패 표기("n/m 등록 — k건 실패" 형식)
- [ ] Jira에 실제로 그 이슈들이 생겼는가 (데모 프로젝트에서 확인)
- [ ] **새로고침** → 대화·카드가 그대로 복원되는가
- [ ] 오류 경로 1개: 스트림 중 중단(탭 이동·네트워크 차단 등) → 오류 카드,
      이전 카드 보존
