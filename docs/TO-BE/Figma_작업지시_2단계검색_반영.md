## 작업 1 — 문서 관리 프레임(59:1073) 재작업 ★ 메인

기존 "문서 관리 (TO-BE · Project 하위)" 프레임은 폐기 대상이다. 이유 두 가지:
① "선택 파일 등록" UI의 존재 이유가 사라짐 ② "이 프로젝트 문서만" 범위 축소가
테넌트 경계(문서=팀 소속)와 충돌 (`9_Figma_검증.md` v3).

새 프레임 스펙:

- **프레임명**: `문서 (TO-BE · 팀 범위) · /documents`
- **경로 가안**: 사이드바 「프로젝트」 영역 안의 "문서" 탭. Settings > Connector의
  폴더 설정에서도 링크. (경로 최종 확정은 PM — 프레임엔 가안으로 표기)
- **레이아웃** (위→아래):
  1. 헤더: 제목 "문서" + 부제 **"폴더의 새 파일은 자동으로 등록됩니다. 내용은
     에이전트가 실제로 사용할 때 읽어 준비하고, 한 번 준비된 문서는 다시 읽지
     않습니다."**
  2. 요약 스탯 4개: `등록 128건 · 준비됨 12건 · 처리 중 1건 · 실패 1건`
  3. 상태 필터 탭: 전체 / 준비됨 / 메타만 / 실패
  4. 목록 테이블 — 열: 파일명 / 폴더 / 수정일 / **요약(자동 생성 한 줄)** / 상태
  5. 삭제 파일 정리 섹션 (기존 기능 유지 — "Drive에서 사라진 문서 N건, 확인 후 정리")
- **상태 칩 4종** (카피 그대로 사용):
  - `준비됨` (success) — 툴팁 "근거로 사용할 수 있습니다"
  - `메타만` (neutral) — 툴팁 "에이전트가 사용할 때 자동으로 읽습니다"
  - `실패` (danger) + [다시 처리] 버튼 — 사유 표시 (예: "스캔본 — 텍스트 추출 실패")
  - `미지원 형식` (neutral·비활성) — hwp 등
- **없어지는 것**: 전체선택 체크박스, "선택 파일 등록" 버튼, "이 프로젝트 문서만"
  범위 문구
- **ANNOTATION**: `G2 · 8/11 결정 — 선택 등록 UI 제거, 2단계 검색 구조의 상태
  화면으로 재정의 (아키 §5). 문서 범위는 팀 전체.`
