## B. 수정 필요 (우선순위순)

**B1. 데모 수치·상태 불일치 — 확인 대기 프레임 (39:118)**
헤더는 "전체 선택 ✓ · 6건 선택됨 · 공수 184h"인데 실제 체크는 2건이고 버튼은
"선택한 2건 Jira에 등록". 셋 중 하나로 통일 필요. 또 "업무 6건"인데 카드는
3장뿐이고 "외 3건 보기" 류 표기가 없다. 다음 프레임(부분 실패)은 갑자기 20건
시나리오(17/20)로 점프 — **데모 스토리 수치를 한 벌로 통일**할 것 (제안: 확인
대기 20건 찾음 → 3건 해제 → "선택한 17건 등록" → 부분 실패 "15/17" 식으로
이어지거나, 6건 기준으로 전부 축소).

**B2. 내부 설계 용어가 사용자 카피로 누출**
- 입력창 placeholder "…· **v1은 체크박스 조정만 허용**" — 내부 범위 표기.
  사용자 문구는 "위 목록에서 등록할 업무를 선택해 주세요" 정도로
- Model 탭 "**P2 · 구조만 잡고 최소 구현**" 배지 — Figma 주석 레이어로 옮길 것
- 이런 범위 주석은 프레임 밖 annotation으로 분리 (구현 세션이 카피로 오해)

**B3. 모델 표기 정합성**
확인 대기 trace·Builder 기본값·Model 탭이 전부 `gpt-5-mini` 중심인데, AS-IS
실측은 검색어 luna(low)/정리 sol(xhigh) 분리다. 모델 라인업을 바꾸는 결정이면
2_아키텍처 §3에 반영하고, 아니면 카피를 luna/sol 기준으로 수정. Model 탭 "권장
용도"(luna=긴 문서, sol=검증)도 실제 용법(luna=검색어 생성, sol=근거 정리)과
어긋난다.

**B4. 빈 상태 프레임의 상태 혼합 (38:2)**
"빈 상태"인데 좌측 세션 3건 중 하나가 선택 하이라이트 — 선택된 세션이 있으면
메시지가 보여야 한다. 진짜 빈 상태(세션 0 또는 "새 대화" 미선택)로 정리.
Drive 미연결 배너도 세션 이력과 공존 중 — 배너는 "온보딩 미완 사용자" 변형
프레임으로 분리 권장.

**B5. 예시 발화 미통일**
빈 상태 카드 예시는 "…업무를 정리해줘"인데 E2E 데모 발화는 "…정리하고 **Jira

(7_홈화면 §2 빈 상태 항목의 의도).
