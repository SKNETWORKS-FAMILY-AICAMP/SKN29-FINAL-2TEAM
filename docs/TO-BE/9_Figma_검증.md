## A. 잘 반영된 것 (설계 문서와 일치 — 통과)

- **상태 5종 전부 프레임화** (빈/스트리밍/확인 대기/부분 실패/오류) — 7_홈화면 §3 그대로
- 근거 카드 완전 이식: E번호·doc_id·intent·유사도%·「어떤 질의로 찾음」·근거 토글·**「근거 없어 비움」**·검색 단계 trace — TaskCard 이식 스펙 전부 반영
- PARTIAL_RESULT 화면화: "17/20 등록 완료 — 3건 실패", 성공분 유지 명시, 실패 사유 구체화(필수 필드·429), **실패분만 재시도** — E2E §2 정확히 구현
- 확인 카드: 업무별 체크+전체 선택, "승인하기 전까지 Jira에는 아무것도 만들지 않습니다" 안전 문구
- 오류 상태: 이전 결과 보존 + `error · mcp_jira · 401 · run_id` — NDJSON 오류 규약 노출
- AppShell 사이드바 4항목 + 프로젝트 컨텍스트 선택기("전체(팀)") — Q4 제안 구현
- Settings 허브 탭 5종, MCP 탭 P0 요소(서버 등록 폼·tool 목록·연결 상태·"연결 나쁘면 편집 화면에서 선택 불가"), Connector/MCP 구분 설명문("읽는 연결 vs 행동하는 연결")
- Builder: 비개발자 3분할(Profile/행동 지시/데이터·도구), Description 호출 판단 안내, 지어내지 말라는 예시 지시문, 저장→Chat 즉시 노출

## B. 수정 필요 (우선순위순)

**B1. 데모 수치·상태 불일치 — 확인 대기 프레임 (39:118)**
헤더는 "전체 선택 ✓ · 6건 선택됨 · 공수 184h"인데 실제 체크는 2건이고 버튼은
"선택한 2건 Jira에 등록". 셋 중 하나로 통일 필요. 또 "업무 6건"인데 카드는
3장뿐이고 "외 3건 보기" 류 표기가 없다. 다음 프레임(부분 실패)은 갑자기 20건
시나리오(17/20)로 점프 — **데모 스토리 수치를 한 벌로 통일**할 것 (제안: 확인
대기 20건 찾음 → 3건 해제 → "선택한 17건 등록" → 부분 실패 "15/17" 식으로
이어지거나, 6건 기준으로 전부 축소).

**B2. 내부 설계 용어가 사용자 카피로 누출**
- 입력창 placeholder "…· **v1은 체크박스 조정만 허용**" — 내부 범위 표기.
  사용자 문구는 "위 목록에서 등록할 업무를 선택해 주세요" 정도로
- Model 탭 "**P2 · 구조만 잡고 최소 구현**" 배지 — Figma 주석 레이어로 옮길 것
- 이런 범위 주석은 프레임 밖 annotation으로 분리 (구현 세션이 카피로 오해)

**B3. 모델 표기 정합성**
확인 대기 trace·Builder 기본값·Model 탭이 전부 `gpt-5-mini` 중심인데, AS-IS
실측은 검색어 luna(low)/정리 sol(xhigh) 분리다. 모델 라인업을 바꾸는 결정이면
2_아키텍처 §3에 반영하고, 아니면 카피를 luna/sol 기준으로 수정. Model 탭 "권장
용도"(luna=긴 문서, sol=검증)도 실제 용법(luna=검색어 생성, sol=근거 정리)과
어긋난다.

**B4. 빈 상태 프레임의 상태 혼합 (38:2)**
"빈 상태"인데 좌측 세션 3건 중 하나가 선택 하이라이트 — 선택된 세션이 있으면
메시지가 보여야 한다. 진짜 빈 상태(세션 0 또는 "새 대화" 미선택)로 정리.
Drive 미연결 배너도 세션 이력과 공존 중 — 배너는 "온보딩 미완 사용자" 변형
프레임으로 분리 권장.

**B5. 예시 발화 미통일**
빈 상태 카드 예시는 "…업무를 정리해줘"인데 E2E 데모 발화는 "…정리하고 **Jira
프로젝트에 등록해줘**". 빈 상태에서 데모를 시작하려면 문구를 E2E 발화로 통일
(7_홈화면 §2 빈 상태 항목의 의도).

## C. 부족한 화면 (스펙에 있는데 미구성)

1. **성공 결과 카드 (E2E STEP 9 전부 성공)** — 부분 실패 프레임만 있다. 데모의
   메인 경로는 성공인데 그 화면이 없다. **최우선 추가** (이슈 링크 목록 + 업무별
   근거 반환).
2. **문서 선택 되묻기 카드 (STEP 2)** — 기준 문서 미지정 시 후보 제시
   (PrimaryDocumentSelectPage 흡수 대상, 8_명세 G3 삭제의 전제).
3. 부하 리포트 결과 카드 — 두 번째 기본 에이전트의 결과 화면 (Q13 확정 후여도
   되지만, 에이전트 카드가 빈 상태에 노출돼 있으니 결과 모습이 있어야 데모 완결).
4. Settings **Connector 탭** 프레임 (기존 재사용이라도 허브 안에서의 모습 1장),
   **권한 탭** placeholder 여부 결정.
5. 온보딩 개편 프레임 (Jira 스텝 분리 후 3스텝 흐름 — G2 작업 범위).

## D. 설계 문서와 상충 — 디자인이 앞서간 3건 (멘토링 전 팀 결정 필요)

| 화면 | 디자인 | 문서 | 처리 |
|---|---|---|---|
| 에이전트 목록 | 기본 제공에 **"복제"** 버튼 | 미결정 ③: v1은 고정 제안 | 채택 시 7_홈화면 §6-3 갱신+구현 범위 증가, 아니면 버튼 제거 |
| 에이전트 편집 | 공개 범위 **"나만 보기"** 옵션 | Q12 제안: v1 팀 공유 고정 | 채택 시 Permission 범위 증가 (agent 소유·가시성) |
| 확인 카드 | **"다시 정리해줘"** 재실행 버튼 | 미결정 ②: 체크박스만 허용 제안 | 전체 재실행 버튼은 허용 가능한 절충 — 채택하면 문서에 명시 |

셋 다 "화면은 좋은데 범위가 늘어나는" 종류다. 수요일 멘토링에서 범위 질문과
함께 확정하고, 확정 결과를 디자인·문서 양쪽에 반영할 것.

## E. 요약

10프레임 중 구조·철학(정직한 표기, 승인 게이트, 근거 우선)은 설계 문서를
충실히 구현했다. 고칠 것은 **수치 일관성(B1)과 카피 누출(B2)** 이 대부분이고,
**성공 결과 카드(C1)** 가 가장 큰 공백이다. 상충 3건(D)은 디자인 문제가 아니라
범위 결정 문제이므로 멘토링 안건에 얹는다.
