## 단계 1 — Chat 실연동 (데모 핵심)

`mockChat.ts` 제거. `ChatPage`가 실제 API를 탄다:

- 세션 목록/생성/삭제: `GET·POST /api/chat/sessions/`, `DELETE .../<id>/`
- 대화 복원: `GET .../<id>/` (새로고침 시 chat_message 카드 재렌더 — 백엔드
  E2E에서 23kB 카드 복원 확인됨)
- 스트리밍: `POST .../<id>/messages/` NDJSON 파싱 (fetch + ReadableStream)
- **이벤트 구별 규칙**: `tool_ref` 있으면 그 도구의 진행(파이프라인 n/5),
  없으면 Loop 회전 — 진행 카드가 1/4→1/5로 튀지 않게 (1차 단계 2 결과 참고)
- 확인 게이트: `awaiting_confirmation` 수신 → 확인 카드 → `POST .../confirm/`
  **body는 체크한 인덱스만** (인자를 보내지 않는다 — 게이트 계약)
- 오류: 스트림 중단 시 마지막 `error` 줄 → 오류 카드, 이전 카드 보존
- 빈 상태: 세션 0일 때 기본 에이전트 카드(agent API에서, 단계 2와 연동)

브라우저 확인: 새 대화 → "문서 정리하고 Jira 등록해줘" → 진행 카드 → 확인
카드 체크·승인 → 결과 카드 → 새로고침 후 복원까지 1회.
⚠ `jira_create_issues` 실호출이 아직 미검증 — **첫 승인 테스트는 데모용 Jira
프로젝트로** (실제 이슈가 생긴다).

**브라우저 클릭 확인을 못 했다.** 이 세션 환경에 브라우저를 띄워 조작할 수단이

### 판단해서 뺀 것

- **문서 선택 카드(Figma 47:654) 삭제.** 서버가 그 카드를 내보내는 경로가 없다 —
  기준 문서는 사람이 별도 화면에서 고른 것을 쓰고 `task_extraction` 은 문서 id 를
  받지 않는다. mock 을 걷으니 데이터 출처 없는 컴포넌트만 남았다. CSS 는 남겨
  뒀으니 되묻기 흐름이 백엔드에 생기면 복원하면 된다.
- **결과 카드의 Jira 등록 결과가 비어 있다.** 등록 결과가 `result.text` 문장으로만
  오고 구조화된 이벤트가 없다. 모르는 이슈 키를 지어내면 화면이 "등록됐다"는데
  Jira 에는 없는 상태가 된다. `liveChat.readJiraResult` 한 곳만 바꾸면 되게
  격리해 뒀고, **백엔드가 `jira_result` 이벤트를 내보내는 것이 선행**이다.
