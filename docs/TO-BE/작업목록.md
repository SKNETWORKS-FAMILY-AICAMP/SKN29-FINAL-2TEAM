## 2026-08-18 밤 — 운영자 콘솔을 「등록」과 「사용」으로 가른다

**두 번 고쳤다. 가운데 한 번은 내가 과하게 읽었다.**

**가르는 선은 「등록이냐 사용이냐」다.**

| 어디 | 무엇 |
|---|---|
| `/ops/models` | 모델 **등록** · 등록된 모델 목록 — 그 둘뿐이다 |
| `/ops/mcp` | 커스텀 도구 **등록** · 등록된 서버 목록 |
| `/ops/teams/<id>` | **사용 중 모델**(고르는 select) · **사용 중 커스텀 도구**(표) |

**등록과 사용은 다른 질문이다.** 등록은 「무엇을 새로 붙이나」라 주제로 시작하는
일이고, 팀 상세는 「이 팀이 지금 무엇을 쓰나」다. 등록을 팀 상세로 끌어오면
등록하려는 사람이 **팀부터 골라 들어가야 한다** — 주제로 시작하는 일에 팀을
앞세운 셈이다.

**기본 채팅 모델을 고르는 것은 등록이 아니라 사용이다.** 이미 등록된 것 중에서
이 팀이 무엇으로 돌지 정하는 일이라, 팀 상세에 select 로 있다. 「모델 등록」
페이지에서는 뺐다.

**설명 문구는 안 붙인다**(PM 지시). 제목이 「사용 중 모델」·「사용 중 커스텀
도구」면 그 아래 무엇이 있는지는 더 말할 것이 없다.

> ⚠ **가는 데 세 번 걸렸다.** 처음엔 등록까지 팀 상세로 옮기고 페이지 둘을
> 지웠다 — PM 의 「전 팀 목록을 확인할 필요가 있을까」를 **「이 페이지들이 필요
> 없다」로 읽었는데**, 물은 것은 **목록의 범위**였다. 되돌린 뒤에는 팀 상세를
> 통째로 읽기 전용으로 뒀는데, 모델을 고르는 것은 읽기가 아니라 **사용**이라
> select 로 되돌아왔다.

### ④ 「내 파일」 — 새 기능

우리 파서 엔진에 **사용자가 직접 문서를 넣는** 길을 만든다.

- 파일을 **drag & drop** 으로 올리면 파싱·인덱싱한다
- 올린 것을 **라이브러리**에서 고를 수 있다
- 문서마다 **toggle** 이 있어 켜면 그 문서에서 검색한다
- 켠 파일은 **에이전트가 검색에서 쓴다** (붙이는 조작은 없다 — 아래 참조)

#### 경계 — 8/15 결정과 부딪히지 않는 이유

그날 「이 문서를 파싱/임베딩 하겠다를 사람이 정하지 않는다」로 정하고 사람이
파일을 고르던 화면(`/files/new`)을 지웠는데, ④의 toggle 은 **사람이 고르는
것**이다. 그래서 부딪혀 보인다.

**부딪히지 않는다 — 가르는 것이 「자동이냐」가 아니라 「누구 것이냐」이기
때문이다**(8/18 PM 결정).

| | 커넥터 문서 | 내 파일 |
|---|---|---|
| 소유 | 팀 | **개인** |
| 들어오는 길 | 폴더를 정하면 자동 | 내가 올린다 |
| 파싱·임베딩 판단 | 시스템(필요할 때) | **내가 toggle** |
| 다른 사람이 보나 | 본다 | **공유해야 본다** |
| 원본은 어디 | Drive·Jira — 우리는 사본 | **우리 저장소 — 우리가 원본** |
| 잃어버리면 | 다시 받으면 된다 | **없어진다** |

**경계를 화면이 말해 주는 것이 이 작업의 핵심이다.** 안 그러면 「어떤 문서는
자동이고 어떤 문서는 내가 켜야 한다」가 뒤섞인다.

> 지운 `/files/new` 를 되살리는 것이 아니다 — 그건 **Drive 폴더에서 고르는**
> 화면이었고, ④는 **내 컴퓨터에서 올리는** 것이다.
>
> **공유는 별개 기능이다.** M④ 안에 끼워 넣지 말고 순서를 지킨다 —
> 올리기·파싱·toggle 이 먼저고, 공유는 그 뒤다. **✅ 그 순서대로 끝났다**
> (8/18 저녁 · 아래 「공유」 절).

#### 정해진 것 (2026-08-18)

| 무엇 | 어떻게 |
|---|---|
| 메타·색인 | **`doc` 한 테이블**에 담는다. `owner_account_id` 를 더한다 |
| 개인 문서의 `team_id` | **NULL 로 둔다** (아래가 핵심) |
| 원문 바이트 | **`user/{account_id}/{doc_id}.ext`** — 팀 문서와 자리를 가른다 |
| 받는 법 | 아바타 업로드를 본뜬다(`apps/accounts/api_views.py`) |
| `source_type` | `UPLOAD` 를 더한다 — 「다시 받을 수 있는가」를 가르는 값이 된다 |

**표를 안 나눈 이유 — 파싱·임베딩이 `doc` 이 아니라 `doc_id` 에 묶여 있다.**

```
doc ─(doc_id)→ doc_block ─→ chunk ─→ vec_idx
                 ↑ 이 셋은 team 을 모른다. doc_id 만 안다.
```

셋 어디에도 팀 칸이 없어서, 표를 나누면 **그 셋까지 나누거나
`doc_block.doc_id` 를 다형(polymorphic)으로 만들어야 한다** — 파서·임베딩·검색을
통째로 두 벌 쓰게 된다. 새 기능 하나 때문에 지금 도는 파이프라인을 복제하는 것은
값이 맞지 않는다.

**`team_id` 를 NULL 로 두는 것이 핵심이다.** 팀 문서를 읽는 자리가 13 곳인데
전부 `WHERE d.team_id = %s` 로 건다. NULL 이면 **그 13 곳이 한 줄도 안 바뀐 채
개인 문서를 걸러낸다**(`NULL = 'TE001'` 은 참이 아니다).

> **틀리는 쪽이 안전한 방향이다.** 조건을 빠뜨리면 개인 문서가 팀 검색에 새는
> 것이 아니라 **안 보인다** — 새는 것은 사고고 안 보이는 것은 버그다. 반대로
> 개인 문서에 팀을 함께 넣었다면 한 곳만 빠뜨려도 남의 파일이 팀 근거로 딸려
> 나온다.

**확인한 것** — `doc.team_id` 는 이미 NULL 을 받는다(NOT NULL 이 아니다). 팀
조건 없이 `doc` 을 읽는 자리는 둘뿐이고 **둘 다 `doc_id` 로 직접 집는다**
(`cur_revision` 조회 · 청크 본문 조회) — 목록·검색이 아니라 범위가 이미 정해진
뒤의 조회라 샐 자리가 아니다. 유일 인덱스(`ux_doc_primary_per_proj`)도 `proj_id`
기준이라 개인 문서(proj 없음)와 부딪히지 않는다.

**원문 자리를 가르는 이유** — 지금 키는 `build_key(team_id, doc_id, mime)` 가
만드는 `{team_id}/{doc_id}.pdf` 다. `team_id` 가 NULL 이면 키가
**`None/DC001.pdf`** 이 된다. 그리고 팀으로 나눈 이유가 「한 팀을 통째로 지울 때
디렉터리 하나만 지우면 된다」였다(`storage.py`) — 개인 파일이 그 아래 있으면
**팀을 지울 때 내 파일이 함께 지워진다.** 자리를 가르는 것이 소유 결정의
연장이지 예외가 아니다.

```
{team_id}/{doc_id}.ext          커넥터 문서  (지금)
user/{account_id}/{doc_id}.ext  내 파일     (더한다)
avatar/{account_id}.ext         프로필 사진  (지금)
```

**이름 있는 앞자리를 쓰는 것이 이 저장소의 방식이다** — `avatar/` 가 이미
그렇다. 계정을 앞자리 없이 뿌리에 얹으면(`UA001/`) 팀과 섞여 눈으로 구분되지
않는다. 계정마다 디렉터리를 하나 주는 것은, 계정을 지울 때 디렉터리 하나면
끝나게 하려는 것이다.

> 그 청소는 **아직 아무 데도 없다** — 저장소를 지우는 코드가 한 줄도 없다
> (`rmtree` 없음). `storage.py` 의 그 문장은 의도이지 구현이 아니다. 그래도 자리는
> 지금 갈라 둔다 — 나중에 그 청소를 쓸 때 정확히 그렇게 지울 것이기 때문이다.

#### 에이전트에 파일을 붙이지 않는다 (2026-08-18 PM)

한동안 「파일을 에이전트에 어떻게 잇나」를 열어 두고 있었는데, **질문이
틀렸다.** 「에이전트에 왜 자료를 직접 골라 줘야 하나」로 되물으니 답이 나왔다 —
**골라 줄 이유가 없다.**

**지금 제품에 그런 개념이 없다.**

| | 누가 정하나 |
|---|---|
| 어느 **도구**를 쓰나 | 에이전트(`agent_tool.tool_ref`) |
| 어느 **문서**를 보나 | **팀** — `document_search` 가 팀 문서 전체를 훑는다 |

에이전트가 문서를 고른 적이 없다. 기준 문서(`doc_role`)를 고르는 것도
프로젝트지 에이전트가 아니다. 그리고 **에이전트 단위 손잡이는 이미 있다** —
`document_search` 를 그 에이전트에 붙이냐 마느냐가 「이 에이전트가 문서를
보나」다. 거기에 「어느 문서를」까지 더하는 것이 이 결정이었다.

**toggle 이 이미 그 선택이다.** 붙이는 표를 따로 두면 같은 파일을 **두 번**
골라야 하고 — 켜고, 또 에이전트마다 붙이고 — 안 붙인 에이전트에서는 켠 파일이
안 보인다. **toggle 이 켜져 있는데 안 나오는 상태가 정상**이 되는데, 그건
화면이 설명할 수 없다.

**그래서 멘토링의 「에이전트를 만들면 이것과 연결될 수 있게」는 「내 파일도
에이전트가 쓸 수 있어야 한다」로 읽는다.** 지금 `document_search` 가 팀 문서만
보기 때문에 나온 말이다. 할 일은 표를 만드는 것이 아니라 **범위를 넓히는
것**이다:

```
지금:  팀 문서
바뀜:  팀 문서 + 내가 켠 내 파일
```

> ⚠ **나중에 올 문제 하나는 알고 간다.** 「계약서 검토」 에이전트가 무관한 개인
> 파일까지 끌어오는 **정확도** 문제다. 그건 권한이 아니라 검색 품질 문제이고,
> 지금은 toggle 로 거친 조절이 된다 — **필요해지면 그때 좁히는 것이 맞지, 지금
> 표를 만들 이유는 아니다.**

#### 남은 결정 — 없다

위 결정이 「파일이 도구인가 자료인가」를 지웠다. **연결한다는 전제가 있어야
성립하던 질문**이었기 때문이다. 그래서 toggle 의 뜻도 확정된다 —

**`doc.search_enabled` 칸 하나.** 「내 검색 범위에 넣나」다.

> 칸이 필요한 이유는 그대로다. `search_ready` 는 **계산값**이고(청크가 있는지
> `EXISTS` 로 본다) toggle 은 **의도**라, 껐는데 청크는 남아 있는 상태가 정상이다.

#### 공유 — **팀에 보여 준다, 넘기지 않는다** (2026-08-18 저녁)

| 무엇 | 내가 올린 것 | 팀원이 공유한 것 |

#### 숫자·화면이 아직 없는 것

- **크기 상한.** 아바타는 2MB 인데 문서는 그 값이 맞지 않는다. **파싱하는

  않고** txt·md·csv 는 시그니처가 아예 없다. 약속할 수 있는 것은 **확장자
  화이트리스트 + 시그니처가 있는 것만 대조**까지다. 이 차이를 주석에 적어 두지
  않으면 다음 사람이 아바타를 보고 같은 수준으로 믿는다.
- **못 읽는 형식을 언제 알리나.** 확장자 표에 없으면 키가 `.bin` 이 된다

  `extract_status = UNSUPPORTED` 로 끝날 형식을 **올리기 전에** 거를지 올린 뒤에

  되살릴 길이 없다는 것도 말해야 한다.

| 뺄 후보였던 열 | 왜 못 빼나 |
|---|---|
| 계정 관리 `매핑 상태` | 값이 셋이다 — 미연결 · 연결됨 · **중복 연결**. 「연결된 직원」이 비었는지로는 **중복 연결을 못 가른다**, 그런데 그게 운영자가 잡아내야 하는 이상 상태다 |
| 계정 관리 `HR 조직` · 팀 현황 `출처 조직` | `team.src_org_id` 가 nullable 이라 **팀과 1:1 이 보장되지 않는다** |

**내가 틀린 이유를 적어 둔다** — 화면에서 두 열의 값이 같아 보여 「중복」이라고
판단했는데, **그때 실데이터가 1건뿐이었다.** 한 건으로 같아 보이는 것은 같다는
뜻이 아니다. 열을 빼는 판단은 값이 아니라 **그 열이 담는 상태의 가짓수**로 해야
한다.

폭 문제 자체는 다른 방법으로 풀렸다 — 좁은 화면에서 표를 세로로 쌓으므로 열이
많아도 전부 읽힌다(8/15).
