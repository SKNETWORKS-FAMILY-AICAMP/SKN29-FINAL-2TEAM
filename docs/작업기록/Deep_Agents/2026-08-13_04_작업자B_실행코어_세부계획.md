### Phase 7 — 운영 엣지케이스 검증 (2026-08-18 완료)

`phase7_hitl_operational_check.py`(저장소 루트)로 실제 `PostgresSaver` + **진짜 별도
OS 프로세스**(subprocess로 완전히 새 파이썬 인터프리터를 띄움 — 페이크 모델 인스턴스도,
`AgentRuntimeFactory`도, 체크포인터 커넥션도 전부 새로 만듦, 공유하는 건 Postgres에 저장된
thread_id 행뿐)로 검증했다. `AgentRuntimeFactory.build()`는 그대로, `ModelFactory.create()`만
결정적 페이크 모델로 바꿔치기했다 — 이 테스트가 보는 건 모델의 tool 선택 품질이 아니라
체크포인터/인터럽트가 프로세스 경계를 넘어 실제로 살아남는지이므로 페이크 모델이 적절한
방법이라고 판단.

- **시나리오 1(승인 대기 중 프로세스 재시작 후 approve)**: 프로세스 1이 `task_register`
  승인 대기(`__interrupt__`)를 유발하고 재개 없이 그대로 종료 → 완전히 새 프로세스 2가 같은
  `thread_id`로 그래프를 새로 만들어 `get_state()`로 대기 상태를 그대로 읽어내고,
  `Command(resume={"decisions": [{"type": "approve"}]})`로 재개 → `task_register` 핸들러가
  정확히 1번만 실행되고(중복 실행 없음) 그래프가 정상 종료됨을 확인. **PASS.**
- **시나리오 2(process 재시작 후 reject)**: 같은 구조로 `{"type": "reject"}` 재개 → 핸들러가
  0번 실행되고(승인 없인 실행 안 됨), 모델에게는 langchain 기본 거부 메시지("User rejected the
  tool call for ... Do not retry ...")가 `ToolMessage(status="error")`로 전달돼 그래프가
  정상 종료됨을 확인. **PASS.**
- 두 시나리오 모두 반복 실행에서 안정적으로 통과(플레이키 없음), 이 세션 안에서 직접 실행해
  확인함(사용자 로컬 환경 불필요 — OpenAI 네트워크가 필요 없는 순수 체크포인터/인터럽트
  메커니즘 검증이라 이 클라우드 샌드박스에서 완결됨).
- **"타임아웃되는 경우"는 검증 대상에서 제외**: 체크포인트 테이블·`HumanInTheLoopMiddleware`
  양쪽 다 자체 TTL/만료 메커니즘이 없다(소스 확인) — 대기 상태는 재개할 때까지 무기한
  유지된다. 즉 "타임아웃"은 이 코드가 자체적으로 처리하는 개념이 아니라 애플리케이션
  레이어(예: UI에서 오래된 승인 요청을 어떻게 보여줄지)의 문제라서, 이 스크립트로 재현할
  성격의 버그가 아니라고 판단해 만들지 않았다 — 만들 필요가 생기면(예: 애플리케이션
  레벨에서 자체 만료 정책을 추가하기로 결정하면) 그때 근거를 갖고 다시 접근.
- 발견된 코드 결함 없음 — Phase 7 배선(`factory.py`/`compat/deepagents_v075.py`)은 프로세스
  재시작 조건에서도 설계대로 동작함을 확인.
