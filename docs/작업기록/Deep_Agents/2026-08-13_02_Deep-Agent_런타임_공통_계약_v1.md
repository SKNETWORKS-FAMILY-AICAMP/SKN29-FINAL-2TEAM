# Deep Agent 런타임 공통 계약 v1

## 1. 문서 목적과 우선순위

이 문서는 Deep Agent형 에이전트 빌더를 두 명이 분할 구현할 때 사용하는 공통 계약 정본이다. DB·빌더·API 담당과 Deep Agent 런타임 담당이 같은 타입과 인터페이스를 기준으로 개발하도록 다음 항목을 고정한다.

- 불변 에이전트 버전과 세션 고정 규칙
- 부모 및 서브 에이전트 런타임 데이터 타입
- Repository와 Loader의 반환 형식
- 서브 에이전트 구조·상태·권한 검증
- 도구 런타임 컨텍스트 주입 방식
- MCP 자격 증명 MVP 범위
- `CompiledSubAgent` 조립 방식
- 실행 전 오류와 스트림 중 오류 처리
- 부모·자식·도구 이벤트 형식
- 두 명의 작업 경계와 통합 순서

이 문서와 기존 설계 문서가 충돌하면 이 문서가 우선한다. 계약 변경은 두 담당자가 합의한 별도 커밋으로만 진행한다.

## 2. 확정 원칙

1. 저장·발행된 `agent_versions`는 불변이다.
2. 세션은 생성 시 선택된 `agent_version_id`에 고정된다.
3. 부모 버전은 자식의 특정 `child_version_id`를 참조한다.
4. 부모와 자식은 각각 자신의 모델·도구·시스템 프롬프트를 가진다.
5. 자식은 독립 그래프로 컴파일하고 `CompiledSubAgent`로 부모에 연결한다.
6. MVP에서는 `부모 → 자식` 한 단계 위임만 허용한다.
7. Deep Agents가 제공하는 기본 Middleware는 사용한다.
8. 서비스 전용 커스텀 Middleware, Memory, TODO, Checkpointer는 MVP에서 비활성화한다.
9. MVP의 MCP 자격 증명은 팀 공용 범위만 지원한다.
10. 구조 검증은 공통 구현체 하나를 저장·발행 API와 런타임이 함께 사용한다.
11. 테스트 실행과 실제 Chat은 같은 런타임 Factory와 Executor를 사용한다.

## 3. 공통 런타임 타입

`AgentDefinition`과 `SubagentDefinition`은 아래 정의만 사용한다. 다른 파일에서 유사 타입을 다시 정의하지 않는다.

### 3.1 `SubagentDefinition`

```python
from dataclasses import dataclass, field


@dataclass(frozen=True)
class SubagentDefinition:
    """부모 버전에 고정된 독립 실행형 서브 에이전트."""

    agent_id: str
    agent_version_id: str

    name: str
    description: str
    system_prompt: str

    model: str
    reasoning_effort: str
    max_iterations: int

    # 부모가 자식을 호출할 때 사용하는 필수 정보
    alias: str
    delegation_description: str

    tool_refs: tuple[str, ...] = field(default_factory=tuple)

    def __post_init__(self) -> None:
        if not self.alias.strip():
            raise InvalidSubagentAliasError(
                "서브 에이전트 alias는 필수입니다."
            )

        if not self.delegation_description.strip():
            raise InvalidDelegationDescriptionError(
                "서브 에이전트 위임 설명은 필수입니다."
            )
```

`alias`와 `delegation_description`에는 빈 문자열 기본값을 두지 않는다. 객체 하나만 생성해도 로컬 필수 조건이 보호되어야 한다.

### 3.2 `AgentDefinition`

```python
@dataclass(frozen=True)
class AgentDefinition:
    """Deep Agent 하나를 생성하기 위한 완전한 런타임 정의."""

    # 저장 전 테스트 초안만 None을 허용한다.
    agent_id: str | None
    agent_version_id: str | None

    name: str
    description: str
    system_prompt: str

    model: str
    reasoning_effort: str
    max_iterations: int

    tool_refs: tuple[str, ...] = field(default_factory=tuple)
    subagents: tuple[SubagentDefinition, ...] = field(default_factory=tuple)
```

ID 규칙은 다음과 같다.

- 저장된 부모는 `agent_id`, `agent_version_id`가 모두 필수다.
- 저장된 자식은 `agent_id`, `agent_version_id`가 모두 필수다.
- 아직 저장되지 않은 부모 초안 테스트만 두 값을 모두 `None`으로 둘 수 있다.
- 저장되지 않은 초안을 서브 에이전트로 사용하는 것은 허용하지 않는다.

### 3.3 요청 단위 서브 에이전트 검증 정보

불변 실행 정의와 현재 요청자의 권한 상태를 분리한다.

```python
@dataclass(frozen=True)
class SubagentReference:
    child_agent_id: str
    child_version_id: str

    alias: str
    delegation_description: str

    # 현재 요청 시점의 상태와 권한
    is_active: bool
    can_execute: bool

    # 고정된 자식 버전이 다시 자식을 포함하는가
    has_subagents: bool
```

`is_active`와 `can_execute`는 요청 시점마다 다시 계산한다. 사용자마다 다른 `can_execute`를 `agent_version_id` 기반 전역 캐시에 저장하지 않는다.

### 3.4 Loader 반환 타입

```python
@dataclass(frozen=True)
class LoadedAgentDefinition:
    definition: AgentDefinition
    subagent_references: tuple[SubagentReference, ...]
```

`definition.subagents`와 `subagent_references`는 `agent_id`, `agent_version_id` 기준으로 일대일 대응해야 한다. Loader가 이 불변 조건을 보장한다.

## 4. 실행 컨텍스트 계약

`RuntimeContext`는 누가 어떤 환경에서 요청했는지만 표현한다. 무엇을 실행하는지는 `run_agent()` 인자와 `AgentDefinition`이 담당한다.

```python
@dataclass(frozen=True)
class RuntimeContext:
    account_id: str
    team_id: str

    session_id: str | None = None
    project_id: str | None = None

    run_id: str | None = None
    parent_run_id: str | None = None
```

`RuntimeContext`에는 `agent_version_id`를 넣지 않는다. 동일한 값이 `run_agent()`와 Context에 이중으로 존재해 서로 달라지는 경로를 만들지 않는다.

이벤트의 `agent_id`, `agent_version_id`는 `AgentDefinition`에서 읽는다.


부모가 발행된 후 자식의 새 버전이 나와도 기존 부모는 고정된 `child_version_id`를 계속 사용한다.

### 5.5 세션 고정

```text
chat_session
- session_id
- agent_id
- agent_version_id
```

세션 생성 이후 `agent_version_id`는 변경하지 않는다.

### 5.6 실행 로그

```text
agent_run
- run_id
- session_id
- agent_id
- agent_version_id
- parent_run_id
- status
```

자식 실행은 자신의 `agent_id`, `agent_version_id`와 부모의 `parent_run_id`를 기록한다.

버전은 불변이어도 에이전트 비활성화와 권한 회수는 안전을 위한 런타임 차단 수단으로 인정한다. 따라서 고정 버전을 실행할 때도 현재 활성 상태와 현재 사용자의 권한은 다시 확인한다.

서브 에이전트 관계 반환 예시는 다음과 같다.

```json
{
```

### 6.2 Loader 인터페이스

```python
class AgentDefinitionLoader:
    def load(
        self,
        *,
        agent_id: str,
        agent_version_id: str,
        context: RuntimeContext,
        include_subagents: bool = True,
    ) -> LoadedAgentDefinition:
        """저장된 특정 버전을 런타임 정의로 변환한다."""

    def from_draft(
        self,
        *,
        draft: dict,
        context: RuntimeContext,
    ) -> LoadedAgentDefinition:
        """아직 발행하지 않은 부모 초안을 테스트 정의로 변환한다."""
```

부모는 `include_subagents=True`, 자식은 `include_subagents=False`로 로딩한다.

```python
parent = loader.load(
    agent_id=parent_id,
    agent_version_id=parent_version_id,
    context=context,
    include_subagents=True,
)

child = loader.load(
    agent_id=child_id,
    agent_version_id=child_version_id,
    context=context,
    include_subagents=False,
)
```

자식 정의에 다시 서브 에이전트가 존재하면 조용히 제거하지 않고 `DelegationDepthError`를 발생시킨다.

## 7. 공통 서브 에이전트 검증

### 7.1 구현체 위치

검증 구현체는 다음 파일 하나만 둔다.

```text
services/agent_runtime/subagents/validation.py
```

저장·발행 API와 런타임 Factory는 같은 함수를 import한다. API View나 Factory 안에 별도의 자기 참조·중복·순환 검사를 다시 구현하지 않는다.

### 7.2 검증 함수

```python
def validate_subagents(
    *,
    parent_agent_id: str | None,
    child_refs: tuple[SubagentReference, ...],
    dependency_graph: dict[str, set[str]],
    allow_subagents: bool,
) -> None:
    ...
```

검증 항목은 다음과 같다.

- 자기 자신 선택 금지
- 동일 자식 중복 금지
- 동일 alias 중복 금지
- 빈 alias 금지
- 빈 위임 설명 금지
- 존재하지 않는 자식 또는 자식 버전 금지
- 비활성 자식 금지
- 현재 요청자에게 실행 권한이 없는 자식 금지
- 순환 참조 금지
- MVP의 한 단계 위임 제한

핵심 검증 형태는 다음과 같다.

```python
def validate_subagents(
    *,
    parent_agent_id,
    child_refs,
    dependency_graph,
    allow_subagents,
):
    child_ids = [ref.child_agent_id for ref in child_refs]
    aliases = [ref.alias for ref in child_refs]

    if parent_agent_id is not None and parent_agent_id in child_ids:
        raise SelfReferenceError()

    if len(child_ids) != len(set(child_ids)):
        raise DuplicateSubagentError()

    if len(aliases) != len(set(aliases)):
        raise DuplicateSubagentAliasError()

    for ref in child_refs:
        if not ref.alias.strip():
            raise InvalidSubagentAliasError()

        if not ref.delegation_description.strip():
            raise InvalidDelegationDescriptionError()

        if not ref.is_active:
            raise InactiveSubagentError(ref.child_agent_id)

        if not ref.can_execute:
            raise SubagentPermissionError(ref.child_agent_id)

        if not allow_subagents and ref.has_subagents:
            raise DelegationDepthError()

    validate_no_cycle(
        parent_agent_id=parent_agent_id,
        child_ids=child_ids,
        dependency_graph=dependency_graph,
    )
```

## 8. 도구 런타임 컨텍스트 계약

### 8.1 명시적 주입 선언

도구마다 서버가 주입해야 하는 컨텍스트 이름을 명시한다.

```python
@dataclass(frozen=True)
class Tool:
    ref: str
    name: str
    description: str
    input_schema: dict
    handler: callable

    side_effect: bool = False
    injected_context: tuple[str, ...] = ()
```

예시는 다음과 같다.

```python
Tool(
    ref="document_search",
    name="문서 검색",
    description="현재 팀의 문서를 검색한다.",
    input_schema={...},
    handler=document_search,
    injected_context=("team_id",),
)
```

### 8.2 서버 컨텍스트 주입

```python
CONTEXT_VALUES = {
    "team_id": lambda context: context.team_id,
    "account_id": lambda context: context.account_id,
    "session_id": lambda context: context.session_id,
    "project_id": lambda context: context.project_id,
    "run_id": lambda context: context.run_id,
    "parent_run_id": lambda context: context.parent_run_id,
}


def inject_runtime_context(tool, arguments, context):
    resolved = dict(arguments)

    for name in tool.injected_context:
        try:
            # 사용자 또는 모델이 같은 키를 보내도 서버 값이 우선한다.
            resolved[name] = CONTEXT_VALUES[name](context)
        except KeyError as exc:
            raise ToolContextConfigurationError(name) from exc

    return resolved
```

모든 도구에 `team_id`, `account_id`를 무조건 전달하지 않는다. 핸들러가 선언하지 않은 인자가 전달되어 `TypeError`가 발생하는 경로를 만들지 않는다.

### 8.3 레거시 호환 종료 조건

기존 도구는 마이그레이션 중에만 `inspect.signature()`로 컨텍스트 인자를 추론할 수 있다.

- 새 도구에는 자동 추론을 사용하지 않는다.
- 자동 추론이 사용되면 deprecation warning을 기록한다.
- 기존 도구는 Deep Agent MVP 통합 중 모두 `injected_context`를 명시한다.
- Deep Agent MVP 정식 배포 전에 자동 추론 fallback을 삭제한다.

동일한 이름이 우연히 다른 의미로 사용되는 충돌을 막기 위해 운영 코드에 자동 추론을 영구 유지하지 않는다.

## 9. MCP 자격 증명 정책

MVP 정책은 다음과 같다.

- 팀 공용 MCP 자격 증명만 지원한다.
- 사용자 개인 MCP 자격 증명은 MVP에서 지원하지 않는다.
- 다른 사용자의 개인 자격 증명을 사용하는 경로는 허용하지 않는다.

도구 Loader에는 전체 `RuntimeContext`를 전달해 후속 버전에서 공개 인터페이스를 바꾸지 않도록 한다.

```python
tools = tool_loader.load(
    tool_refs=definition.tool_refs,
    context=context,
)
```

후속 개인 자격 증명 지원 시에는 도구에 선언된 `credential_scope`에 따라 현재 `account_id` 또는 `team_id`의 자격 증명만 선택한다. 개인 자격 증명이 없을 때 팀 자격 증명으로 자동 fallback할지는 별도 제품 정책으로 결정한다.

## 10. `CompiledSubAgent` 조립 계약

자식은 부모와 독립된 모델·도구·시스템 프롬프트를 가진 그래프로 조립한다.

```python
from deepagents import CompiledSubAgent


def build_subagent(
    definition: SubagentDefinition,
    context: RuntimeContext,
) -> CompiledSubAgent:
    child_definition = AgentDefinition(
        agent_id=definition.agent_id,
        agent_version_id=definition.agent_version_id,
        name=definition.name,
        description=definition.description,
        system_prompt=definition.system_prompt,
        model=definition.model,
        reasoning_effort=definition.reasoning_effort,
        max_iterations=definition.max_iterations,
        tool_refs=definition.tool_refs,
        subagents=(),
    )

    child_graph = runtime_factory.build(
        definition=child_definition,
        context=context,
        allow_subagents=False,
    )

    return CompiledSubAgent(
        name=definition.alias,
        description=definition.delegation_description,
        runnable=child_graph,
    )
```

`name`에는 부모가 호출할 `alias`, `description`에는 위임 판단용 `delegation_description`을 넣는다.

`allow_subagents=False`일 때 자식이 다시 자식을 포함하면 이를 무시하지 않고 `DelegationDepthError`를 발생시킨다.

## 11. Runtime Factory 계약

```python
class AgentRuntimeFactory:
    def build(
        self,
        *,
        definition: AgentDefinition,
        subagent_references: tuple[SubagentReference, ...] = (),
        context: RuntimeContext,
        allow_subagents: bool = True,
    ):
        validate_subagents(
            parent_agent_id=definition.agent_id,
            child_refs=subagent_references,
            dependency_graph=self.dependency_graph.load(context.team_id),
            allow_subagents=allow_subagents,
        )

        model = self.model_factory.create(
            model=definition.model,
            reasoning_effort=definition.reasoning_effort,
        )

        tools = self.tool_loader.load(
            tool_refs=definition.tool_refs,
            context=context,
        )

        subagents = (
            self.subagent_builder.build(
                definitions=definition.subagents,
                context=context,
            )
            if allow_subagents
            else []
        )

        custom_middleware = self.middleware_factory.build(
            definition=definition,
            context=context,
        )

        return create_deep_agent(
            model=model,
            system_prompt=definition.system_prompt,
            tools=tools,
            subagents=subagents,
            middleware=custom_middleware,
        )
```

MVP에서 `custom_middleware=[]`를 반환하더라도 Deep Agents 자체의 기본 Middleware를 제거한다는 의미가 아니다. 서비스에서 추가하는 커스텀 Middleware가 아직 없다는 뜻이다.

Memory, TODO, 서비스 전용 Checkpointer는 확장 위치만 만들고 런타임에 연결하지 않는다. 실제 도입 시 고정한 Deep Agents SDK 버전의 생성 함수 시그니처를 다시 확인한다.

### 13.1 공개 인터페이스

저장된 에이전트 실행에는 `agent_id`, `agent_version_id`가 모두 필요하다. 초안 테스트에는 `draft`만 사용하며 저장된 ID와 동시에 전달할 수 없다.

### 13.2 실행 대상 가드

```python
def validate_execution_target(
    *,
    agent_id,
    agent_version_id,
    draft,
):
    has_draft = draft is not None
    has_agent_id = agent_id is not None
    has_version_id = agent_version_id is not None

    if has_draft and (has_agent_id or has_version_id):
        raise InvalidExecutionTargetError(
            "초안과 저장된 에이전트 버전을 동시에 실행할 수 없습니다."
        )

    if not has_draft and not (has_agent_id and has_version_id):
        raise InvalidExecutionTargetError(
            "저장된 실행에는 agent_id와 agent_version_id가 모두 필요합니다."
        )
```

이 가드는 Loader나 Factory를 호출하기 전에 실행한다.

### 13.3 실행 전 오류와 스트림 중 오류

```python
def run_agent(...):
    validate_execution_target(
        agent_id=agent_id,
        agent_version_id=agent_version_id,
        draft=draft,
    )

    try:
        loaded = (
            loader.from_draft(draft=draft, context=context)
            if draft is not None
            else loader.load(
                agent_id=agent_id,
                agent_version_id=agent_version_id,
                context=context,
            )
        )

        runtime = factory.build(
            definition=loaded.definition,
            subagent_references=loaded.subagent_references,
            context=context,
        )
    except AgentRuntimeError:
        raise
    except Exception as exc:
        logger.exception("Deep Agent 조립 실패")
        raise AgentBuildError(
            "에이전트를 준비하지 못했습니다."
        ) from exc

    try:
        for raw_event in stream_adapter.stream(
            runtime=runtime,
            user_input=user_input,
        ):
            converted = event_mapper.convert(
                raw_event,
                definition=loaded.definition,
                context=context,
            )
            if converted is not None:
                yield converted
    except Exception:
        logger.exception(
            "Deep Agent 실행 실패: agent=%s version=%s",
            loaded.definition.agent_id,
            loaded.definition.agent_version_id,
        )
        yield {
            "type": "error",
            "error_code": "AGENT_EXECUTION_FAILED",
            "message": "에이전트 실행 중 오류가 발생했습니다.",
            "agent_id": loaded.definition.agent_id,
            "agent_version_id": loaded.definition.agent_version_id,
            "run_id": context.run_id,
            "complete": True,
        }
```

내부 예외 문자열과 스택트레이스는 사용자 이벤트에 포함하지 않는다.

## 15.0 스파이크 실행 결과 (2026-08-13 완료 — ✅ fallback 불필요)

`services/agent_runtime/_spike/streaming_spike.py`를 로컬(Python 3.13,
`deepagents==0.7.5`·`langchain-openai`, 모델 `gpt-4o-mini`)에서 실행했다.
아래 §15.1 6단계가 **`stream_mode="updates"` 하나만으로 실시간·정확하게 전부
관측됐다** — `"messages"`·`"custom"` 모드나 `stream_events(version="v3")`
상위 API는 필요 없었다.

관측한 신호(실제 raw event 발췌 기준):

| 판정 대상 | 신호 |
|---|---|
| 부모 vs 자식 | 네임스페이스 튜플. 부모 `()`, 자식 `('tools:<uuid>', ...)` |
| `subagent_started` | 부모 네임스페이스, `{'model': {'messages': [AIMessage(tool_calls=[{'name': 'task', 'args': {'subagent_type': <alias>, 'description': <task_summary>}}])]}}` — deepagents 내장 위임 도구 `task`의 인자가 그대로 alias·task_summary다 |
| `tool_started`(자식) | 자식 네임스페이스, `{'model': {'messages': [AIMessage(tool_calls=[{'name': <tool_ref>}])]}}` |
| `tool_completed`(자식) | 자식 네임스페이스, `{'tools': {'messages': [ToolMessage(name=<tool_ref>)]}}` |
| `subagent_completed` | **부모** 네임스페이스로 복귀, `{'tools': {'messages': [ToolMessage(name='task', content=<자식 최종 답변>)]}}` |
| `result`(부모) | 부모 네임스페이스, `{'model': {'messages': [AIMessage(content=<텍스트>, tool_calls=[])]}}`(tool_calls 없음) |

실측 순서가 §15.1의 기대 순서와 정확히 일치했다:
`agent_started → subagent_started → tool_started → tool_completed →
subagent_completed → result`.

**결론**: §14 이벤트 계약(`subagent_started`/`subagent_completed` 2종)을
그대로 쓴다. §15.1 마지막의 fallback(`subagent_invoked`/`subagent_completed`
2단계로 낮추는 안)은 폐기한다 — 필요 없었다.

**구현 완료**: `services/agent_runtime/events.py`의 `EventMapper`를 위 신호
기준으로 실제 구현했다(더 이상 스텁 아님). FIFO(`_pending`)로 부모의 위임
결정과 자식 네임스페이스를 대응시킨다 — **단, 이건 "부모가 서브 에이전트를
동시에 여러 개 병렬 호출하지 않는다"는 전제에 기댄다.** 이번 스파이크는
서브 에이전트 1개짜리 시나리오만 검증했다 — 병렬 위임(모델이 한 턴에
`tool_calls`를 여러 개 내는 경우)은 아직 관측하지 못했다. MVP는 위임 정책상
"명시적으로 선택한 서브 에이전트만, 부모→자식 1단계"이지 "동시 호출 금지"는
아니므로, 실제 다중 위임이 나오면 네임스페이스와 `tool_call_id`를 직접
대응시키는 방식으로 `EventMapper`를 다시 검증할 것(`events.py` 모듈
docstring에 TODO로 남겨둠).

`EventMapper`는 무상태가 아니다 — **실행(run)마다 새 인스턴스가 필요하다**
(위임 추적 상태를 들고 있어서). `executor.py`의 `AgentExecutor`는 생성자에
`EventMapper` 인스턴스를 주입받지 않고 `event_mapper_factory`(기본값
`EventMapper` 클래스)를 받아 `run()` 호출마다 새로 만들도록 이미 고쳤다.

## 15. 서브 에이전트 스트리밍 선행 검증

Deep Agents는 동기 서브 에이전트 실행도 LangGraph 서브그래프 스트리밍으로 관측할 수 있다. 다만 실제 이벤트 형식은 고정한 SDK 버전에 따라 달라질 수 있으므로 본 구현 전에 스파이크 테스트를 수행한다.

우선 검토할 방식은 다음 두 가지다.

```python
# 상위 이벤트 API를 지원하는 버전
stream = runtime.stream_events(input, version="v3")
for subagent in stream.subagents:
    ...
```

```python
# LangGraph 저수준 스트림
runtime.stream(
    input,
    stream_mode=["updates", "messages", "custom"],
    subgraphs=True,
    version="v2",
)
```

공식 자료:

- [Deep Agents Event streaming](https://docs.langchain.com/oss/python/deepagents/event-streaming)
- [Deep Agents Streaming](https://docs.langchain.com/oss/python/deepagents/streaming)
- [LangGraph Streaming](https://docs.langchain.com/oss/python/langgraph/streaming)

`AsyncSubAgent`는 백그라운드·비동기 작업을 위한 별도 기능이다. 동기 `CompiledSubAgent`의 실시간 관측에 반드시 필요한 전제는 아니다.

### 15.1 스파이크 테스트 시나리오

```text
부모 Deep Agent
└─ CompiledSubAgent
   └─ 테스트 도구 1회 호출
```

다음을 검증한다.

- `subagent_started`가 자식 완료 전에 발생한다.
- `subagent_completed`가 부모의 최종 `result` 전에 발생한다.
- namespace 또는 projection에서 자식 alias를 얻을 수 있다.
- 자식 내부 도구 시작·완료 이벤트를 구분할 수 있다.
- 자식 실패 상태를 구분할 수 있다.
- 부모와 자식 메시지를 분리할 수 있다.

기대 순서는 다음과 같다.

```text
agent_started(parent)
subagent_started(child)
tool_started(child)
tool_completed(child)
subagent_completed(child)
result(parent)
```

고정한 SDK 버전에서 실시간 자식 이벤트를 얻지 못하면 시작과 완료를 동시에 합성해서 실시간처럼 표시하지 않는다. 대신 MVP 이벤트를 다음 수준으로 낮춘다.

```text
subagent_invoked
→ task 도구 호출 시점

subagent_completed
→ task 결과 수신 시점
```

스파이크 테스트가 통과하기 전에는 프런트에서 자식 내부 단계까지 보여주는 진행 UI를 구현하지 않는다.

```text
부모와 자식 버전 발행
→ 부모 버전에 자식 버전 고정
→ 세션에 부모 버전 고정
→ Loader가 같은 버전의 정의와 요청 단위 권한 정보 조회
→ 공통 검증으로 상태·권한·순환·깊이 검사
→ 각 자식을 독립 Deep Agent로 조립
→ CompiledSubAgent로 부모에 연결
→ 부모가 자식에게 작업 위임
→ 자식의 모델과 도구로 독립 실행
→ 부모·자식·도구 이벤트 스트리밍
→ 실행 오류 발생 시 terminal error 이벤트
→ 부모·자식 실행 버전과 parent_run_id 기록
```

Memory, 서비스 전용 Middleware, TODO, Checkpointer는 폴더와 확장 위치만 존재해도 된다. 이 기능들은 1차 완료 조건에 포함하지 않는다.

## 20. 분업 시작 체크리스트

- [ ] `AgentDefinition`, `SubagentDefinition`이 한 곳에만 정의되어 있다.
- [ ] 부모와 자식 모두 `agent_version_id`를 사용한다.
- [ ] `RuntimeContext`에 `agent_version_id`가 없다.
- [ ] `SubagentReference`에 `is_active`, `can_execute`, `has_subagents`가 있다.
- [ ] `validation.py` 시그니처가 공동 커밋되어 있다.
- [ ] 저장 API와 Factory가 같은 검증 함수를 사용한다.
- [ ] 초안과 저장 버전의 동시 실행을 가드한다.
- [ ] 도구가 `injected_context`를 명시한다.
- [ ] 레거시 자동 컨텍스트 추론의 삭제 조건이 정해져 있다.
- [ ] 개인 MCP 자격 증명이 MVP 제외로 명시되어 있다.
- [ ] 공통 예외와 HTTP 매핑이 구현되어 있다.
- [ ] 실행 전 오류와 스트림 중 오류를 구분한다.
- [ ] `CompiledSubAgent`가 alias와 위임 설명을 사용한다.
- [ ] `allow_subagents=False`가 재위임을 오류로 차단한다.
- [ ] 서브 에이전트 이벤트 스파이크가 완료되어 있다.
- [ ] 이벤트 스파이크 결과에 맞춰 프런트 범위가 확정되어 있다.
