## 1. 범위 — 장기만, 단기는 이미 있음

deepagents 공식 문서(docs.langchain.com/oss/python/deepagents/memory) 기준으로
"단기"와 "장기"는 서로 다른 메커니즘이다:

- **단기(short-term)**: 한 세션 안의 대화 이력·스크래치 공간. deepagents는
  LangGraph의 checkpointer(스레드 단위)로 관리한다.
- **장기(long-term)**: 세션을 넘어 남는 것. `memory=`(파일 경로) +
  `backend=StoreBackend(...)` + `store=`(실제 저장소)로 관리한다.

**이 앱은 단기를 이미 다른 방식으로 갖고 있다.** `chat_message` 테이블에 대화를
저장해 두고, `apps/chat/api_views.py`가 매 요청마다 이전 메시지를 다시 실어
`executor.run()`에 넘긴다(LangGraph의 thread_id/checkpointer 방식이 아니라 이
저장소 자체 방식 — `tests/test_chat.py`의 `conversation_history_is_threaded_through`
참고). deepagents가 기본 제공하는 `StateBackend`(단일 실행 안의 파일 스크래치
공간)는 손대지 않아도 이미 붙어 있다. 그래서 이번 작업은 **장기 메모리만** 새로
만들었다.

## 2. 설계 — 에이전트 단위 공유 메모리

deepagents 문서가 제시하는 패턴 중 "agent-scoped"(팀/에이전트가 공유)를 골랐다
— "user-scoped"(계정별 격리)도 가능하지만, 이 앱은 팀이 같이 쓰는 업무 도구라
"이 에이전트가 팀과 함께 배운 것"을 모으는 쪽이 기본값으로 맞다고 판단했다
(지훈에게 별도 확인은 안 함 — 나중에 계정 단위로 바꾸고 싶으면 namespace 튜플에
`account_id`만 추가하면 된다, `memory/backend.py` 주석 참고).

- **namespace**: `(team_id, agent_id)` — 팀 안에서 같은 에이전트로 나눈 모든
  대화가 같은 메모리 파일을 읽고 쓴다.
- **파일**: `/memories/AGENTS.md` 하나. 경로 문자열은 모든 에이전트가 공유하고,
  격리는 순전히 Store의 namespace가 한다(공식 예시와 같은 패턴).
- **backend**: `CompositeBackend(default=StateBackend(), routes={"/memories/": StoreBackend(...)})`
  — `/memories/` 밖의 파일 도구는 그대로 휘발성.
- **store**: `langgraph.store.postgres.PostgresStore` — 이 저장소가 이미 쓰는
  같은 Postgres(`settings.RAW_DATABASE_URL`)에 붙는다. 자체 테이블(`store`,
  `store_migrations` 등)을 `store.setup()`으로 직접 만든다 — `DB/schema.sql`이
  관리하는 다른 테이블과 달리 langgraph 라이브러리가 스스로 관리한다.
- **Root에만 붙인다.** Child(서브에이전트)는 메모리 없이 그대로 둔다 — MVP
  범위를 좁게 유지하려는 선택.

## 3. deepagents `middleware=`에 대한 정정 — 이전에 잘못 설명한 것

이 리서치 도중 발견한, **지훈에게 이미 잘못 말한 내용**을 여기 정정해 둔다.

이전에 "미들웨어는 우리가 넘긴 리스트로 통째로 대체된다"고 설명했는데, 이건
틀렸다. 공식 문서(docs.langchain.com/oss/python/deepagents/customization
"Middleware" 절)에 따르면:

> Pass middleware to the `middleware` argument... Each instance is **merged**
> into the Deep Agents stack by matching its `.name` against built-in entries:
> a match replaces that instance in place, and anything that does not match is
> **inserted** after `PatchToolCallsMiddleware`.

즉 `middleware=`는 **병합**이다 — `FilesystemMiddleware`, `SubAgentMiddleware`,
`SummarizationMiddleware`, `PatchToolCallsMiddleware`, prompt caching 같은
deepagents 기본 스택은 우리가 뭘 넘기든 항상 그대로 살아 있고, 우리가 넘긴
것(`ModelCallLimitMiddleware`/`ToolCallLimitMiddleware`)은 그 뒤에 끼워지는
것뿐이다. `.name`이 겹치면 그 자리를 교체하고, 안 겹치면 추가된다.

`TodoListMiddleware`가 자동으로 안 딸려오는 건 맞다 — 그건애초에 deepagents
기본 스택 목록(bare/full stack)에 아예 없는 항목이라, 쓰려면 명시적으로
`middleware=[TodoListMiddleware(...)]`로 넣어야 한다(팀이 시도했다가 되돌린
이유, `middleware/factory.py` 주석). `MemoryMiddleware`도 같은 원리로 동작한다
— "Only when you pass `memory`"(공식 문서 Full stack §11) — 그래서 이번
구현에서 `middleware/factory.py`를 안 건드리고 `factory.py`의 `build()`가
`create_root_graph(memory=...)`로 따로 넘기기만 해도 `MemoryMiddleware`가
자동으로 붙는다.

## 4. 구현

새 패키지 `services/agent_runtime/memory/`:

- `store.py` — `get_memory_store()`. 프로세스 전역 `PostgresStore` 하나를
  최초 호출에서 열고 재사용한다. **이 패키지의 "호출마다 새로 조립한다"는
  원칙(`bootstrap.py` docstring)의 유일한 예외** — Postgres 연결 풀을 매
  요청마다 열고 닫을 수는 없어서다. 모듈 docstring에 이 예외를 명시해 뒀다.
- `backend.py` — `build_memory_backend(team_id, agent_id)`, `memory_paths()`.
- `provider.py` — `MemoryProvider`. `AgentRuntimeFactory`가 다른 협력자들
  (`ModelFactory`, `ToolLoader` 등)과 같은 방식으로 생성자 주입받는다.

연결 지점:

- `compat/deepagents_v075.py`의 `create_root_graph()`에 `memory`/`backend`/`store`
  파라미터 추가(전부 기본값 없음/빈 값이면 deepagents 기본 동작 그대로 — 하위 호환).
- `factory.py`의 `AgentRuntimeFactory.__init__`에 `memory_provider: MemoryProvider | None = None`
  추가. `None`이면(기존 테스트 등) 예전과 완전히 동일하게 동작 — `build()`가
  Root 분기에서만 `memory_kwargs`를 채우고, Child 분기는 손 안 댔다.
- `bootstrap.py`의 `build_default_executor()`가 `MemoryProvider()`를 만들어
  넘긴다. `MemoryProvider()` 생성 자체는 I/O가 없다(연결은 실제 사용 시점에
  `get_memory_store()`가 연다) — "호출마다 새로 조립" 원칙과 안 어긋난다.

DB: 새 테이블을 `DB/schema.sql`에 안 만들었다 — `PostgresStore.setup()`이
자기 테이블을 스스로 관리한다(멱등). 대신 `requirements/base.txt`에
`langgraph-checkpoint-postgres`(PostgresStore가 들어있는 패키지)와
`psycopg[pool]` extra를 추가했다.

## 5. 검증 — 못 했음

이 세션 샌드박스에 deepagents·langgraph가 없고 로컬 Postgres도 없어서
(앞선 `2026-08-15_01` 문서 §5.2와 같은 제약) 실제로 메모리 파일이 쓰이고
읽히는지 실행 검증은 못 했다. `python3 -m py_compile`로 문법 오류만 확인했다.

**남은 확인(지훈 환경에서)**:

1. `pip install -r requirements/base.txt` (또는 `pip install langgraph-checkpoint-postgres "psycopg[binary,pool]"`)로 새 의존성 설치
2. 기본 챗 에이전트로 대화 → "내가 짧은 답을 좋아한다고 기억해줘" 같은 요청 →
   `PostgresStore`의 `store`/`store_migrations` 테이블에 실제로 행이 생기는지 확인
3. 같은 팀·같은 에이전트로 **새 세션**을 열어서 방금 기억한 내용을 실제로
   반영해 답하는지 확인(agent-scoped라 세션이 달라도 같은 에이전트면 공유돼야 함)
