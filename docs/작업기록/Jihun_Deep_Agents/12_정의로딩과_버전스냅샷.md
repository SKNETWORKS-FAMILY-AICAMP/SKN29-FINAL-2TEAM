# 12. 에이전트 정의 로딩과 버전 스냅샷

## 한 줄 정리

Deep Agents 설정을 코드에 고정하지 않고 DB의 발행 버전 또는 Builder 초안에서 읽어 불변 실행 정의로 바꾸며, Child는 연결 당시 선택한 특정 버전을 사용한다.

## Deep Agents 기본 설계

일반적인 Deep Agents 사용은 Python 코드에서 모델, 도구, 프롬프트, 서브에이전트를 직접 넘긴다. 에이전트 저장·발행·팀 권한·초안 실행 개념은 제공하지 않는다.

## 우리 설계

- `AgentDefinitionLoader`가 DB 행을 `AgentDefinition`과 `SubagentDefinition`으로 변환한다.
- 저장된 실행은 agent_id와 agent_version_id를 모두 지정한다.
- Builder Test Run은 아직 발행하지 않은 Root 초안과 이미 저장된 Child 버전을 합친다.
- Child를 불러올 때 현재 계정·팀 권한과 활성 상태를 다시 확인한다.
- Child 모델 해석 결과와 endpoint hash를 run snapshot에 남긴다.
- 레거시 에이전트 설정은 `legacy_bridge`에서 새 draft 계약으로 변환한다.

## 설계 이유

사용자가 에이전트를 자유롭게 만들면서도 실행 재현성, 권한, 발행 이력, 레거시 전환을 유지하기 위해서다.

## 좋은 부분

- 실행 대상이 특정 버전으로 명확하다.
- Child 권한을 저장 시점뿐 아니라 실행 로딩 시점에도 확인한다.
- 초안 테스트와 실제 실행이 같은 Factory 경로를 최대한 공유한다.
- 모델 endpoint의 원문 대신 hash를 기록해 비밀 노출을 줄인다.

## 문제점

- 공통 Scaffold와 런타임 정책은 실행 시점 값이므로 같은 agent_version도 완전히 같은 동작을 보장하지 않는다.
- Child 버전이 비활성화되거나 권한이 바뀌면 과거 Root 버전도 더 이상 실행되지 않을 수 있다.
- Builder Test Run은 Root는 초안, Child는 저장 버전이라 완전한 전체 초안 조합 테스트는 아니다.
- 레거시 변환 경로가 오래 남으면 두 설정 계약을 동시에 유지해야 한다.

## 현재 판단

DB 기반 Agent Platform에 필요한 설계다. “에이전트 버전”과 “실행 환경 버전”을 함께 기록해야 재현성이 완성된다.

## 즉시 수정이 필요한 치명적 문제

실행 로그에 agent/child 버전뿐 아니라 runtime profile, Deep Agents 버전, 모델 해석 결과, 주요 정책 버전이 모두 남는지 운영 전 통합 검증해야 한다. 빠지면 사고 재현과 감사가 불가능해진다.
