# 15. 7단계 세부 07 — GP 서브에이전트 구성

## GP가 무엇인가

GP는 `General Purpose` 서브에이전트다. 특정 업무 전용 Child가 아니라
조사·검색·분석 같은 범용 작업을 Root 대신 수행한다.

```text
사용자 정의 Child
→ 특정 업무 전용 에이전트

GP
→ 범용 조사·검색 보조 에이전트
```

## 이 단계에서 하는 일

1. Root 도구에서 읽기 도구만 고른다.
2. GP 전용 호출 상한 미들웨어를 만든다.
3. Deep Agents 기본 GP 프롬프트에 프로젝트 공통 지침을 결합한다.
4. GP가 사용할 스킬 경로를 준비한다.
5. GP의 이름·설명·도구·미들웨어를 하나의 설정으로 만든다.
6. Root Graph의 서브에이전트 목록 첫 번째에 추가한다.

## 전체 동작 흐름

```text
Root Runtime Tool 목록
    ↓
side_effect=False 도구만 선택
    ↓
GP 전용 모델·도구 호출 상한 생성
    ↓
GP 시스템 프롬프트 조립
    ↓
GP 설명 적용
    ↓
사용 가능한 Skill 경로 연결
    ↓
GP Spec 생성
    ↓
Root의 subagents 목록에 추가
```

## GP는 항상 추가된다

```text
Root Graph
└─ general-purpose
```

GP를 켜고 끄는 별도 설정은 없다. 사용자 Child가 없어도 GP는 존재한다.

## GP 도구 제한

```text
Root tools
    ↓
side_effect=False만 선택
    ↓
gp_read_only_tools
```

GP는 조회·검색 도구만 받고 업무 등록·수정, Jira 생성, 스킬 등록과 MCP 도구는
받지 않는다. MCP 도구는 모두 `side_effect=True`로 분류된다.

## 빈 도구 목록의 의미

```text
tools=[]
→ GP는 도구 없이 실행

tools 키 자체를 생략
→ Deep Agents가 Root 전체 도구를 상속
```

Root의 쓰기 도구를 잘못 상속하지 않게 읽기 도구가 없어도 빈 목록을 명시한다.

## GP 미들웨어

```text
ModelCallLimitMiddleware
ToolCallLimitMiddleware
```

기본 설정 기준 모델 호출 최대 50회, 도구 호출 최대 100회이며 전역 ceiling이 더
작으면 작은 값이 적용된다. GP는 읽기 도구만 사용하므로 TODO, MCP timeout과 내장
쓰기 잠금은 붙이지 않는다.

## GP 시스템 프롬프트와 설명

```text
프로젝트 공통 Runtime Scaffold
+ Deep Agents 기본 GP 프롬프트
```

GP 설명은 조사·검색과 복합 작업을 수행하되 조회 도구만 사용하고 외부 상태 변경은
Root가 수행한다는 역할을 명시한다. Root는 이 설명을 보고 GP 위임 여부를 판단한다.

## GP와 Root의 역할 분리

```text
GP
→ 조사·검색·분석·결과 정리

Root
→ 사용자 대화·쓰기 도구·HITL·최종 응답
```

쓰기 작업이 필요하면 GP가 조사한 결과를 Root가 받은 뒤 Root가 쓰기 도구와 HITL을
처리한다.

## GP 스킬 연결

```text
MemoryProvider 있음
+ SkillsProvider 있음
    ↓
개인·팀 Skill 경로 계산
    ↓
GP Spec에 skills 추가
```

둘 중 하나라도 없으면 스킬을 연결하지 않는다. Skill이 Memory와 같은 Backend
경로를 사용하기 때문이다.

## GP 모델과 생성 방식

GP Spec에는 별도 모델을 지정하지 않아 Root Graph의 모델을 사용한다.

```text
사용자 Child
→ Child Graph 미리 컴파일
→ CompiledSubAgent

GP
→ GP Spec 생성
→ Root의 subagents에 전달
→ Deep Agents가 Root Graph 조립 중 구성
```

## GP Spec 결과

```text
GP Spec
├─ name = general-purpose
├─ description
├─ system_prompt
├─ tools
├─ middleware
└─ skills
```

`skills`는 사용 가능한 경우에만 포함된다.

## Root에 연결되는 순서

```text
subagents
├─ GP Spec
├─ Compiled Child 1
├─ Compiled Child 2
└─ Compiled Child N
```

## 이 단계의 결과

```text
gp_spec
→ Root Graph에 연결할 General Purpose 설정
```
