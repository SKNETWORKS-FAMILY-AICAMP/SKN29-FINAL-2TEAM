# 06. 미들웨어와 실행 상한

## 한 줄 정리

Deep Agents가 자동으로 붙이는 미들웨어는 중복 생성하지 않고, 우리 서비스의 호출 상한·TODO·MCP timeout·쓰기 잠금만 추가했다.

## Deep Agents 기본 설계

Deep Agents 0.7.5는 그래프 생성 과정에서 파일시스템, 서브에이전트, 요약, 잘못된 도구 호출 보정 등의 미들웨어를 자동 조립한다. 애플리케이션은 추가 미들웨어를 넘길 수 있다.

## 우리 설계

- `ModelCallLimitMiddleware`: Root와 Child는 각 에이전트의 `max_iterations`를 사용하되 최대 50으로 제한한다.
- `ToolCallLimitMiddleware`: Root와 Child는 최대 100회, GP도 모델 50회·도구 100회다.
- `TodoListMiddleware`: 기본 활성화하며, 대화용 계획과 실제 팀 업무를 구분하는 설명을 추가했다.
- MCP 호출에만 timeout 미들웨어를 붙인다.
- 같은 팀·프로젝트의 일부 내장 쓰기 도구는 잠금으로 직렬화한다.
- Deep Agents가 이미 만드는 요약·SubAgent·PatchToolCalls 미들웨어는 다시 만들지 않는다.

## 설계 이유

무한 반복과 비용 폭증을 코드로 막고, 라이브러리 기본 기능과 우리 기능의 중복·충돌을 피하기 위해서다.

## 좋은 부분

- 프롬프트가 아니라 코드로 호출 횟수를 강제한다.
- 에이전트가 요청한 값과 플랫폼 전체 상한을 함께 적용한다.
- 미들웨어 순서까지 고려해 timeout 대기 중 쓰기 잠금을 오래 잡지 않게 했다.
- Deep Agents 내부 미들웨어를 중복 부착하지 않았다.

## 문제점

- 도구 상한 100회와 GP 모델 상한 50회는 상당히 커서 잘못된 루프가 비용을 크게 만들 수 있다.
- 현재 값은 역할·요금제·모델 비용에 따라 실측해 정한 값이 아니다.
- 상한에 걸리면 `exit_behavior="error"`라 부분 결과를 정리하지 못하고 오류로 끝날 수 있다.
- Root, Child, GP가 실제 업무 복잡도와 무관하게 비슷하게 큰 상한을 가진다.

## 현재 판단

상한이 아예 없는 것보다 훨씬 안전하지만 운영 지표를 보고 기본값을 낮추거나 역할별로 나눌 필요가 있다.

## 즉시 수정이 필요한 치명적 문제

즉시 보안 사고로 이어지는 문제는 없다. 공개 운영 전 비용 경보와 실행 시간·호출 수 계측 없이 50/100 상한을 유지하는 것은 운영 위험이 크다.
