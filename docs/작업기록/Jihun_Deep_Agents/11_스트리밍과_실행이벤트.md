# 11. 스트리밍과 실행 이벤트

## 한 줄 정리

Deep Agents의 원시 LangGraph 스트림을 제품 UI와 DB가 이해하는 이벤트 계약으로 변환해 Root·Child·도구·추론·승인 상태를 실시간 표시한다.

## Deep Agents 기본 설계

LangGraph는 `updates`, `messages`, `custom` 스트림 모드와 subgraph namespace를 제공한다. 기본 출력은 제품 화면에서 바로 쓰기 위한 업무 이벤트 형식이 아니다.

## 우리 설계

- 세 모드를 동시에 구독하고 `subgraphs=True`로 Child 이벤트까지 받는다.
- 원시 이벤트를 `agent_started`, `subagent_started/completed`, `tool_started/completed/progress`, `reasoning`, `message_delta`, `awaiting_confirmation`, `result`, `error`로 변환한다.
- namespace를 이용해 병렬 Child 실행을 서로 구분한다.
- OpenAI reasoning summary 조각의 index를 추적해 같은 문단은 이어 붙이고 새 모델 호출은 분리한다.
- MCP의 모델용 이름을 원래 tool_ref로 복원해 UI와 로그에 기록한다.
- 이벤트를 DB 실행 기록과 프런트엔드의 기존 계약에 맞춘다.

## 설계 이유

라이브러리 내부 이벤트를 그대로 노출하지 않고, 사용자에게 이해 가능한 진행 상황과 감사 가능한 실행 기록을 제공하기 위해서다.

## 좋은 부분

- 병렬 서브에이전트와 도구 실행의 시작·종료를 구분할 수 있다.
- 승인 대기와 실패를 별도 상태로 표현한다.
- 제너레이터 도구의 진행률과 모델 reasoning summary를 실시간 표시할 수 있다.
- 레거시 화면 계약과 호환성을 유지한다.

## 문제점

- 이벤트 파서는 Deep Agents·LangGraph·provider의 내부 payload 모양에 강하게 의존한다.
- 존재하지 않는 subagent 오류를 영문 문자열 접두사로 판별하는 부분은 버전 변경에 취약하다.
- reasoning index 의미가 provider마다 다를 수 있다.
- 병렬 이벤트는 도착 순서가 실행 의도 순서와 다르므로 UI에서 오해될 수 있다.
- 이벤트 일부는 화면에만 보이고 DB에 영구 저장되지 않는다.

## 현재 판단

제품화에 꼭 필요한 계층이며 현재 구조도 합리적이다. 다만 호환 계층과 마찬가지로 라이브러리 업그레이드 회귀 테스트가 필수다.

## 즉시 수정이 필요한 치명적 문제

현재 고정 버전에서는 즉시 문제는 없다. 버전을 올리면서 이벤트 fixture 기반 계약 테스트를 통과시키지 않으면 실행 상태 누락이나 잘못된 성공 표시가 생길 수 있으므로 무검증 업그레이드는 금지해야 한다.
