# 09. 가상 파일시스템과 TODO

## 한 줄 정리

Deep Agents의 작업용 파일시스템과 계획 도구를 유지하되, 삭제 도구를 숨기고 대화 계획과 실제 팀 업무를 구분했다.

## Deep Agents 기본 설계

Deep Agents는 `ls`, `read_file`, `write_file`, `edit_file`, `delete`, `glob`, `grep` 등의 가상 파일 도구를 제공한다. LangChain의 TodoListMiddleware를 추가하면 `write_todos`로 에이전트 내부 계획을 관리할 수 있다.

## 우리 설계

- 기본 파일 도구 중 `delete`를 제외한다.
- Root는 CompositeBackend를 사용해 개인 메모리 경로만 StoreBackend로 보내고 나머지는 StateBackend로 처리한다.
- Child는 별도 장기 Store 없이 StateBackend만 사용한다.
- `write_todos`를 기본 활성화한다.
- `write_todos`는 팀원이 보는 실제 업무가 아니며, 실제 업무는 `task_register/task_update`를 사용해야 한다고 도구 설명에 추가했다.
- 파일 도구는 사용자 PC 파일이 아니라 에이전트의 가상 작업 공간이라고 공통 프롬프트에 명시했다.

## 설계 이유

긴 작업에서 중간 자료와 계획을 유지하면서 실제 사용자 파일·팀 업무와 혼동하지 않게 하기 위해서다.

## 좋은 부분

- 실제 로컬 파일과 가상 파일의 오해를 줄였다.
- 위험한 삭제 기능을 기본 제외했다.
- 대화용 TODO와 영구 팀 업무를 명확히 구분했다.
- 같은 thread에서는 계획과 작업 파일이 이어질 수 있다.

## 문제점

- 사용자는 UI에서 `write_todos`와 실제 팀 업무의 차이를 여전히 혼동할 수 있다.
- 체크포인트가 유지되는 동안 임시 파일도 DB에 남아 저장량이 커질 수 있다.
- `delete`만 제외하고 쓰기·편집은 남아 있으므로 장기 메모리 경로 보호는 별도 guard에 의존한다.
- TODO가 단순 요청에도 불필요하게 사용되면 모델 호출과 화면 이벤트가 늘어난다.

## 현재 판단

기능 구분은 적절하다. UI 명칭과 보존 정책까지 맞춰야 사용자 관점에서 완전히 이해되는 설계가 된다.

## 즉시 수정이 필요한 치명적 문제

현재 즉시 수정할 치명적 문제는 없다. 다만 체크포인트·임시 파일의 보존 기간과 용량 제한은 운영 전에 정해야 한다.
