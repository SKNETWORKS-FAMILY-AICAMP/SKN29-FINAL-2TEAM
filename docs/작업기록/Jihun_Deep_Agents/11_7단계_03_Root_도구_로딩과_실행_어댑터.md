# 11. 7단계 세부 03 — Root 도구 로딩과 실행 어댑터

## 이 단계에서 하는 일

1. Root 정의의 `tool_refs`를 가져온다.
2. 내장 도구 목록을 런타임 도구 형식으로 변환한다.
3. MCP 도구가 필요하면 팀의 MCP 도구를 조회한다.
4. 요청한 도구가 실제로 존재하는지 확인한다.
5. 항상 활성화되는 도구를 추가한다.
6. 각 도구에 `RuntimeContext` 주입 규칙을 연결한다.
7. 각 도구를 LangChain `StructuredTool`로 변환한다.
8. 실행 시 적용할 권한 검사와 중복 실행 방어를 연결한다.

## 전체 동작 흐름

```text
Root AgentDefinition.tool_refs
    ↓
내장 도구 목록 준비
    ↓
MCP 도구 참조가 있는지 확인
    ↓
├─ 없음
│  → MCP DB 조회 생략
│
└─ 있음
   → 현재 팀의 MCP 도구 조회
    ↓
요청한 tool_refs와 실제 도구 비교
    ↓
없는 도구 처리
    ↓
Always-on 도구 추가
    ↓
Runtime Tool 목록 생성
    ↓
각 Runtime Tool을 StructuredTool로 변환
    ↓
Root Graph에 전달할 langchain_tools 완성
```

## 입력 정보

```text
tool_refs
+ RuntimeContext
+ AgentDefinition.model
+ RuntimeCapabilityPolicy
```

| 입력 | 사용 목적 |
|---|---|
| `tool_refs` | Root가 사용할 도구 선택 |
| `RuntimeContext` | 계정·팀·프로젝트·실행 정보 주입 |
| `AgentDefinition.model` | `task_extraction` 도구에 Root 모델 전달 |
| `RuntimeCapabilityPolicy` | 실행 시 역할별 권한 확인 |

## Runtime Tool 구조

```text
Tool
├─ ref
├─ name
├─ description
├─ input_schema
├─ handler
├─ side_effect
└─ injected_context
```

## 내장 도구 로딩

```text
BUILTIN_TOOLS
    ↓
adapt_builtin_tools()
    ↓
Runtime Tool 목록
```

내장 도구마다 필요한 서버 컨텍스트도 함께 지정한다.

```text
문서 검색
→ team_id + account_id + project_id

프로젝트 업무 도구
→ project_id + account_id

계정 범위 도구
→ account_id

스킬 등록
→ account_id + team_id + account_role
```

## MCP 도구 로딩

`tool_refs`에 `mcp:`로 시작하는 값이 하나라도 있을 때만 팀의 MCP 도구를
조회한다.

```text
mcp: 참조 없음
→ MCP DB 조회하지 않음

mcp: 참조 있음
→ 현재 team_id의 활성 MCP 도구 조회
```

MCP 도구는 읽기·쓰기 구분 정보가 없으므로 모두 `side_effect=True`로 처리한다.
MCP 서버 주소와 인증 토큰은 Tool 객체에 미리 저장하지 않고 실제 호출 직전에
다시 조회한다.

## 없는 도구 처리

### 없는 내장 도구

```text
정의에 없는 내장 tool_ref가 있음
    ↓
ToolUnavailableError
    ↓
Runtime Graph 조립 중단
```

### 없는 MCP 도구

```text
발행된 버전에 MCP 참조가 남아 있음
+ 운영자가 MCP 서버를 삭제함
    ↓
경고 로그 기록
    ↓
해당 MCP 도구만 제외
    ↓
나머지 도구로 조립 계속
```

## Always-on 도구

```text
요청한 tool_refs
+ ALWAYS_ON_TOOL_REFS
    ↓
중복 제거
    ↓
최종 Runtime Tool 목록
```

Always-on 도구가 실제 등록 목록에 없으면 오류 없이 제외한다.

## RuntimeContext 주입

도구가 실행될 때 서버가 필요한 컨텍스트 값을 덮어쓴다.

```text
team_id
account_id
session_id
project_id
run_id
parent_run_id
account_role
```

```text
모델이 만든 도구 인자
    ↓
도구가 요구하는 injected_context 확인
    ↓
RuntimeContext 값으로 덮어쓰기
    ↓
실제 handler 호출
```

따라서 모델이 다른 `account_id`나 `team_id`를 인자로 만들어도 서버 값이 우선한다.

## LangChain 도구로 변환

```text
Runtime Tool
    ↓
_to_langchain_tool()
    ↓
StructuredTool
```

모델에게는 도구 함수 이름, 설명, 입력 스키마와 실행 wrapper가 전달된다.

## 모델용 도구 이름 변환

```text
mcp:MT001
→ mcp__MT001
```

OpenAI 함수 이름 제약 때문에 콜론을 이중 밑줄로 바꾸며, 이벤트와 실행 기록을
만들 때는 원래 `tool_ref`로 복원한다.

## 도구 노출과 실행 권한

도구는 역할과 관계없이 모델에게 모두 보여주고 실제 실행 직전에 권한을 확인한다.

```text
모델이 도구 선택
    ↓
도구 실행 직전 역할 확인
    ↓
├─ 허용
│  → handler 실행
│
└─ 거부
   → ToolException 반환
   → 그래프 전체는 계속 진행
```

## Side-effect 도구 중복 실행 방어

```text
run_id
+ langchain_tool_call_id
    ↓
이전에 성공한 결과가 있는지 확인
    ↓
├─ 있음
│  → handler를 다시 실행하지 않음
│  → 저장된 결과 반환
│
└─ 없음
   → handler 실행
   → 성공 결과 저장
```

읽기 도구는 중복 실행 방어 대상이 아니다.

## MCP 실행 중 표시

```text
MCP 실행 시작
→ active 표시 저장

MCP 실행 완료 또는 실패
→ active 표시 제거
```

이 정보는 같은 MCP 서버에서 다른 작업이 실행 중이라는 HITL 경고를 만드는 데
사용한다.

## 도구 오류 처리

```text
도구 handler 오류
    ↓
모델에게 설명 가능한 오류인가?
    ↓
├─ 설명 가능
│  → 실제 오류 문구를 ToolException으로 전달
│
└─ 내부 장애
   → 원문을 숨기고 오류 코드만 전달
```

도구 하나의 오류로 Runtime Graph 전체를 바로 중단하지 않고 모델이 오류를 읽어
다음 행동을 선택할 수 있게 한다.

## 아직 도구는 실행하지 않는다

```text
StructuredTool 생성
≠ 실제 handler 실행
```

실제 실행은 9단계에서 모델이 해당 도구를 선택했을 때 발생한다.

## 이 단계의 결과

```text
tools
→ 프로젝트 내부 Runtime Tool 목록

langchain_tools
→ Root Graph에 연결할 StructuredTool 목록
```

## 이 단계에서 아직 처리하지 않는 것

```text
HITL interrupt_on 구성
MCP timeout 미들웨어 적용
도구 병렬 실행 상한 적용
Root Graph에 최종 연결
```
