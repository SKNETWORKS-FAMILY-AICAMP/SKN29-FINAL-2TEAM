# 06. 5단계 — 사용자 원문 선저장

## 5단계에서 하는 일

1. 사용자 원문을 채팅 메시지로 저장한다.
2. 메시지 역할을 `user`로 기록한다.
3. 채팅 세션의 최근 수정 시간을 갱신한다.
4. 저장이 성공하면 런타임 실행 단계로 넘긴다.

저장되는 내용은 다음과 같다.

```text
session_id
+ role: user
+ content:
    type: text
    text: 사용자 원문
```

민감정보를 마스킹한 `model_input`이 아니라 사용자가 작성한 원문 `text`를 저장한다.

## 전체 동작 흐름

```text
4단계 가드레일 통과
    ↓
채팅 세션 접근 권한 다시 확인
    ↓
사용자 원문으로 메시지 생성
    ↓
chat_message 테이블에 저장
    ↓
chat_session.updated_at 갱신
    ↓
저장 결과 반환
    ↓
6단계 런타임 실행 시작
```

## 저장 시점

사용자 메시지는 런타임을 실행하기 전에 저장한다.

```text
사용자 메시지 저장
    ↓
AgentExecutor.run() 실행
```

따라서 이후 런타임 실행이 실패해도 사용자가 보낸 질문은 채팅 기록에 남는다.
반대로 4단계에서 가드레일에 차단된 입력은 이 단계까지 도달하지 않으므로
저장되지 않는다.

## 원문과 모델 입력의 차이

```text
text
→ 사용자가 입력한 원문
→ 채팅 기록 저장에 사용

model_input
→ 민감정보가 마스킹된 입력
→ 모델 실행에 사용
```

## DB에서 함께 처리되는 작업

메시지를 저장하면 채팅 세션의 `updated_at`도 현재 시간으로 변경한다.

```text
chat_message INSERT
+ chat_session.updated_at UPDATE
```

이 값은 채팅 목록을 최근 활동 순서로 정렬하는 데 사용된다.
