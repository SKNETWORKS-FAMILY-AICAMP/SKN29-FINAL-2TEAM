# 12. 7단계 세부 04 — HITL 승인 대상 구성

## 이 단계에서 하는 일

1. Checkpointer가 연결되어 있는지 확인한다.
2. 현재 역할이 side-effect 도구를 실행할 수 있는지 확인한다.
3. 로딩한 도구 중 `side_effect=True`인 도구를 찾는다.
4. 해당 도구를 HITL 승인 대상으로 등록한다.
5. MCP 도구에는 승인 카드에 표시할 경고 생성 함수를 연결한다.
6. 최종 `interrupt_on` 설정을 만든다.

## 전체 동작 흐름

```text
Root Runtime Tool 목록
    ↓
Checkpointer가 있는지 확인
    ↓
├─ 없음
│  → interrupt_on 생성 안 함
│
└─ 있음
   ↓
현재 역할의 side-effect 실행 권한 확인
   ↓
├─ 권한 없음
│  → interrupt_on 생성 안 함
│
└─ 권한 있음
   ↓
side_effect=True 도구 선택
   ↓
├─ 내장 도구
│  → 기본 HITL 설정
│
└─ MCP 도구
   → 호출별 경고와 허용 결정 설정
   ↓
interrupt_on 완성
```

## 입력 정보

```text
tools
+ RuntimeContext.role
+ RuntimeCapabilityPolicy
+ CheckpointerProvider
```

## Side-effect 도구

```text
side_effect = False
→ HITL 대상 아님

side_effect = True
→ HITL 대상 후보
```

업무 등록·수정, Jira 이슈 생성, 스킬 등록과 MCP 도구처럼 외부 상태를 바꾸는
도구가 승인 대상이다.

## Checkpointer가 필요한 이유

```text
모델이 쓰기 도구 선택
    ↓
Graph 실행 중단
    ↓
사용자 승인 대기
    ↓
나중에 같은 실행 재개
```

중단된 Graph 상태를 보관해야 승인 후 같은 지점에서 이어갈 수 있다. 따라서
Checkpointer가 없으면 `interrupt_on=None`으로 둔다.

## 역할별 실행 권한 확인

```text
RuntimeContext.role
+ RuntimeCapabilityPolicy
    ↓
side-effect 실행 가능 여부
```

실행 권한이 없는 도구는 승인받아도 실행 단계에서 거부되므로 승인 대상으로
만들지 않는다. 현재 기본 정책에서는 `leader`와 `member` 모두 쓰기 도구를 사용할
수 있으며 실제 실행 전 사용자 승인을 거친다.

## 내장 도구 HITL 설정

```text
interrupt_on[모델용 도구 이름] = True
```

`True`는 Human-in-the-Loop 미들웨어의 기본 승인 설정을 사용한다는 뜻이다.

## MCP 도구 HITL 설정

```text
interrupt_on["mcp__MT001"] = {
    allowed_decisions,
    description
}
```

MCP 도구 이름은 모델용 안전 이름을 사용한다.

```text
mcp:MT001
→ mcp__MT001
```

## 허용되는 사용자 결정

```text
approve
edit
reject
respond
```

| 결정 | 의미 |
|---|---|
| `approve` | 모델이 만든 호출을 그대로 승인 |
| `edit` | 도구 호출 인자를 수정한 뒤 승인 |
| `reject` | 도구 호출 거부 |
| `respond` | 도구 실행 대신 사용자 응답을 Graph에 전달 |

현재 채팅 API의 호출별 부분 승인 UI는 주로 `approve`와 `reject`를 사용하지만,
런타임 설정은 미들웨어가 지원하는 전체 결정 종류를 열어 둔다.

## MCP 승인 경고

MCP 승인 카드 설명은 다음 상태를 확인할 수 있다.

```text
같은 MCP 서버에 다른 호출이 실행 중인가
이 도구가 최근 timeout됐는가
재시도 시 외부 작업이 중복될 가능성이 있는가
```

이 경고는 실행을 자동으로 막는 기능이 아니라 사용자가 승인 여부를 판단하도록
정보를 제공하는 기능이다.

## `interrupt_on` 결과

```text
interrupt_on
├─ task_register
├─ task_update
├─ jira_create_issues
├─ skill_register
└─ mcp__MT001
```

side-effect 도구가 하나도 없으면 `interrupt_on=None`이다.

## 실제 중단 시점

```text
interrupt_on 구성
≠ Graph 중단
```

실제 중단은 9단계에서 모델이 승인 대상 도구를 호출했을 때 발생한다.

```text
runtime.stream()
    ↓
모델이 side-effect 도구 호출
    ↓
HumanInTheLoopMiddleware가 호출 감지
    ↓
Checkpointer에 현재 상태 저장
    ↓
interrupt 이벤트 발생
    ↓
사용자 승인 대기
```

## Child·GP와의 관계

Child Graph에도 같은 방식으로 자신의 `interrupt_on`을 만들 수 있다. GP
서브에이전트에는 side-effect 도구를 넘기지 않으므로 GP용 쓰기 도구 승인 설정은
만들지 않는다.

## 이 단계의 결과

```text
interrupt_on
→ 도구 이름별 HITL 승인 설정
```

이 값은 이후 Child Graph 또는 Root Graph를 생성할 때 전달한다.
