## 1. 구조·문맥 복원

네가 적은 1번과 5번을 하나로 묶을 수 있어.

### 1번: 제목 구조 복원

```
파싱된 heading이 모두 level=1이어도
텍스트, 위치, 크기, 페이지, 반복 패턴 등을 이용해
가능한 제목 계층과 섹션 문맥을 추론
```

단, “정확하게 복원한다”보다는 다음처럼 정의하는 게 안전해.

> 불완전한 제목 정보를 기반으로 신뢰 가능한 범위에서 계층과 문맥을 복원한다.

파싱 단계에서 정보가 완전히 사라진 경우에는 청킹 단계에서도 100% 정확한 복원이 불가능하기 때문이야.

### 5번: 인접 peer 병합 개선

현재 순정 기준:

```
인접
AND headings 동일
AND 토큰 제한 이하
```

개선할 때 검토할 정보:

```
페이지
제목 계층
DocItem 유형
Group
bbox 및 레이아웃 거리
제품·섹션 문맥
```

1번에서 제목 문맥을 복원하면 5번의 병합 정확도도 자연스럽게 좋아져. 따라서 둘은 다음 하나의 문제로 정의할 수 있어.

> 불완전한 제목 구조를 복원하고, 복원된 문맥과 페이지·요소 정보를 사용해 peer 병합의 정확도를 개선한다.

## 2. 유형별 구조 보존 청킹

네가 적은 2번과 4번이 연결돼.

### 4번: 콘텐츠 유형 구별

이게 상위 구조야.

```
DocItem
├─ 일반 텍스트·목록
├─ 표
├─ 이미지
├─ 캡션
├─ 페이지 머리글·바닥글
└─ 기타 구조 요소
```

모든 요소를 HybridChunker 하나에 넣는 대신 유형에 따라 다른 처리 기준을 적용하는 거야.

### 2번: 표 구조 보존

표는 유형별 처리의 대표적인 하위 전략이야.

정확한 목표는 다음과 같아.

> 파싱 결과에 남아 있는 행·열·병합 셀 정보를 최대한 보존하여 논리적인 표 청크를 생성한다.

“행과 열을 정확하게 파악한다”라고 하면 파싱에서 누락된 셀까지 청킹 단계가 완벽하게 복원해야 한다는 의미로 들릴 수 있어. 청킹 단계의 책임은 다음 정도가 적절해.

- 파싱된 셀 구조 보존
- 셀 내부 분절 방지
- 헤더와 값 관계 유지
- 표 방향에 맞는 논리 단위 선택
- 구조가 불완전하면 경고로 기록

이미 1차로 제품 열 중심 사양표를 처리했으므로, 이 주제는 개선 근거와 결과가 가장 명확해.

## 3. 청크 품질 관리

네가 적은 3번이 여기에 해당해.

### 의미 있는 짧은 청크

```
Petrochemical
- Ethylene
- Polymers
- EO/EG
- Fine Chemicals
```

짧지만 독립적인 정보가 있으므로 유지할 가치가 있어.

### 저정보 짧은 청크

```
Icon
Logo
Engineering drawing
```

단독으로는 검색 가치가 거의 없을 가능성이 커.

따라서 문제를 단순히:

```
20토큰 미만 청크 제거
```

로 정의하면 안 돼.

더 정확한 정의는 다음과 같아.

> 청크 길이뿐 아니라 콘텐츠 유형, 정보량, 주변 문맥을 함께 고려해 의미 있는 짧은 청크와 저정보 고립 청크를 구분한다.

여기에도 4번의 유형 구분이 필요해. `Icon`이 짧아서 문제가 아니라, **이미지 유형 문자열만 있고 실질 정보가 없기 때문에** 문제인 거야.

# 다섯 문제의 관계

```
1. 제목 계층 복원
        ↓
2. peer 병합 개선

3. 콘텐츠 유형 구별
   ├─ 2. 표 구조 보존
   └─ 3. 짧은 청크 품질 판단
```
