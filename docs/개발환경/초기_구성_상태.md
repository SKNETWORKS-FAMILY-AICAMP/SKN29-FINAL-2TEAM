## 1. 기술 결정

| 영역 | 현재 결정 |
|---|---|
| 웹 API | Django + Django REST Framework |
| DB 관리 | `DB/schema.sql` 직접 관리, Django ORM·Migration 미사용 |
| DB 접근 | psycopg Repository |
| 관계 데이터 | PostgreSQL 17 |
| 벡터 검색 | 같은 PostgreSQL의 pgvector `vec_idx` |
| People 목업 | `DB/peopleDB/peopledb_mock.sql` |
| 프론트 | React + Vite + TypeScript |

Django는 HTTP 요청·응답과 API 라우팅만 담당한다. Django Admin, 기본 Auth,
Session, ORM 모델 테이블은 사용하지 않는다.

## 4. DB 설계 적용 원칙

- HR·플랫폼 기준정보의 짧은 코드는 `VARCHAR(5)`를 사용한다.
- `doc_block.block_id`, `chunk.chunk_id`, `chunk.up_chunk_id`는 UUID다.
- `vec_idx.chunk_id`는 UUID PK이며 Chunk와 논리적 1:1이다.
- FK 제약은 사용하지 않는다.
- 참조 대상 존재 여부는 Repository가 INSERT 전에 검사한다.
- 5자리 코드 충돌은 PostgreSQL advisory transaction lock으로 방지한다.
- 테이블 생성과 변경은 Django Migration이 아니라 SQL 파일에서 관리한다.

## 8. 운영 주의사항

- 팀장/팀원은 `org.mgr_id`가 아니라 가입 경로로 판정한다. 직접 가입은 팀장,
  초대 코드 가입(`match_method='TEAM_INVITATION'`)은 팀원이다.
- 직접 가입자의 HR 이메일 매칭은 People DB 연결 시점에 실행되며
  `match_method='SELF_EMAIL'`로 기록된다.
- 화면은 본인 조직을 기본 표시하지만 팀장의 초대 권한은 본인 조직과 하위 조직까지다.
- **우리 플랫폼을 쓰는 단위는 회사가 아니라 팀이다.** 팀장이 온보딩에서 팀명을 적어
  만들고(`team`/`team_member`), 그 뒤 HR 조회는 전부 팀원 명부 기준으로 좁혀진다.
  `user_account.team_id`가 비어 있는 계정은 아무도 못 본다 — 온보딩을 다시 타야 한다.
- **HR 8개 테이블은 `mock_hr` 스키마에 있다.** `backend/services/hr/`만 이 스키마를
  읽는다. 다른 곳에서 `JOIN person`을 쓰면 `relation "person" does not exist`가
  나는데, 그게 의도한 동작이다([[HR_어댑터와_테넌트_경계]] §8).
- `docker compose down -v`는 PostgreSQL 볼륨을 삭제한다. 복구 순서는
  `schema.sql` → `peopledb_mock.sql` → `team_overrides.sql`이다.
- Windows 바인드 마운트에서 Vite 감시가 멈추면
  `docker compose restart frontend`로 프론트 컨테이너를 재시작한다.
