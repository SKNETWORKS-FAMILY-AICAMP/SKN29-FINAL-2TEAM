> 알고 시간을 쓴다. 아래 1·2·3만 읽어도 된다.

## 1. ⚠ `main` 에 푸시하면 **시연 서버에 바로 나간다**

GitHub Actions 가 붙었다(`.github/workflows/deploy.yml`).
`main` 에 커밋이 들어오면 자동으로 빌드·배포된다.

**배포하면 `web` 컨테이너가 재생성돼 몇 초 끊긴다.**
**시연·발표 중에는 `main` 에 푸시하지 말 것.** 급하면 Actions 탭에서 워크플로를
잠시 비활성화한다.

각자 브랜치에 푸시하는 것은 아무 영향이 없다.

## 2. ⚠ 로컬에서 **Jira 연결이 안 된다** — 고장이 아니다

Atlassian 은 앱 하나에 Callback URL 을 **하나만** 받는다(구글은 여러 개 된다).
그 하나를 AWS 주소로 옮겼다. 그래서 로컬에서 Jira 를 연결하려 하면
`redirect_uri_mismatch` 가 난다.

Google Drive·People DB 는 로컬에서 그대로 된다. Jira 만 해당한다.

로컬에서 Jira 를 꼭 봐야 하면 개발자 콘솔에 앱을 하나 더 만들어 로컬 전용으로
쓴다. 근거는 `AWS_이전_매뉴얼.md` §1 「결정 — Jira 는 로컬을 포기했다」.

## 3. 프론트 이미지를 다시 빌드해야 한다

`frontend/Dockerfile` 이 멀티스테이지로 바뀌었다. **로컬 동작은 그대로다** —
`docker-compose.yml` 은 지금까지처럼 Vite 개발 서버(HMR)를 받는다. 다만 이미지가
바뀌었으니 한 번은 다시 빌드해야 한다.

```bash
docker compose -f infra/docker/docker-compose.yml up -d --build
```

AWS 만 정적 빌드(`target: static`)를 쓴다.

## 그 밖에 바뀐 것

### `.env.example` 에 항목이 늘었다

- `OPS_ADMIN_EMAIL` · `OPS_ADMIN_PASSWORD` — 운영자 계정 시드용
  (`backend/services/createDB/seed_ops_admin.py`). 로컬에서는 안 채워도 된다.
- `PUBLIC_BACKEND_BASE_URL` 설명이 갈렸다 — **로컬은 여전히 Cloudflare 빠른
  터널**이 필요하고, AWS 만 `https://api.halil-ai.site` 로 고정이다.

### 로컬 DB 초기화 순서에 파일이 하나 빠져 있었다

`schema.sql → peopledb_mock.sql → team_overrides.sql → **demo_skills.sql**`

`demo_skills.sql` 이 빠져 있었다. 없으면 팀장으로 로그인했을 때
「내 프로필 → 보유 스킬」이 본인만 비어 보인다. 여러 번 돌려도 안전하다.

### 문서에서 고친 것 (숫자·경로가 틀렸던 것들)

| 무엇 | 전 → 후 |
|---|---|
| 테이블 개수 검증 | 48개 → **57개** (public 49 + mock_hr 8) |
| `analysis-runs` API 2개 | 표에서 삭제 — **코드에 없다** |
| `vec_idx_setup.py` | 실행 절차 삭제 — **지금 돌리면 실패한다** |
| 「로그인 후 비밀번호 변경」 | 미구현 목록에서 제거 — 이미 구현돼 있다 |
| 「화면 구현 전에는 빈 화면이 정상」 | 삭제 — **지금 빈 화면이면 고장이다** |

`AWS_이전_매뉴얼.md` 와 `AWS_1단계_공유환경_구축.md` 도 실제 코드와 대조해
바로잡았다(§7 의 「Django migration」 표기 등).
