## 04. 기업 AI Agent의 업무 확장 과제

### 발표 스크립트

> “최근 기업 AI의 흐름은 단순 도입을 넘어 AI로 업무 방식을 전환하는 AX로 확장되고 있습니다. McKinsey의 2025년 조사에서는 39%의 기업이 AI Agent를 실험하고 있고, 23%는 최소 한 개 업무 기능에서 실제 확장을 시작했습니다. 다만 기업 전반의 활용은 아직 초기 단계입니다. 저희는 이 과정에서 두 가지 과제에 주목했습니다. 하나는 문서와 업무 시스템이 여러 곳에 흩어져 있다는 점이고, 다른 하나는 반복 업무의 방식과 경험이 개인에게 머문다는 점입니다.”

### 화면에서 가리킬 부분

1. `39% 실험 중`
2. `23% 최소 1개 업무에서 확장 중`
3. `우리가 주목한 두 가지 과제`

### 다음 장 연결

> “이런 기업 환경을 선도 서비스들은 어떤 구조로 다루는지 살펴봤습니다.”

### 상세 이해와 Q&A

- `39%`와 `23%`는 전환율이 아니라 서로 다른 상태의 집단이다.
- `23%`는 전사 확장 완료가 아니라 최소 하나의 업무 기능에서 확장 중이라는 의미다.
- `62%`는 39% 실험과 23% 확장의 합이므로 `검토 중 62% → 확장 23%`로 표현하지 않는다.
- `AX`는 시장 맥락을 설명하는 구두 도입으로 사용한다. 장표 제목은 실제 내용과 수치에 맞춰 `기업 AI Agent의 업무 확장 과제`로 유지한다.
- 두 문제는 McKinsey가 확장 실패 원인으로 제시한 항목이 아니라, 프로젝트가 구현 범위와 연결해 선택한 문제다.
- 시장 규모나 TAM·SAM·SOM은 별도 장표로 두지 않았다. 이번 발표는 투자 IR보다 구현과 검증이 중심이며, 04의 도입 현황과 05의 선도 서비스 사례로 시장 흐름을 충분히 설명할 수 있기 때문이다.

## 05. 선도 서비스 공통 요소

### 발표 스크립트

> “제품별 구현 방식과 강점에는 차이가 있지만 공통적으로 확인되는 영역이 있었습니다. 기업의 정보와 업무 도구를 연결하고, 그 정보를 활용하는 Agent를 구성해 실행하며, 기업 환경에 맞게 운영하고 관리하는 구조입니다.”

### 화면에서 가리킬 부분

1. 두 서비스 이름을 짧게 확인
2. `정보·도구 연결`
3. `에이전트 생성·실행`
4. `운영·관리`

### 다음 장 연결

> “저희도 이 세 영역을 하나의 업무 흐름으로 연결하는 방향을 잡았습니다.”

### 상세 이해와 Q&A

- 이 페이지는 경쟁사 우위 비교가 아니라 기업용 Agent 플랫폼에서 중요하게 다루는 공통 영역을 확인하는 장표다.
- 두 서비스의 구조가 완전히 같다는 뜻은 아니다.
- `Glean보다 우수하다`, `Copilot Studio보다 자유롭다`와 같은 주장은 하지 않는다.
- Glean은 기업 정보 연결, Agent Builder, 공유·접근 관리를 제공한다.
- Copilot Studio는 데이터·업무 도구 연결, Agent와 업무 흐름 구성, 보안·환경 관리 기능을 제공한다.

## 06. 기업 업무 활용 Agent 플랫폼

### 발표 스크립트

> “HALIL은 비정형 문서를 처리하고 Connector와 MCP로 정보와 업무 도구를 연결하며, 사용자가 Agent를 구성해 실행할 수 있도록 구현했습니다. 또한 기업 환경에서 활용할 수 있도록 권한과 승인, 실행 결과 추적까지 하나의 플랫폼 안에 연결했습니다.”

### 화면에서 가리킬 부분

1. `정보·도구 연결`
2. `에이전트 생성·실행`
3. `운영·관리`
4. 하단의 `하나의 업무 흐름`

화면의 HALIL 로고는 세 영역의 상위 개념을 나타낸다. 세 영역을 각각 독립 기능으로 설명하기보다 왼쪽에서 오른쪽으로 이어지는 하나의 플랫폼 흐름으로 설명한다.

### 다음 장 연결

> “이 플랫폼을 구현하기 위해 팀에서는 각 영역을 나누어 개발했습니다.”

### 상세 이해와 Q&A

#### HALIL을 한 문장으로 정의하면?

기업의 정보와 업무 도구를 연결하고, 사용자가 Agent를 구성해 실행하며, 조직 차원에서 권한·승인·실행 결과를 관리하는 기업 업무 활용 Agent 플랫폼이다.

#### 왜 플랫폼이라고 부르는가?

하나의 고정 업무만 수행하는 것이 아니라 Connector, MCP, 문서, Tool, Sub-agent를 조합해 Agent를 구성할 수 있고, 운영 측에서 연결 서비스, 모델, 권한, 승인과 실행 현황을 관리하는 구조를 제공하기 때문이다.

#### 평가 대신 실행 추적이라고 쓴 이유는?

개요에서는 정식 성능평가와 운영 기능이 혼동되지 않도록 실제 OPS에서 확인 가능한 실행 현황과 사용 기록을 중심으로 표현했다. 구체적인 품질 평가는 뒤의 평가 파트에서 설명한다.

## 발표자가 기억할 네 문장

1. Agent에 대한 관심은 높지만 기업 전반의 실제 업무 확장은 아직 초기다.
2. 우리는 흩어진 정보와 개인에게 머무는 업무 노하우에 주목했다.
3. 선도 서비스에서도 연결·실행·관리라는 공통 영역을 확인했다.
4. HALIL은 이 세 영역을 하나의 기업 업무 활용 Agent 플랫폼으로 구현했다.

HALIL은 비정형 문서를 처리하고 Connector와 MCP로 정보와 업무 도구를 연결하며, 사용자가 Agent를 구성해 실행할 수 있도록 구현했습니다. 또한 권한과 승인, 실행 결과 추적까지 하나의 플랫폼 안에 연결했습니다.”

## 표현상 주의사항

- `39%에서 23%로 전환됐다`고 말하지 않는다.
- 두 문제를 McKinsey가 직접 규정했다고 말하지 않는다.
- 선도 서비스와 HALIL의 구조가 완전히 동일하다고 말하지 않는다.
- 구현하거나 검증하지 않은 기능을 확정적으로 말하지 않는다.
- 화면에 제거한 회색 부제목은 읽지 않고, 필요한 맥락만 각 페이지 스크립트의 첫 문장으로 전달한다.
