# 인증·세션·비밀번호 재설정 정책

> 기준일: 2026-07-31
> 구현 기준: `apps/accounts`, `frontend/src/utils/session.ts`

## 1. 계정 가입과 역할

플랫폼 계정은 이메일·비밀번호로 가입한다. `user_account`에 별도 역할 컬럼을 두지 않고 가입 경로와 `user_person_link.match_method`로 역할을 계산한다.

| 가입 경로 | 역할 | PERSON 매핑 |
|---|---|---|
| 초대 코드 없이 직접 가입 | 팀장 | 가입 시에는 매핑하지 않는다. People DB 커넥터에서 본인 확인을 완료하면 `SELF_EMAIL`로 연결 |
| 유효한 초대 코드로 가입 | 팀원 | 초대가 가리키는 PERSON과 즉시 `TEAM_INVITATION`으로 연결 |

직접 가입 계정은 역할상 팀장이지만 People DB 본인 매핑이 없으면 조직 범위가 비어 있으므로 팀원 조회·초대 기능을 사용할 수 없다. 역할 판정과 HR 권한 개방을 분리한 이유다.

## 2. 로그인 세션

- 로그인·가입 성공 시 서버가 `SECRET_KEY`로 서명한 타임스탬프 토큰을 발급한다.
- 클라이언트는 `Authorization: Bearer <token>` 헤더로 인증한다.
- 토큰 유효기간은 12시간이다. 응답이 `expires_at`으로 만료 시각을 함께 알려준다.
- 프론트엔드는 세션을 `sessionStorage`의 `halil.session` 키에 저장한다. **탭이나 브라우저를 닫으면 로그아웃된다.**
- 프론트엔드는 세션을 읽을 때마다 `expires_at`을 확인해 지났으면 스스로 버린다.
- 보호 API가 현재 토큰에 대해 401을 반환하면 프론트엔드는 저장된 세션을 삭제하고 로그인 화면으로 보낸다.
- 서버에는 세션 테이블이나 토큰 폐기 목록이 없다. 따라서 개별 토큰 강제 로그아웃은 지원하지 않으며, 로그아웃은 클라이언트 토큰 삭제·탭 종료 또는 12시간 만료로 처리한다.

> **이 절의 앞선 서술은 틀렸다 (2026-07-31 수정).** 원래 `localStorage`에 저장하고 만료는 401로만 감지한다고 적혀 있었고 구현도 그랬다. 두 가지가 문제였다. 브라우저를 껐다 켜도 로그인이 유지돼 시연·공용 PC에서 곤란했고, 랜딩처럼 보호 API를 부르지 않는 화면은 401을 받을 일이 없어 12시간이 지난 죽은 토큰으로 로그인 상태를 계속 보여줬다. `sessionStorage` 전환과 만료 시각 확인으로 둘 다 정리했다.

### 보안상 한계

`sessionStorage` 토큰은 XSS에 노출될 수 있으므로 사용자 입력을 HTML로 직접 삽입하지 않는다. 운영 배포에서 즉시 세션 폐기나 더 강한 방어가 필요하면 HttpOnly 쿠키·서버 세션 또는 토큰 폐기 목록 도입을 별도로 검토한다.

## 3. 비밀번호 재설정

### 요청

`POST /api/auth/password-reset/`에 이메일을 전달한다. 계정 존재 여부 노출을 막기 위해 등록 여부와 관계없이 동일한 성공 응답을 반환한다.

### 토큰

- `SECRET_KEY`와 전용 salt로 서명한다.
- 유효기간은 1시간이다.
- 현재 `password_hash`의 지문을 토큰에 포함한다.
- 재설정 성공으로 비밀번호 해시가 바뀌면 이전 토큰의 지문이 더 이상 일치하지 않아 재사용할 수 없다.
- 발급 이력을 저장하는 별도 테이블은 사용하지 않는다.

### 확인

`POST /api/auth/password-reset/confirm/`은 토큰 서명·만료·비밀번호 지문을 확인한 후 새 비밀번호 해시를 저장한다.

## 4. 메일 발송

메일은 비밀번호 재설정 링크에만 사용한다.

| 환경 | `EMAIL_BACKEND` | 동작 |
|---|---|---|
| 기본 개발환경 | `django.core.mail.backends.console.EmailBackend` | 실제 발송 없이 `web` 컨테이너 로그에 메일 본문 출력 |
| Gmail SMTP | `django.core.mail.backends.smtp.EmailBackend` | `.env`의 Gmail 계정과 앱 비밀번호로 실제 발송 |

Gmail은 일반 계정 비밀번호가 아니라 2단계 인증 후 발급한 앱 비밀번호를 사용한다. `.env`와 앱 비밀번호는 Git에 커밋하지 않는다.

필요한 설정:

```dotenv
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST_USER=운영자@gmail.com
EMAIL_HOST_PASSWORD=앱-비밀번호-16자리
DEFAULT_FROM_EMAIL=halil <운영자@gmail.com>
FRONTEND_BASE_URL=http://localhost:5173
```

SMTP 기본값은 `smtp.gmail.com:587`, TLS 사용이다.
